# Requirement

The `ShoppingCart` should support adding a product with a specified quantity.

When a product is added with a quantity:

- `getItemCount()` should return the **total quantity** of all items.    
- `getTotal()` should calculate **price × quantity** for each item.
- The existing `addItem(Product product)` method should continue to work with a default quantity of `1`.

### Example

Adding:

```text
Product: Book
Price: 10
Quantity: 3
```

should result in:

```text
Item count = 3
Total = 30
```

---

## TDD Cycle

### 🔴 Red — Write the Test

First, write a test describing the new behavior.

```java
@Test
public void testForAddingMultipleQuantities() {
    // Arrange
    Product book = new Product("1", "Book", 10);

    // Act
    cart.addItem(book, 3);

    // Assert
    assertEquals(3, cart.getItemCount());
    assertEquals(30, cart.getTotal());
}
```

This test requires a new overloaded method:

```java
addItem(Product product, int quantity)
```

The existing `ShoppingCart` does not support quantities, so the test should initially fail.

---

## 🟢 Green — Make the Test Pass

To support quantities, introduce a `CartItem` class that extends `Product` and stores the quantity.

### `CartItem.java`

```java
public class CartItem extends Product {

    private int quantity;

    public CartItem(Product product, int quantity) {
        super(product.getId(), product.getName(), product.getPrice());
        this.quantity = quantity;
    }

    public int getQuantity() {
        return quantity;
    }
}
```

### Why `CartItem`?

A `Product` contains information about the product itself:

```text
ID
Name
Price
```

A `CartItem` represents that product **as it exists in the shopping cart**, so it additionally needs:

```text
Quantity
```

Therefore:

```text
Product
   ↓
CartItem
   ├── ID
   ├── Name
   ├── Price
   └── Quantity
```

---

## Update `ShoppingCart`

The list now needs to store `CartItem` objects rather than plain `Product` objects.

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private List<CartItem> items = new ArrayList<>();

    public int getItemCount() {
        return items.stream()
                .mapToInt(CartItem::getQuantity)
                .sum();
    }

    public int getTotal() {
        return items.stream()
                .mapToInt(item -> item.getPrice() * item.getQuantity())
                .sum();
    }

    public void addItem(Product product) {
        items.add(new CartItem(product, 1));
    }

    public void addItem(Product product, int quantity) {
        items.add(new CartItem(product, quantity));
    }
}
```

### `getItemCount()`

Previously, the item count was simply the number of elements in the list:

```java
items.size()
```

That no longer works for quantities.

For example:

```text
Book × 3
```

There is only **one `CartItem`**, but the cart contains **three products**.

Therefore:

```java
items.stream()
     .mapToInt(CartItem::getQuantity)
     .sum();
```

calculates the total quantity.

---

### `getTotal()`

The total must now account for quantity:

```java
items.stream()
     .mapToInt(item -> item.getPrice() * item.getQuantity())
     .sum();
```

For:

```text
Book
Price = 10
Quantity = 3
```

the calculation is:

```text
10 × 3 = 30
```

---

### Existing `addItem(Product product)`

The original method should continue to work.

Instead of duplicating logic, it creates a `CartItem` with a quantity of `1`:

```java
public void addItem(Product product) {
    items.add(new CartItem(product, 1));
}
```

The overloaded method handles explicitly specified quantities:

```java
public void addItem(Product product, int quantity) {
    items.add(new CartItem(product, quantity));
}
```

This allows both:

```java
cart.addItem(book);
```

and:

```java
cart.addItem(book, 3);
```

---

## 🔵 Refactor

The implementation already uses streams to calculate the total quantity and total price, so there is little additional refactoring required.

One improvement is to make the collection reference `final`:

```java
private final List<CartItem> items = new ArrayList<>();
```

Similarly, `Product` and `CartItem` fields can be made `final` when their values should not change after construction.

### Refactored `ShoppingCart.java`

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private final List<CartItem> items = new ArrayList<>();

    public int getItemCount() {
        return items.stream()
                .mapToInt(CartItem::getQuantity)
                .sum();
    }

    public int getTotal() {
        return items.stream()
                .mapToInt(item -> item.getPrice() * item.getQuantity())
                .sum();
    }

    public void addItem(Product product) {
        addItem(product, 1);
    }

    public void addItem(Product product, int quantity) {
        items.add(new CartItem(product, quantity));
    }
}
```

The `addItem(Product product)` method now delegates to the overloaded method:

```java
addItem(product, 1);
```

This avoids duplicating the logic for creating and adding a `CartItem`.

## Key Takeaways

- A `CartItem` can extend `Product` to add cart-specific information such as `quantity`.
- `getItemCount()` must calculate the **sum of quantities**, not the number of `CartItem` objects.
- `getTotal()` must calculate **price × quantity**.
- Method overloading allows both:
    - `addItem(Product product)` → quantity `1`
    - `addItem(Product product, int quantity)` → specified quantity
- Existing functionality should continue to pass after introducing the new requirement.
- The refactoring step can remove duplicated logic by having one method delegate to the other.
