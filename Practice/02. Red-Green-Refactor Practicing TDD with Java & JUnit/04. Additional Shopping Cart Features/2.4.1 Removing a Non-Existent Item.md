# Overview

This requirement introduces exception handling when attempting to remove an item that does not exist in the `ShoppingCart`.

Following the **Red-Green-Refactor** cycle:

1. Write a test describing the expected behavior.    
2. Run the test and verify that it fails.
3. Implement the minimum amount of code required to make the test pass.
4. Refactor the code if necessary while ensuring all tests continue to pass.

---

## Requirement

### Description

Trying to remove an item that is not present in the cart should throw an exception indicating that the item was not found.

### Requirements

- Update the `removeItem(String id)` method to handle non-existent items.
- Create a custom `ItemNotFoundException`.
- Throw `ItemNotFoundException` when the specified item is not present in the cart.
- The exception should contain the message `"Item not found"`.

### Example

Attempting to remove an item with ID `"999"` when it is not present in the cart should throw an exception.

```text
ItemNotFoundException: Item not found
```

> [!note]  
> Although the requirement mentions `removeItem(int id)`, the provided implementation uses `String` IDs throughout the `Product` and `ShoppingCart` classes. Therefore, this implementation uses `removeItem(String id)`.

## ShoppingCart.java

The existing `removeItem()` method only removes an item if it exists. If the item does not exist, the method does nothing.

```java
import java.util.HashMap;
import java.util.Map;

public class ShoppingCart {

    private Map<String, CartItem> items = new HashMap<>();

    public int getItemCount() {
        return items.values()
                .stream()
                .mapToInt(CartItem::getQuantity)
                .sum();
    }

    public int getTotal() {
        return items.values()
                .stream()
                .mapToInt(item -> item.getPrice() * item.getQuantity())
                .sum();
    }

    public void addItem(Product product, int quantity) {
        items.put(product.getId(), new CartItem(product, quantity));
    }

    public void addItem(Product product) {
        addItem(product, 1);
    }

    public void removeItem(String id) {
        if (items.containsKey(id)) {
            CartItem item = items.get(id);

            if (item.getQuantity() > 1) {
                item.setQuantity(item.getQuantity() - 1);
            } else {
                items.remove(id);
            }
        }
    }
}
```

# Green Phase: Implement the Minimum Code

## Create `ItemNotFoundException`

Create a custom exception by extending `RuntimeException`.

```java
package exceptions;

public class ItemNotFoundException extends RuntimeException {

    public ItemNotFoundException(String message) {
        super(message);
    }
}
```

The exception can now be created with a custom error message.

For example:

```java
throw new ItemNotFoundException("Item not found");
```

## Update `removeItem()`

Import the custom exception:

```java
import exceptions.ItemNotFoundException;
```

Update `removeItem()` to throw the exception when the specified ID is not present in the cart.

```java
public void removeItem(String id) {
    if (items.containsKey(id)) {
        CartItem item = items.get(id);

        if (item.getQuantity() > 1) {
            item.setQuantity(item.getQuantity() - 1);
        } else {
            items.remove(id);
        }
    } else {
        throw new ItemNotFoundException("Item not found");
    }
}
```

The method now has two possible outcomes:

```text
Item exists
    ↓
Decrease its quantity or remove it completely

Item does not exist
    ↓
Throw ItemNotFoundException("Item not found")
```

# Key Takeaways

- A custom exception can be created by extending `RuntimeException`.
- `assertThrows()` verifies that a specific exception is thrown during test execution.
- Exceptional scenarios should also be covered by tests.
- The implementation should satisfy the behavior defined by the failing test with the minimum necessary code.
- A missing item is now treated as an exceptional condition instead of being silently ignored.

> [!important]  
> The requirement specifies the exception message `"Item not found"`. The current test verifies only the exception type. To fully verify the requirement, the exception message could also be asserted in a future test.
