# Task

Implement the next feature by addressing **Requirement #6** with the **least amount of code necessary** to make the test pass.

### Requirement

The `calculateDiscount()` function must reject negative discount percentages and throw an `IllegalArgumentException`.

The exception message must be:

```text
Discount cannot be negative
```

---

## Existing Validation

The `DiscountCalculator` class already validates discount percentages greater than `100%`:

```java
private void validateDiscountPercentage(double discountPercentage) {
    if (discountPercentage > 100) {
        throw new IllegalArgumentException("Discount percentage cannot be > 100%");
    }
}
```

To satisfy Requirement #6, we only need to extend this validation method.

---

## Solution

### `DiscountCalculator.java`

```java
import java.lang.Math;

public class DiscountCalculator {

    private void validatePrice(double price) {
        if (price < 0) {
            throw new IllegalArgumentException("Price cannot be negative");
        }
    }

    private void validateDiscountPercentage(double discountPercentage) {
        if (discountPercentage > 100) {
            throw new IllegalArgumentException("Discount percentage cannot be > 100%");
        }

        if (discountPercentage < 0) {
            throw new IllegalArgumentException("Discount cannot be negative");
        }
    }

    private double roundToCents(double amount) {
        return Math.round(amount * 100.0) / 100.0;
    }

    public double calculateDiscount(double price, double discountPercentage) {
        validatePrice(price);
        validateDiscountPercentage(discountPercentage);

        double discountMultiplier = 1 - (discountPercentage / 100);
        return roundToCents(price * discountMultiplier);
    }
}
```

### What Changed?

Only this validation was added:

```java
if (discountPercentage < 0) {
    throw new IllegalArgumentException("Discount cannot be negative");
}
```

This is a good example of the **Green phase** of TDD: implement only what is necessary to satisfy the new failing test.

# Test for Requirement #6

### `DiscountCalculatorTest.java`

```java
// Requirement #6
@Test
public void testShouldThrowExceptionForDiscountsLessThanZeroPercent() {

    // Arrange
    DiscountCalculator discountCalculator = new DiscountCalculator();

    double originalPrice = 100.0;
    double discountPercentage = -10.0;

    // Act & Assert
    Exception exception = assertThrows(
            IllegalArgumentException.class,
            () -> {
                discountCalculator.calculateDiscount(
                        originalPrice,
                        discountPercentage
                );
            }
    );

    assertEquals(
            "Discount cannot be negative",
            exception.getMessage()
    );
}
```

## TDD Cycle

### 🔴 Red

The new test is introduced:

```java
double discountPercentage = -10.0;
```

The existing implementation does not reject negative discounts, so the test fails.

### 🟢 Green

Add the minimum validation required:

```java
if (discountPercentage < 0) {
    throw new IllegalArgumentException("Discount cannot be negative");
}
```

The test now passes.

### 🔵 Refactor

There is no necessary refactoring at this point. The implementation is already simple and readable.

> [!note]  
> The important TDD principle demonstrated here is **incremental development**. We did not redesign `calculateDiscount()` or add unnecessary functionality. We made the smallest change required to satisfy Requirement #6 while preserving the behavior covered by Requirements #1–#5.
