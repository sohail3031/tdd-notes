# Goal

This task demonstrates an important principle when working with interfaces:

> **When an interface method changes, every class that implements that interface and every class that calls that method must be updated accordingly.**

The required change is to add a `LogSeverity` parameter to the `log()` method.

---

# 1. Create the `LogSeverity` Enum

**`LogSeverity.java`**

```java
package interfaces;

public enum LogSeverity {
    INFO,
    ERROR
}
```

### Purpose

An `enum` represents a fixed set of constants.

Here, logging can have two severity levels:

```text
INFO
ERROR
```

Using an enum is safer than using strings such as:

```java
"INFO"
"ERROR"
```

because Java restricts the value to one of the predefined constants.

---

# 2. Update the `ILogger` Interface

### Before

```java
void log(String message);
```

### After

```java
package interfaces;

public interface ILogger {

    void log(String message, LogSeverity logSeverity);

}
```

The interface now requires two parameters:

1. `String message`
2. `LogSeverity logSeverity`

The method contract has changed, so every implementation of `ILogger` must now follow this new signature.

---

# 3. Update `EmailService`

**`EmailService.java`**

```java
import interfaces.*;

public class EmailService {

    private final ILogger logger;
    private final IEmailSender emailSender;

    public EmailService(ILogger logger, IEmailSender emailSender) {
        this.logger = logger;
        this.emailSender = emailSender;
    }

    public boolean sendEmail(String to, String subject, String body) {

        if (to == null || to.isEmpty() || !to.contains("@")) {
            return false;
        }

        if (subject == null || subject.isEmpty()) {
            return false;
        }

        if (body == null || body.isEmpty() || body.length() > 1000) {
            return false;
        }

        logger.log("Sending email to " + to, LogSeverity.INFO);

        emailSender.send(to, subject, body);

        return true;
    }
}
```

### Key Change

The old call:

```java
logger.log("Sending email to " + to);
```

becomes:

```java
logger.log("Sending email to " + to, LogSeverity.INFO);
```

Since this is a normal successful operation, `INFO` is used as the severity.

---

# 4. Update `DummyLogger`

**`DummyLogger.java`**

```java
package dummies;

import interfaces.ILogger;
import interfaces.LogSeverity;

public class DummyLogger implements ILogger {

    @Override
    public void log(String message, LogSeverity logSeverity) {
        // Do nothing
    }
}
```

The dummy must match the exact method signature defined by `ILogger`.

Although the method receives:

```java
String message
LogSeverity logSeverity
```

it deliberately ignores both parameters.

This is correct because it is a **Dummy**.

---

# Dependency Flow

```text
                 ILogger
                    │
        log(message, severity)
                    │
                    ▼
             DummyLogger
                    │
             Does nothing


EmailService
     │
     │ logger.log(
     │     message,
     │     LogSeverity.INFO
     │ )
     ▼
 DummyLogger
```

---

# Key Learning Points

### 1. Interfaces define a contract

```java
void log(String message, LogSeverity logSeverity);
```

Any class implementing `ILogger` must provide this exact method.

---

### 2. Changing an interface has a ripple effect

Changing:

```java
void log(String message);
```

to:

```java
void log(String message, LogSeverity logSeverity);
```

requires updates to:

- `ILogger`
- `EmailService`
- `DummyLogger`
- Any other implementation of `ILogger`

---

### 3. Dummies still follow the interface contract

Even though `DummyLogger` does nothing:

```java
public void log(String message, LogSeverity logSeverity) {
    // Do nothing
}
```

it must still accept the required parameters.

A dummy's purpose is to **satisfy the dependency**, not to perform real work.

---

## Final Summary

The complete change is:

```text
LogSeverity enum
        ↓
ILogger updated
        ↓
EmailService passes LogSeverity.INFO
        ↓
DummyLogger implements the new method signature
```

The important concept here is **interface consistency**: when an interface changes, all implementations and usages of its methods must be updated to match the new contract.
