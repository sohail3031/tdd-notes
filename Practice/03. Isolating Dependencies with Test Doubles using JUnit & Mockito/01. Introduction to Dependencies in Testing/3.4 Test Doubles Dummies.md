# Task

Building on the understanding of **test doubles**, this exercise focuses on creating **dummies** by completing a test suite for the `EmailService` class.

The goal is to add the missing parts required to complete the test setup.

The dummies should satisfy the dependencies required by `EmailService` without providing any real functionality.

## What Is a Dummy?

A **dummy** is a type of test double that is created primarily to satisfy a dependency.

A dummy generally does not contain meaningful behavior. Its methods can have empty implementations because the test does not need to verify or use their functionality.

In this example, `EmailService` has two dependencies:

- `ILogger`
- `IEmailSender`

Therefore, the test needs dummy implementations of both interfaces:

- `DummyLogger`
- `DummyEmailSender`

## EmailService Dependencies

The `EmailService` constructor requires two dependencies:

```java
public EmailService(ILogger logger, IEmailSender emailSender) {
    this.logger = logger;
    this.emailSender = emailSender;
}
````

The `sendEmail()` method uses both dependencies:

```java
logger.log("Sending email to " + to, LogSeverity.INFO);
emailSender.send(to, subject, body);
```

Because these dependencies are required by the constructor, the test must provide implementations of them.

## Creating DummyEmailSender

`DummyEmailSender` implements the `IEmailSender` interface.

The interface requires the following method:

```java
void send(String to, String subject, String body);
```

The dummy implementation does not need to perform any real email-sending functionality.

```java
package dummies;

import interfaces.IEmailSender;

public class DummyEmailSender implements IEmailSender {

    @Override
    public void send(String to, String subject, String body) {
        // Do nothing
    }
}
```

## Creating DummyLogger

`DummyLogger` implements the `ILogger` interface.

The interface requires the following method:

```java
void log(String message, LogSeverity severity);
```

Again, the dummy does not need to perform any actual logging.

```java
package dummies;

import interfaces.ILogger;
import interfaces.LogSeverity;

public class DummyLogger implements ILogger {

    @Override
    public void log(String message, LogSeverity severity) {
        // Do nothing
    }
}
```

## Using the Dummies in the Test

The test class creates instances of both dummy classes:

```java
private DummyLogger dummyLogger = new DummyLogger();
private DummyEmailSender dummyEmailSender = new DummyEmailSender();
```

These objects are then passed to the `EmailService` constructor during test setup:

```java
@BeforeEach
public void setUp() {
    // Arrange
    emailService = new EmailService(dummyLogger, dummyEmailSender);
}
```

This satisfies the dependencies required by `EmailService`.

## Complete EmailServiceTest

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

import dummies.*;

public class EmailServiceTest {

    private EmailService emailService;
    private DummyLogger dummyLogger = new DummyLogger();
    private DummyEmailSender dummyEmailSender = new DummyEmailSender();

    @BeforeEach
    public void setUp() {
        // Arrange
        emailService = new EmailService(dummyLogger, dummyEmailSender);
    }

    @Test
    public void shouldAcceptValidEmailParameters() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            "This is a test"
        );

        // Assert
        assertTrue(result);
    }

    @Test
    public void shouldRejectInvalidEmailAddress() {
        // Act
        boolean result = emailService.sendEmail(
            "invalid-email",
            "Hello",
            "This is a test"
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectEmptySubject() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "",
            "This is a test"
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectEmptyBody() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            ""
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectBodyExceeding1000Characters() {
        // Arrange
        String longBody = new String(new char[1001]).replace('\0', 'a');

        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            longBody
        );

        // Assert
        assertFalse(result);
    }
}
```

## Supporting Interfaces

### ILogger

```java
package interfaces;

public interface ILogger {
    void log(String message, LogSeverity severity);
}
```

### IEmailSender

```java
package interfaces;

public interface IEmailSender {
    void send(String to, String subject, String body);
}
```

### LogSeverity

```java
package interfaces;

public enum LogSeverity {
    INFO,
    ERROR
}
```

## Key Lesson

The purpose of a **dummy** is to satisfy a dependency without providing real functionality.

In this example:

```text
EmailService
    |
    +-- ILogger
    |      |
    |      +-- DummyLogger
    |
    +-- IEmailSender
           |
           +-- DummyEmailSender
```

The test does not need to verify logging or email delivery. It only needs `EmailService` to have valid objects for its required dependencies.

> [!NOTE]  
> Dummies are useful when a dependency is required by the class under test but its behavior is irrelevant to the particular test.

## Important Distinction

A dummy is different from other types of test doubles such as **stubs, mocks, and fakes**.

The important characteristic of a dummy is that it exists mainly to **satisfy a dependency**.

In this exercise:

- `DummyLogger` satisfies the `ILogger` dependency.
- `DummyEmailSender` satisfies the `IEmailSender` dependency.
- Neither dummy performs real logging or email sending.
- The tests focus only on the validation behavior of `EmailService`.
