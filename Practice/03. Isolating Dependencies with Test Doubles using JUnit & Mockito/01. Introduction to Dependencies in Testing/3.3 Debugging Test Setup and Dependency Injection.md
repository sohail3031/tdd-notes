# Task

The provided test suite for the `EmailService` class is not passing as expected.

The task is to identify and fix the bug in the test suite by carefully examining the test setup and the construction of `EmailService`.

Once the test setup is corrected, all tests should successfully pass.

## Problem

The initial `EmailServiceTest` creates the `EmailService` object using:

```java
emailService = new EmailService();
````

However, the `EmailService` class does not have a no-argument constructor.

Instead, its constructor requires two dependencies:

```java
public EmailService(ILogger logger, IEmailSender emailSender) {
    this.logger = logger;
    this.emailSender = emailSender;
}
```

Therefore, the test must provide implementations of `ILogger` and `IEmailSender` when constructing `EmailService`.

## Understanding the Dependencies

`EmailService` depends on two interfaces:

- `ILogger` — responsible for logging messages.    
- `IEmailSender` — responsible for sending emails.

For unit testing, we can use dummy implementations of these interfaces.

The project provides:

- `DummyLogger`
- `DummyEmailSender`

These dummy classes satisfy the required dependencies without performing any real logging or email sending.

## DummyLogger

```java
package dummies;

import interfaces.ILogger;
import interfaces.LogSeverity;

public class DummyLogger implements ILogger {

    @Override
    public void log(String message, LogSeverity severity) {
        // Do nothing
    }
}
```

## DummyEmailSender

```java
package dummies;

import interfaces.IEmailSender;

public class DummyEmailSender implements IEmailSender {

    @Override
    public void send(String to, String subject, String body) {
        // Do nothing
    }
}
```

## Correcting the Test Setup

The test class should create instances of the dummy dependencies:

```java
private DummyLogger dummyLogger = new DummyLogger();
private DummyEmailSender dummyEmailSender = new DummyEmailSender();
```

These dependencies are then passed to the `EmailService` constructor inside the `setUp()` method:

```java
@BeforeEach
public void setUp() {
    // Arrange
    emailService = new EmailService(dummyLogger, dummyEmailSender);
}
```

Using `@BeforeEach` ensures that a properly initialized `EmailService` instance is created before every test.

## Final Test Code

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

import dummies.*;

public class EmailServiceTest {

    private EmailService emailService;
    private DummyLogger dummyLogger = new DummyLogger();
    private DummyEmailSender dummyEmailSender = new DummyEmailSender();

    @BeforeEach
    public void setUp() {
        // Arrange
        emailService = new EmailService(dummyLogger, dummyEmailSender);
    }

    @Test
    public void shouldAcceptValidEmailParameters() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            "This is a test"
        );

        // Assert
        assertTrue(result);
    }

    @Test
    public void shouldRejectInvalidEmailAddress() {
        // Act
        boolean result = emailService.sendEmail(
            "invalid-email",
            "Hello",
            "This is a test"
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectEmptySubject() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "",
            "This is a test"
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectEmptyBody() {
        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            ""
        );

        // Assert
        assertFalse(result);
    }

    @Test
    public void shouldRejectBodyExceeding1000Characters() {
        // Arrange
        String longBody = new String(new char[1001]).replace('\0', 'a');

        // Act
        boolean result = emailService.sendEmail(
            "test@example.com",
            "Hello",
            longBody
        );

        // Assert
        assertFalse(result);
    }
}
```

## Key Lesson

The problem was not with the `sendEmail()` logic. The problem was with the **test setup**.

The test attempted to construct `EmailService` without providing its required dependencies.

```java
emailService = new EmailService();
```

The correct construction is:

```java
emailService = new EmailService(dummyLogger, dummyEmailSender);
```

This is an example of **dependency injection**.

> [!NOTE]  
> When a class requires dependencies through its constructor, the test must provide those dependencies when creating the object under test.

## TDD / Unit Testing Concept

Using dummy implementations allows the test to focus on the behavior of `EmailService` without relying on real logging or email-sending functionality.

The dependency flow is:

```text
EmailServiceTest
       |
       v
EmailService
   /        \
  v          v
ILogger   IEmailSender
  |          |
  v          v
DummyLogger  DummyEmailSender
```

This keeps the unit test isolated from external dependencies.
