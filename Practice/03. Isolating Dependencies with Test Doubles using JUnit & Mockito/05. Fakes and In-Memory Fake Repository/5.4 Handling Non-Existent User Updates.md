# Task

Implement functionality to handle the scenario where a user attempts to update the name of a **non-existent user**.

The goal is to ensure that the application gracefully handles this case by throwing an appropriate exception with the message:

```text
User not found
```

---

## Requirements

The `updateUserName` method in `UserService` should:

1. Search for the user using the provided ID.
2. Check whether the user exists.
3. If the user does not exist, throw an `IllegalArgumentException` with the message `"User not found"`.
4. If the user exists, update the user's name normally.

---

## TDD Approach

### Red

First, update the test to verify the expected behavior for a non-existent user.

The test attempts to update the user with ID `"999"`, which does not exist in the repository.

```java
@Test
public void testUpdateUserNameThrowsExceptionForNonExistentUser() {

    // Act & Assert
    Exception exception = assertThrows(
            IllegalArgumentException.class,
            () -> userService.updateUserName("999", "newName")
    );

    assertEquals("User not found", exception.getMessage());
}
```

The test initially fails because `updateUserName` does not check whether the user exists before attempting the update.

---

## Green

Modify `updateUserName` to first retrieve the user using `repository.findById(id)`.

If the returned user is `null`, throw an `IllegalArgumentException`.

```java
public User updateUserName(String id, String newName) throws Exception {
    User user = repository.findById(id);

    if (user == null) {
        throw new IllegalArgumentException("User not found");
    }

    return repository.update(id, new User(null, null, newName, null));
}
```

Now the test passes.

### Why This Works

`InMemoryUserRepository.findById()` returns `null` when the requested ID does not exist:

```java
@Override
public User findById(String id) {
    return users.get(id);
}
```

Therefore, `UserService` can detect the missing user before calling `repository.update()`.

## Refactored `UserService`

```java
public class UserService {

    private final IUserRepository repository;

    public UserService(IUserRepository repository) {
        this.repository = repository;
    }

    public User registerUser(String email, String name) throws Exception {
        User existingUser = repository.findByEmail(email);

        if (existingUser != null) {
            throw new Exception("User with this email already exists");
        }

        return repository.create(new User(email, name));
    }

    public User updateUserName(String id, String newName) throws Exception {
        User user = repository.findById(id);

        if (user == null) {
            throw new IllegalArgumentException("User not found");
        }

        return repository.update(
                id,
                new User(null, null, newName, null)
        );
    }
}
```

## Why Check Before Calling `update()`?

The repository's `update()` method already handles a missing user by returning `null`:

```java
User existing = users.get(id);

if (existing == null) {
    return null;
}
```

However, the service layer should provide meaningful business behavior rather than silently returning `null`.

The `UserService` therefore checks for the user first and throws a clear exception:

```java
if (user == null) {
    throw new IllegalArgumentException("User not found");
}
```

This makes the application's behavior explicit and easier for callers to understand.

## AAA Pattern

The test follows the **Arrange-Act-Assert (AAA)** pattern.

### Arrange

There is no explicit setup required because the `@BeforeEach` method creates a new empty repository.

### Act

Attempt to update a user that does not exist:

```java
userService.updateUserName("999", "newName");
```

### Assert

Verify the exception type and message:

```java
assertEquals("User not found", exception.getMessage());
```

---

## Key Takeaways

- Always validate that a resource exists before updating it.    
- `findById()` returns `null` when the user does not exist.
- The service layer converts the missing user condition into a meaningful exception.
- `assertThrows()` is used to verify expected exceptions in JUnit.
- The exception message can be verified using `getMessage()`.
- `IllegalArgumentException` is appropriate when the supplied user ID does not identify a valid user.
- This test improves the robustness of the `updateUserName` functionality.
- TDD helps identify and implement edge cases such as updating a non-existent user.
