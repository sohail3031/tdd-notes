# Supporting Code

## `InMemoryUserRepository.java`

The `InMemoryUserRepository` acts as a **Fake test double**.

It stores users in memory instead of communicating with a real database.

The repository provides the `findById()` and `update()` methods needed for user updates.

### Find a User

```java
@Override
public User findById(String id) {
    return users.get(id);
}
```

### Update a User

```java
@Override
public User update(String id, User data) {
    User existing = users.get(id);

    if (existing == null) {
        return null;
    }

    User updated = new User(
            existing.getId(),
            data.getEmail() != null ? data.getEmail() : existing.getEmail(),
            data.getName() != null ? data.getName() : existing.getName(),
            existing.getCreatedAt()
    );

    users.put(id, updated);
    return updated;
}
```

The `update()` method preserves the existing user's:

- ID    
- Email, unless a new email is provided
- Creation date

It updates the name when a new name is provided.

# 2. Green — Implement the Minimum Code

The minimum implementation needs to:

1. Find the user using their ID.    
2. Update the user's name.
3. Return the updated user.

```java
public User updateUserName(String id, String newName) {

    User user = repository.findById(id);
    user.setName(newName);

    return user;
}
```

### How It Works

The method first retrieves the user:

```java
User user = repository.findById(id);
```

Then it updates the name:

```java
user.setName(newName);
```

Finally, it returns the updated user:

```java
return user;
```

The flow is:

```text
updateUserName(id, newName)
            ↓
     repository.findById(id)
            ↓
       Find existing User
            ↓
       user.setName(newName)
            ↓
       Return updated User
```

The test should now pass.

This completes the **Green** phase.

## `UserServiceTest.java`

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

import java.util.List;

public class UserServiceTest {

    private InMemoryUserRepository userRepository;
    private UserService userService;

    @BeforeEach
    public void setUp() {
        userRepository = new InMemoryUserRepository();
        userService = new UserService(userRepository);
    }

    @Test
    public void testRegisterUserCreatesNewUserSuccessfully() throws Exception {

        // Act
        User user = userService.registerUser(
                "test@example.com",
                "Test User"
        );

        // Assert
        assertEquals("test@example.com", user.getEmail());
        assertEquals("Test User", user.getName());
        assertNotNull(user.getId());
        assertNotNull(user.getCreatedAt());

        List<User> repositoryUsers = userRepository.findAll();

        assertEquals(1, repositoryUsers.size());
        assertEquals("Test User", repositoryUsers.get(0).getName());
    }

    @Test
    public void testRegisterUserWithDuplicateEmailThrowsException() throws Exception {

        // Arrange
        String duplicateEmail = "test@example.com";

        userService.registerUser(
                duplicateEmail,
                "First User"
        );

        // Act & Assert
        Exception exception = assertThrows(Exception.class, () -> {
            userService.registerUser(
                    duplicateEmail,
                    "Second User"
            );
        });

        assertEquals(
                "User with this email already exists",
                exception.getMessage()
        );
    }

    @Test
    public void testUpdateUserNameUpdatesUserSuccessfully() throws Exception {

        // Arrange
        User user = userService.registerUser(
                "test@example.com",
                "Test User"
        );

        // Act
        User updatedUser = userService.updateUserName(
                user.getId(),
                "New Name"
        );

        // Assert
        assertEquals("New Name", updatedUser.getName());
        assertEquals("test@example.com", updatedUser.getEmail());
        assertEquals(user.getId(), updatedUser.getId());
    }
}
```

## `UserService.java`

```java
public class UserService {

    private final IUserRepository repository;

    public UserService(IUserRepository repository) {
        this.repository = repository;
    }

    public User registerUser(String email, String name) throws Exception {

        // Check if a user with the given email already exists
        User existingUser = repository.findByEmail(email);

        if (existingUser != null) {
            throw new Exception(
                    "User with this email already exists"
            );
        }

        // Create and return the new user
        return repository.create(new User(email, name));
    }

    public User updateUserName(String id, String newName) {

        User user = repository.findById(id);
        user.setName(newName);

        return user;
    }
}
```

# Key Takeaways

- Use a **Fake repository** to simulate data storage during testing.    
- Register a user before testing an update operation.
- Use the user's ID to identify the user that needs to be updated.
- `repository.findById(id)` retrieves the existing user.
- `setName(newName)` changes only the user's name.
- The test should verify both the changed attribute and the unchanged attributes.
- Testing only the new name is less comprehensive than verifying the user's email and ID as well.
- The test demonstrates the **Arrange → Act → Assert (AAA)** pattern.
- The exercise also reinforces the **Red → Green → Refactor** TDD cycle.

### Arrange

### Assert
