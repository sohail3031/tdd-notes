# Objective

In this task, we extend the previous user registration functionality to ensure that **duplicate email addresses are not allowed**.

We will:

1. Write a test that verifies duplicate email registration throws an exception.
2. Implement the required validation in `UserService`.
3. Use the `InMemoryUserRepository` fake to check whether the email already exists.
4. Verify the exception message.

The TDD approach is:

> **Red → Green → Refactor**

---

# Requirements

When registering a new user:

- If the email does not already exist, create the user.
- If the email already exists, do not create another user.
- Throw an `IllegalArgumentException`.
- The exception message must be:

```text
User with this email already exists
````

# Supporting Code

## `InMemoryUserRepository.java`

`InMemoryUserRepository` is the **Fake test double** used instead of a real database.

```java
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

public class InMemoryUserRepository implements IUserRepository {

    private final Map<String, User> users = new ConcurrentHashMap<>();
    private int currentId = 1;

    private synchronized String generateId() {
        return String.valueOf(currentId++);
    }

    @Override
    public User create(User userData) {
        User user = new User(
                generateId(),
                userData.getEmail(),
                userData.getName(),
                new Date()
        );

        users.put(user.getId(), user);
        return user;
    }

    @Override
    public User findById(String id) {
        return users.get(id);
    }

    @Override
    public User findByEmail(String email) {
        return users.values().stream()
                .filter(user -> user.getEmail().equals(email))
                .findFirst()
                .orElse(null);
    }

    @Override
    public User update(String id, User data) {
        User existing = users.get(id);

        if (existing == null) {
            return null;
        }

        User updated = new User(
                existing.getId(),
                data.getEmail() != null ? data.getEmail() : existing.getEmail(),
                data.getName() != null ? data.getName() : existing.getName(),
                existing.getCreatedAt()
        );

        users.put(id, updated);
        return updated;
    }

    @Override
    public boolean delete(String id) {
        return users.remove(id) != null;
    }

    @Override
    public List<User> findAll() {
        return new ArrayList<>(users.values());
    }

    public void clear() {
        users.clear();
        currentId = 1;
    }
}
```

The method relevant to this task is:

```java
@Override
public User findByEmail(String email) {
    return users.values().stream()
            .filter(user -> user.getEmail().equals(email))
            .findFirst()
            .orElse(null);
}
```

This allows `UserService` to determine whether a user with the specified email already exists.

## 1. Red — Write the Failing Test

First, create a user with the email `test@example.com`.

Then, attempt to register another user using the same email.

The second registration should throw an exception.

```java
@Test
public void testRegisterUserWithDuplicateEmailThrowsException() throws Exception {

    // Arrange
    User user = userService.registerUser(
            "test@example.com",
            "Test User"
    );

    // Act & Assert
    Exception exception = assertThrows(
            IllegalArgumentException.class,
            () -> userService.registerUser(
                    "test@example.com",
                    "Test User"
            )
    );

    assertEquals(
            "User with this email already exists",
            exception.getMessage()
    );
}
```

### What Does This Test Verify?

The test performs two registration attempts:

```text
First registration
test@example.com
        ↓
User created successfully


Second registration
test@example.com
        ↓
Duplicate email detected
        ↓
IllegalArgumentException
```

Initially, `UserService` does not perform the duplicate email check.

Therefore, the second registration would also succeed, causing the test to fail.


This is the **Red** phase.

# 2. Green — Implement the Minimum Code

Now modify `registerUser()` to check whether the email already exists.

```java
public User registerUser(String email, String name) throws Exception {

    if (repository.findByEmail(email) != null) {
        throw new IllegalArgumentException(
                "User with this email already exists"
        );
    }

    return repository.create(new User(email, name));
}
```

The important part is:

```java
if (repository.findByEmail(email) != null) {
    throw new IllegalArgumentException(
            "User with this email already exists"
    );
}
```

### How It Works

When `registerUser()` is called:

1. `repository.findByEmail(email)` searches for an existing user.
    
2. If no user is found, it returns `null`.
    
3. If a user is found, it returns the existing `User`.
    
4. If an existing user is found, `IllegalArgumentException` is thrown.
    
5. Otherwise, a new user is created.
    

The flow is:

```text
registerUser(email, name)
          ↓
repository.findByEmail(email)
          ↓
     User exists?
       ↙       ↘
     Yes        No
      ↓          ↓
  Throw       Create
 Exception      User
```

The test should now pass.

This completes the **Green** phase.

# Key Concepts

## `assertThrows()`

JUnit's `assertThrows()` is used to verify that a specific exception is thrown by a piece of code.

```java
Exception exception = assertThrows(
        IllegalArgumentException.class,
        () -> userService.registerUser(
                "test@example.com",
                "Test User"
        )
);
```

This assertion verifies two things:

1. An exception is thrown.
    
2. The exception is of type `IllegalArgumentException`.
    

We can then verify the exception message:

```java
assertEquals(
        "User with this email already exists",
        exception.getMessage()
);
```

---

## Why Check the Repository Before Creating the User?

Without the validation:

```java
return repository.create(new User(email, name));
```

every registration request would create a new user, even when the email already exists.

With the validation:

```java
if (repository.findByEmail(email) != null) {
    throw new IllegalArgumentException(
            "User with this email already exists"
    );
}
```

the service prevents duplicate registrations.

# Key Takeaways

- Use `assertThrows()` to verify that code throws an expected exception.
    
- `IllegalArgumentException` can be used when an invalid argument is supplied to a method.
    
- `repository.findByEmail()` can be used to detect duplicate email addresses.
    
- The validation should happen **before** creating the new user.
    
- The fake repository allows us to test this behavior without using a real database.
    
- The test verifies both the **exception type** and the **exception message**.
    
- This is an example of testing **business rules**, not just implementation details.
    

## Important Pattern

```java
if (repository.findByEmail(email) != null) {
    throw new IllegalArgumentException(
            "User with this email already exists"
    );
}

return repository.create(new User(email, name));
```

The general pattern is:

> **Validate → Throw exception if invalid → Perform the operation if valid**
