- A user is created successfully.
- The user's email is stored correctly.

- The user receives an ID.

- The user is stored in the in-memory repository.

We will follow the **Test-Driven Development (TDD)** approach:

> **Red → Green → Refactor**

# Supporting Code

## `InMemoryUserRepository.java`

The `InMemoryUserRepository` is our **Fake**.

Instead of communicating with a real database, it stores users in a `ConcurrentHashMap`.

```java
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

public class InMemoryUserRepository implements IUserRepository {

    private final Map<String, User> users = new ConcurrentHashMap<>();
    private int currentId = 1;

    private synchronized String generateId() {
        return String.valueOf(currentId++);
    }

    @Override
    public User create(User userData) {
        User user = new User(
                generateId(),
                userData.getEmail(),
                userData.getName(),
                new Date()
        );

        users.put(user.getId(), user);
        return user;
    }

    @Override
    public User findById(String id) {
        return users.get(id);
    }

    @Override
    public User findByEmail(String email) {
        return users.values().stream()
                .filter(user -> user.getEmail().equals(email))
                .findFirst()
                .orElse(null);
    }

    @Override
    public User update(String id, User data) {
        User existing = users.get(id);

        if (existing == null) {
            return null;
        }

        User updated = new User(
                existing.getId(),
                data.getEmail() != null ? data.getEmail() : existing.getEmail(),
                data.getName() != null ? data.getName() : existing.getName(),
                existing.getCreatedAt()
        );

        users.put(id, updated);
        return updated;
    }

    @Override
    public boolean delete(String id) {
        return users.remove(id) != null;
    }

    @Override
    public List<User> findAll() {
        return new ArrayList<>(users.values());
    }

    public void clear() {
        users.clear();
        currentId = 1;
    }
}
```

### Important Points

The fake repository provides several repository operations:

- `create()` — Creates and stores a user.    
- `findById()` — Finds a user by ID.
- `findByEmail()` — Finds a user by email.
- `update()` — Updates an existing user.
- `delete()` — Deletes a user.
- `findAll()` — Returns all stored users.
- `clear()` — Removes all users and resets the ID counter.

The important part for this task is the `create()` method:

```java
@Override
public User create(User userData) {
    User user = new User(
            generateId(),
            userData.getEmail(),
            userData.getName(),
            new Date()
    );

    users.put(user.getId(), user);
    return user;
}
```

This method:

1. Generates a unique ID.    
2. Copies the email and name from the provided user.
3. Creates a timestamp.
4. Stores the user in the in-memory map.
5. Returns the newly created user.

## `IUserRepository.java`

`IUserRepository` defines the contract that `UserService` uses to interact with the repository.

```java
import java.util.List;

public interface IUserRepository {

    User create(User user);

    User findById(String id);

    User findByEmail(String email);

    User update(String id, User user);

    boolean delete(String id);

    List<User> findAll();
}
```

The `UserService` depends on the interface rather than directly depending on a specific database implementation.

This allows us to provide `InMemoryUserRepository` as a fake during testing.

# 2. Green — Implement the Minimum Code

Now implement the minimum amount of code necessary to make the test pass.

```java
public class UserService {

    private final IUserRepository repository;

    public UserService(IUserRepository repository) {
        this.repository = repository;
    }

    public User registerUser(String email, String name) {
        return this.repository.create(new User(email, name));
    }
}
```

The `registerUser()` method:

1. Creates a new `User` object using the provided email and name.    
2. Passes the new user to the repository's `create()` method.
3. Returns the user created by the repository.

The fake repository handles the rest:

```text
registerUser()
      ↓
new User(email, name)
      ↓
repository.create(user)
      ↓
InMemoryUserRepository
      ↓
Generate ID + Created Date
      ↓
Store User
      ↓
Return User
```

After implementing this method, the test should pass.

This completes the **Green** phase.

# Key Concepts

## Fake Test Double

`InMemoryUserRepository` is a **Fake** because it provides a working implementation of the repository interface while avoiding the complexity of a real database.

```text
Production:

UserService → IUserRepository → Real Database


Test:

UserService → IUserRepository → InMemoryUserRepository
                                      ↓
                              In-Memory Storage
```

## Dependency Injection

`UserService` receives the repository through its constructor:

```java
public UserService(IUserRepository repository) {
    this.repository = repository;
}
```

This is an example of **Dependency Injection**.

It allows us to provide different repository implementations depending on the environment.

For example:

- Production → Real database repository    
- Tests → `InMemoryUserRepository`

## Test Isolation

The fake repository provides a `clear()` method:

```java
public void clear() {
    users.clear();
    currentId = 1;
}
```

This allows tests to start with a clean repository state and prevents data from one test from affecting another.

# Key Takeaways

- A **Fake** is a simplified but functional implementation of a real dependency.    
- `InMemoryUserRepository` acts as a fake database repository.
- The fake allows us to test `UserService` without connecting to a real database.
- `registerUser()` creates a `User` and delegates persistence to the repository.
- The repository is injected through the `IUserRepository` interface.
- The test verifies both the returned `User` and the state of the repository.
- The test checks:
    - Email
    - Name
    - ID
    - Creation timestamp
    - Repository contents
- This exercise demonstrates how **TDD + Dependency Injection + Fakes** can be used together to create fast and reliable tests.
