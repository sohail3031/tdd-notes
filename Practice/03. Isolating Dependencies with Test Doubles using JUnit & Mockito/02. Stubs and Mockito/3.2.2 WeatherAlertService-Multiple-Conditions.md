# Task

In this exercise, we continue building the `WeatherAlertService` using a stubbed `WeatherService`.

The goal is to extend the existing functionality to handle multiple temperature conditions and verify the behavior through automated tests.

The service should now:

1. Return an extreme heat warning when the temperature is above `35°C`.    
2. Return a freezing warning when the temperature is below `0°C`.
3. Use a stubbed `WeatherService` to simulate different weather conditions.
4. Ensure both tests pass successfully.

---

# Requirements

The `WeatherAlertService` must return the following alerts based on temperature:

|Temperature Condition|Expected Alert|
|---|---|
|Greater than `35°C`|`"Extreme heat warning. Stay hydrated!"`|
|Less than `0°C`|`"Freezing warning. Stay warm!"`|
|Between `0°C` and `35°C`|`null`|

> [!NOTE]  
> The current requirements only define alerts for extreme heat and freezing conditions. For all other temperatures, the method returns `null`.

# Supporting Classes

## IWeatherService

The `IWeatherService` interface defines the dependency used by the `WeatherAlertService`.

```java
public interface IWeatherService {

    WeatherData getCurrentWeather(String location);
}
```

The `WeatherAlertService` does not need to know how the weather data is retrieved. It only depends on the interface.

This allows us to replace a real weather service with a test double during testing.

---

## WeatherData

The `WeatherData` class stores information about the current weather.

```java
public class WeatherData {

    private final int temperature;
    private final String conditions;

    public WeatherData(int temperature, String conditions) {
        this.temperature = temperature;
        this.conditions = conditions;
    }

    public int getTemperature() {
        return temperature;
    }

    public String getConditions() {
        return conditions;
    }
}
```

The class contains:

- `temperature` — The current temperature in degrees Celsius.
- `conditions` — A description of the weather, such as `"sunny"` or `"snowy"`.

---

# WeatherServiceStub

The tests use a hand-crafted stub called `WeatherServiceStub`.

```java
class WeatherServiceStub implements IWeatherService {

    private WeatherData currentWeather =
        new WeatherData(20, "sunny");

    public void setWeather(int temperature, String conditions) {
        this.currentWeather =
            new WeatherData(temperature, conditions);
    }

    @Override
    public WeatherData getCurrentWeather(String location) {
        return currentWeather;
    }
}
```

## How the Stub Works

The stub initially contains default weather data:

```java
private WeatherData currentWeather =
    new WeatherData(20, "sunny");
```

The test can change the weather data by calling:

```java
weatherService.setWeather(36, "sunny");
```

or:

```java
weatherService.setWeather(-5, "snowy");
```

When `WeatherAlertService` calls:

```java
weatherService.getCurrentWeather("London");
```

the stub returns the predefined `WeatherData`.

> [!IMPORTANT]  
> The stub does not retrieve real weather information. Its purpose is to provide controlled and predictable data for the test.

# Red: Add the Freezing Temperature Test

The existing test verifies the extreme heat scenario.

The next requirement is to add a test for freezing temperatures.

The test should simulate:

- Temperature: `-5°C`
- Conditions: `"snowy"`
- Location: `"London"`
- Expected result: `"Freezing warning. Stay warm!"`

## Test Using the AAA Pattern

### Arrange

Configure the stub with freezing weather conditions.

```java
weatherService.setWeather(-5, "snowy");
```

### Act

Call the method being tested.

```java
String alert = alertService.shouldSendAlert("London");
```

### Assert

Verify that the correct freezing warning is returned.

```java
assertEquals("Freezing warning. Stay warm!", alert);
```

# Complete Test Class

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

public class WeatherAlertServiceTest {

    private WeatherServiceStub weatherService;
    private WeatherAlertService alertService;

    class WeatherServiceStub implements IWeatherService {

        private WeatherData currentWeather =
            new WeatherData(20, "sunny");

        public void setWeather(
            int temperature,
            String conditions
        ) {
            this.currentWeather =
                new WeatherData(temperature, conditions);
        }

        @Override
        public WeatherData getCurrentWeather(String location) {
            return currentWeather;
        }
    }

    @BeforeEach
    public void setUp() {
        weatherService = new WeatherServiceStub();
        alertService = new WeatherAlertService(weatherService);
    }

    @Test
    public void testShouldReturnHeatWarningWhenTemperatureIsAbove35() {
        // Arrange
        weatherService.setWeather(36, "sunny");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Extreme heat warning. Stay hydrated!",
            alert
        );
    }

    @Test
    public void testShouldReturnFreezingWarningWhenTemperatureIsBelow0() {
        // Arrange
        weatherService.setWeather(-5, "snowy");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Freezing warning. Stay warm!",
            alert
        );
    }
}
```

# Green: Implement the Freezing Alert Logic

After adding the new test, update the `WeatherAlertService` with the minimum logic required to make both tests pass.

```java
public class WeatherAlertService {

    private final IWeatherService weatherService;

    public WeatherAlertService(
        IWeatherService weatherService
    ) {
        this.weatherService = weatherService;
    }

    public String shouldSendAlert(String location) {
        WeatherData weatherData =
            weatherService.getCurrentWeather(location);

        if (weatherData.getTemperature() > 35) {
            return "Extreme heat warning. Stay hydrated!";
        }

        if (weatherData.getTemperature() < 0) {
            return "Freezing warning. Stay warm!";
        }

        return null;
    }
}
```

# Key Concepts

## Stub

`WeatherServiceStub` is a **stub** because it returns predefined data to the system under test.

```java
@Override
public WeatherData getCurrentWeather(String location) {
    return currentWeather;
}
```

The test controls that data through:

```java
weatherService.setWeather(
    temperature,
    conditions
);
```

---

## Dependency Injection

`WeatherAlertService` receives `IWeatherService` through its constructor.

```java
public WeatherAlertService(
    IWeatherService weatherService
)
```

This makes it possible to substitute a real implementation with a test double.

---

## Test Isolation

The tests do not depend on:

- A real weather API.
- Network connectivity.
- Actual weather conditions.
- External systems.

This makes the tests deterministic, fast, and repeatable.

---

## Arrange-Act-Assert

Both tests follow the AAA pattern.

### Arrange

Configure the required weather conditions.

```java
weatherService.setWeather(-5, "snowy");
```

### Act

Execute the method under test.

```java
String alert =
    alertService.shouldSendAlert("London");
```

### Assert

Verify the expected result.

```java
assertEquals(
    "Freezing warning. Stay warm!",
    alert
);
```

# Key Takeaways

- A **stub** provides controlled and predefined responses during testing.
- The `WeatherServiceStub` allows different weather conditions to be simulated without using real weather data.
- The `setWeather()` method makes the stub configurable for each test scenario.
- Each new requirement should ideally be introduced through a new test.
- The implementation is expanded incrementally to satisfy the newly added test.
- `WeatherAlertService` now supports both extreme heat and freezing temperature alerts.
- Dependency injection makes it easy to replace real dependencies with test doubles.
- The tests remain isolated, predictable, and independent of external services.
