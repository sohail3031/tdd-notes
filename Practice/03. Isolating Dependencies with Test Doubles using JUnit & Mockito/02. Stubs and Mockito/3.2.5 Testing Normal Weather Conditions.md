# Task

In this exercise, we extend the `WeatherAlertService` test suite by testing **normal weather conditions**.

The goal is to verify that when the weather is neither extremely hot, freezing, nor stormy, the service returns `null` because no alert is required.

---

# Test Scenario

For the normal weather scenario, we use:

- **Location:** `London`    
- **Temperature:** `20°C`
- **Conditions:** `sunny`
- **Expected alert:** `null`

The existing `stubWeatherData()` helper method is used to configure the Mockito test double.

---

# Test Using the AAA Pattern

The test follows the **Arrange-Act-Assert (AAA)** pattern.

## Arrange

Configure the stub to return normal weather conditions:

```java
stubWeatherData("London", 20, "sunny");
```

This configures the mock so that:

```java
weatherServiceMock.getCurrentWeather("London")
```

returns:

```java
new WeatherData(20, "sunny")
```

## Act

Call the method under test:

```java
String alert = alertService.shouldSendAlert("London");
```

## Assert

Verify that no alert is returned:

```java
assertNull(alert);
```

> [!TIP]  
> `assertNull(alert)` is preferred over `assertEquals(null, alert)` because it clearly communicates that the purpose of the assertion is to verify that the value is `null`.

---

# Completed Test

```java
@Test
public void testShouldReturnNoAlertWhenWeatherIsNormal() {
    // Arrange
    stubWeatherData("London", 20, "sunny");

    // Act
    String alert = alertService.shouldSendAlert("London");

    // Assert
    assertNull(alert);
}
```

# Complete Test Class

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;

import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertNull;
import static org.mockito.Mockito.when;

@ExtendWith(MockitoExtension.class)
public class WeatherAlertServiceTest {

    @Mock
    private IWeatherService weatherServiceMock;

    @InjectMocks
    private WeatherAlertService alertService;

    @Test
    public void testShouldReturnHeatWarningWhenTemperatureIsAbove35() {
        // Arrange
        stubWeatherData("London", 36, "sunny");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Extreme heat warning. Stay hydrated!",
            alert
        );
    }

    @Test
    public void testShouldReturnFreezingWarningWhenTemperatureIsBelow0() {
        // Arrange
        stubWeatherData("London", -5, "snowy");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Freezing warning. Stay warm!",
            alert
        );
    }

    @Test
    public void testShouldReturnStormWarningWhenConditionsAreThunderstorm() {
        // Arrange
        stubWeatherData("London", 20, "thunderstorm");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Storm warning. Stay indoors if possible!",
            alert
        );
    }

    @Test
    public void testShouldReturnNoAlertWhenWeatherIsNormal() {
        // Arrange
        stubWeatherData("London", 20, "sunny");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertNull(alert);
    }

    // Helper method to stub weather data
    private void stubWeatherData(
            String location,
            int temperature,
            String conditions
    ) {
        when(weatherServiceMock.getCurrentWeather(location))
            .thenReturn(new WeatherData(temperature, conditions));
    }
}
```

# Why Does the Service Return `null`?

The `WeatherAlertService` checks for three alert conditions:

```java
if (weather.getTemperature() > 35) {
    return "Extreme heat warning. Stay hydrated!";
} else if (weather.getTemperature() < 0) {
    return "Freezing warning. Stay warm!";
} else if (weather.getConditions().equalsIgnoreCase("thunderstorm")) {
    return "Storm warning. Stay indoors if possible!";
}
```

If none of these conditions is true, execution reaches:

```java
return null;
```

For the normal weather scenario:

```text
Temperature = 20°C
Conditions  = sunny
```

Therefore:

```text
20 > 35             → false
20 < 0              → false
sunny = thunderstorm → false
```

So the method returns:

```text
null
```

---

# `assertEquals(null, alert)` vs. `assertNull(alert)`

The provided final code uses:

```java
assertEquals(null, alert);
```

This can work, but the better JUnit assertion is:

```java
assertNull(alert);
```

### Why?

`assertNull()` directly expresses the intention of the test:

```java
assertNull(alert);
```

means:

> Verify that `alert` is `null`.

This is clearer than:

```java
assertEquals(null, alert);
```

which treats `null` as the expected value in a general equality assertion.

# Key Takeaways

- Stubs can provide controlled dependency data for different test scenarios.
- The `stubWeatherData()` helper reduces repeated Mockito configuration.
- Normal weather should result in `null` because no alert condition is triggered.
- `assertNull()` is the preferred JUnit assertion when explicitly checking for `null`.
- The test continues to follow the **Arrange-Act-Assert** pattern.
- Testing the normal/default case is important because it verifies what happens when none of the alert conditions applies.
