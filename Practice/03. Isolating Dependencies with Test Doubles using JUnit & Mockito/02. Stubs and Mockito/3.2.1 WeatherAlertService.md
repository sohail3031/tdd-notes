# Task

In this exercise, a stubbed `WeatherService` is used to test the `WeatherAlertService`.

The goal is to simulate specific weather conditions without relying on real weather data and verify that the alert mechanism responds correctly.

The exercise involves:

1. Configuring a stubbed weather service.
2. Writing a test for extreme heat conditions.
3. Implementing the minimum logic required to make the test pass.

---

## Scenario

The `WeatherAlertService` depends on an `IWeatherService` to retrieve weather information.

```text
WeatherAlertService
        |
        v
IWeatherService
        |
        v
WeatherServiceStub
````

Instead of using an actual weather service, the test uses a `WeatherServiceStub`.

The stub allows the test to control the weather data returned by `IWeatherService`.

The test scenario is:

- **Location:** `London`
- **Temperature:** `36°C`
- **Conditions:** `sunny`
- **Expected alert:** `"Extreme heat warning. Stay hydrated!"`

## Supporting Interface: IWeatherService

The `IWeatherService` interface defines the dependency used by `WeatherAlertService`.

```java
public interface IWeatherService {

    WeatherData getCurrentWeather(String location);
}
```

The `WeatherAlertService` uses this interface to retrieve the current weather for a specified location.

## WeatherData

The `WeatherData` class represents the weather information returned by the weather service.

```java
public class WeatherData {

    private final int temperature;
    private final String conditions;

    public WeatherData(int temperature, String conditions) {
        this.temperature = temperature;
        this.conditions = conditions;
    }

    public int getTemperature() {
        return temperature;
    }

    public String getConditions() {
        return conditions;
    }
}
```

The class contains:

- `temperature` — the current temperature.
- `conditions` — the current weather conditions.

# Red: Write the Test

The first step is to write a test describing the expected behavior.

The test uses a hand-crafted `WeatherServiceStub`.

```java
class WeatherServiceStub implements IWeatherService {

    private WeatherData currentWeather =
        new WeatherData(20, "sunny");

    public void setWeather(
        int temperature,
        String conditions
    ) {
        this.currentWeather =
            new WeatherData(temperature, conditions);
    }

    @Override
    public WeatherData getCurrentWeather(String location) {
        return currentWeather;
    }
}
```

## How the Stub Works

The stub initially contains default weather data:

```java
private WeatherData currentWeather =
    new WeatherData(20, "sunny");
```

The `setWeather()` method allows the test to configure a specific weather scenario:

```java
weatherService.setWeather(36, "sunny");
```

When `WeatherAlertService` requests the weather data:

```java
weatherService.getCurrentWeather("London");
```

the stub returns the predefined `WeatherData` object.

> [!NOTE]  
> The stub does not retrieve real weather information. It returns controlled data configured specifically by the test.

## Complete Test

The test verifies that a temperature above `35°C` produces an extreme heat warning.

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.*;

public class WeatherAlertServiceTest {

    private WeatherServiceStub weatherService;
    private WeatherAlertService alertService;

    class WeatherServiceStub implements IWeatherService {

        private WeatherData currentWeather =
            new WeatherData(20, "sunny");

        public void setWeather(
            int temperature,
            String conditions
        ) {
            this.currentWeather =
                new WeatherData(temperature, conditions);
        }

        @Override
        public WeatherData getCurrentWeather(String location) {
            return currentWeather;
        }
    }

    @BeforeEach
    public void setUp() {
        weatherService = new WeatherServiceStub();
        alertService = new WeatherAlertService(weatherService);
    }

    @Test
    public void testShouldReturnHeatWarningWhenTemperatureIsAbove35() {
        // Arrange
        weatherService.setWeather(36, "sunny");

        // Act
        String alert = alertService.shouldSendAlert("London");

        // Assert
        assertEquals(
            "Extreme heat warning. Stay hydrated!",
            alert
        );
    }
}
```

# Test Breakdown

The test follows the **Arrange-Act-Assert (AAA)** pattern.

## Arrange

Configure the stub to simulate an extreme heat scenario.

```java
weatherService.setWeather(36, "sunny");
```

The stub will now return:

```java
new WeatherData(36, "sunny");
```

## Act

Call the method being tested.

```java
String alert =
    alertService.shouldSendAlert("London");
```

`WeatherAlertService` requests the weather data from the stub.

## Assert

Verify that the returned alert matches the expected message.

```java
assertEquals(
    "Extreme heat warning. Stay hydrated!",
    alert
);
```

# Green: Implement the Minimum Logic

The goal of the Green phase is to write the minimum amount of production code necessary to make the test pass.

```java
public class WeatherAlertService {

    private final IWeatherService weatherService;

    public WeatherAlertService(
        IWeatherService weatherService
    ) {
        this.weatherService = weatherService;
    }

    public String shouldSendAlert(String location) {
        WeatherData weatherData =
            weatherService.getCurrentWeather(location);

        if (weatherData.getTemperature() > 35) {
            return "Extreme heat warning. Stay hydrated!";
        }

        return null;
    }
}
```

---

## Implementation Flow

The `shouldSendAlert()` method performs the following steps:

### 1. Retrieve Weather Data

```java
WeatherData weatherData =
    weatherService.getCurrentWeather(location);
```

The service requests weather data through the `IWeatherService` dependency.

During the test, this call is handled by `WeatherServiceStub`.

### 2. Check the Temperature

```java
if (weatherData.getTemperature() > 35) {
```

The method checks whether the temperature is greater than `35°C`.

### 3. Return the Alert

If the condition is true:

```java
return "Extreme heat warning. Stay hydrated!";
```

The expected extreme heat warning is returned.

### 4. Return No Alert

If the temperature is not above `35°C`:

```java
return null;
```

No alert is currently returned for other weather conditions.

> [!NOTE]  
> Returning `null` is sufficient for the current implementation because the test only defines behavior for temperatures above `35°C`. Additional tests can introduce additional requirements later.

# Key Concepts

## Stub

`WeatherServiceStub` is a **stub** because it provides predefined weather data to the `WeatherAlertService`.

```java
@Override
public WeatherData getCurrentWeather(String location) {
    return currentWeather;
}
```

The returned value is controlled by the test through:

```java
weatherService.setWeather(36, "sunny");
```

## Dependency Injection

The `WeatherAlertService` receives its dependency through its constructor.

```java
public WeatherAlertService(
    IWeatherService weatherService
)
```

This allows the real weather service to be replaced with a stub during testing.

## Test Isolation

The test does not depend on:

- A real weather API.
- Network access.
- Current weather conditions.
- An external service.

This makes the test predictable and repeatable.

# Key Takeaways

- A **stub** provides controlled, predefined responses during testing.
- `WeatherServiceStub` replaces a real weather service.
- The `setWeather()` method allows the test to simulate different weather conditions.
- Dependency injection allows `IWeatherService` to be replaced with a test double.
- The test follows the **Arrange-Act-Assert** pattern.
- The implementation follows the **Red-Green-Refactor** approach.
- The production code implements only the minimum behavior required to make the current test pass.
