# Task

In this task, we use **Mockito spies** to test the functionality of the `NotificationService` class.

The `NotificationService` determines the priority of a notification based on the message content and length.

### Priority Rules

| Condition | Priority |
|---|---|
| Message contains `"URGENT"` (case-insensitive) | `HIGH` |
| Message does not contain `"URGENT"` and has 20 or more characters | `MEDIUM` |
| Message does not contain `"URGENT"` and has fewer than 20 characters | `LOW` |

The goal is to complete both the test case and the `NotificationService` implementation so that medium-priority messages are handled correctly.

```java
public class Notification {

    private String userId;
    private String message;
    private Priority priority;

    public Notification(String userId, String message, Priority priority) {
        this.userId = userId;
        this.message = message;
        this.priority = priority;
    }

    public String getUserId() {
        return userId;
    }

    public void setUserId(String userId) {
        this.userId = userId;
    }

    public String getMessage() {
        return message;
    }

    public void setMessage(String message) {
        this.message = message;
    }

    public Priority getPriority() {
        return priority;
    }

    public void setPriority(Priority priority) {
        this.priority = priority;
    }

    @Override
    public String toString() {
        return String.format(
            "[UserId: %s, Message: %s, Priority: %s]",
            userId,
            message,
            priority
        );
    }
}
```

# Step 2: Update `NotificationService`

The priority logic needs to account for all three priority levels.

```java
public void notifyUser(String userId, String message) {
    Priority priority;

    if (message.toLowerCase().contains("urgent")) {
        priority = Priority.HIGH;
    } else if (message.length() >= 20) {
        priority = Priority.MEDIUM;
    } else {
        priority = Priority.LOW;
    }

    sender.send(new Notification(userId, message, priority));
}
```

The conditions are evaluated from highest priority to lowest priority.

### Priority Decision Flow

```text
                  ┌─────────────────────────┐
                  │      notifyUser()       │
                  └────────────┬────────────┘
                               │
                               ▼
                  ┌─────────────────────────┐
                  │ Contains "urgent"?      │
                  │    (case-insensitive)   │
                  └────────────┬────────────┘
                         Yes /   \ No
                            /     \
                           ▼       ▼
                        HIGH    ┌─────────────────────┐
                                │ message.length()    │
                                │       >= 20?        │
                                └──────────┬──────────┘
                                     Yes /   \ No
                                        /     \
                                       ▼       ▼
                                    MEDIUM    LOW
```

---

# Why the Order of Conditions Matters

The `URGENT` check must come **before** the message-length check.

For example:

```text
"This is an URGENT message!"
```

This message:

- Contains `"URGENT"`.
- Has more than 20 characters.

According to the requirements, it must be classified as:

```java
Priority.HIGH
```

Therefore, the implementation checks for `URGENT` first:

```java
if (message.toLowerCase().contains("urgent")) {
    priority = Priority.HIGH;
}
```

Only when the message is **not urgent** do we check its length:

```java
else if (message.length() >= 20) {
    priority = Priority.MEDIUM;
}
```

# Mockito Spy

## What Is a Spy?

A Mockito **spy** wraps a real object and allows us to monitor its interactions while keeping the object's real behavior.

In this example:

```java
@Spy
private RealNotificationSender senderSpy = new RealNotificationSender();
```

`senderSpy` is a spy around the real `RealNotificationSender` object.

Unlike a mock, the real implementation of `send()` is still executed.

```java
public void send(Notification notification) {
    System.out.println("Sending notification: " + notification);
}
```

At the same time, Mockito can verify that the method was called with the expected arguments.

---

# `@InjectMocks`

The following annotation:

```java
@InjectMocks
private NotificationService notificationService;
```

tells Mockito to create a `NotificationService` instance and inject the available mock/spy dependencies into it.

The equivalent constructor call is conceptually:

```java
notificationService = new NotificationService(senderSpy);
```

Therefore, when `notifyUser()` calls:

```java
sender.send(...)
```

it is actually interacting with the `senderSpy`.

---

# Mockito `verify()`

The following statement verifies that `send()` was called exactly once:

```java
verify(senderSpy, times(1)).send(any(Notification.class));
```

### `times(1)`

```java
times(1)
```

means the method must have been called exactly once.

### `any(Notification.class)`

```java
any(Notification.class)
```

matches any `Notification` object.

---

# Mockito `argThat()`

`argThat()` allows us to verify the specific properties of the object passed to the method.

```java
verify(senderSpy, times(1)).send(argThat(notification ->
    notification.getUserId().equals("user3") &&
    notification.getMessage().equals("...") &&
    notification.getPriority() == Priority.MEDIUM
));
```

This verifies three properties:

1. The correct user ID was used.
2. The correct message was used.
3. The correct priority was assigned.

# Key Takeaways

- A **Mockito spy** wraps a real object while allowing Mockito to verify its interactions.
- `@Spy` is used to create the `senderSpy`.
- `@InjectMocks` injects the spy into `NotificationService`.
- `verify()` checks whether a method was called.
- `times(1)` verifies that a method was called exactly once.
- `argThat()` allows verification of specific properties of a method argument.
- Notification priority is determined in this order:
    1. `URGENT` → `HIGH`
    2. Length `>= 20` → `MEDIUM`
    3. Otherwise → `LOW`
- Checking `URGENT` first is important because an urgent message can also be longer than 20 characters.
