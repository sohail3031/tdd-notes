# Task

Enhance the `NotificationService` to correctly handle urgent notifications.

A notification should be categorized as **high priority** when its message contains the word `URGENT`, regardless of its case. Otherwise, the notification should be categorized as **low priority**.

The priority determines how the system sends the notification, so it is important to correctly identify urgent messages.

## Requirements

1. **Write test cases**
   - Verify that messages containing `URGENT` are sent with `Priority.HIGH`.
   - Verify that messages that do not contain `URGENT` are sent with `Priority.LOW`.
   - The check for `URGENT` must be **case-insensitive**.

2. **Update `notifyUser`**
   - Modify the `notifyUser` method in `NotificationService`.
   - Check whether the message contains the word `URGENT`.
   - If it does, send the notification with `Priority.HIGH`.
   - Otherwise, send it with `Priority.LOW`.

3. **Use Mockito**
   - Use Mockito to verify that the `send` method is called with the correct `Notification` object.
   - Verify the user ID, message, and priority.

# Step 3: Update `NotificationService`

The `notifyUser` method is updated to check whether the message contains `"urgent"` without considering letter case.

```java
public class NotificationService {

    private final INotificationSender sender;

    public NotificationService(INotificationSender sender) {
        this.sender = sender;
    }

    public void notifyUser(String userId, String message) {
        if (message.toLowerCase().contains("urgent")) {
            sender.send(new Notification(userId, message, Priority.HIGH));
        } else {
            sender.send(new Notification(userId, message, Priority.LOW));
        }
    }
}
```

### How It Works

The following condition performs the case-insensitive check:

```java
message.toLowerCase().contains("urgent")
```

For example:

|Message|Result|Priority|
|---|---|---|
|`"Hi!"`|Does not contain `urgent`|`LOW`|
|`"Urgent!"`|Contains `urgent`|`HIGH`|
|`"URGENT: Server is down"`|Contains `urgent`|`HIGH`|
|`"This is URGENT"`|Contains `urgent`|`HIGH`|
|`"Please help"`|Does not contain `urgent`|`LOW`|

The original message is passed to the `Notification` object unchanged. Only the comparison is converted to lowercase.

# Key TDD Concepts

## 1. Test First

The expected behavior is defined through tests before modifying the production code.

## 2. Arrange-Act-Assert

The test follows the **AAA pattern**:

```text
Arrange → Act → Assert
```

In this example:

- **Arrange:** Mockito creates and injects the `senderSpy`.
- **Act:** Call `notificationService.notifyUser(...)`.
- **Assert:** Use Mockito's `verify()` to check the notification sent.

## 3. Mockito `verify()`

Mockito's `verify()` method checks whether a mocked or spied dependency was called.

```java
verify(senderSpy, times(1)).send(any(Notification.class));
```

This verifies that `send()` was called exactly once.

## 4. Mockito `argThat()`

`argThat()` allows us to verify specific properties of the argument passed to a method.

```java
verify(senderSpy).send(argThat(notification ->
    notification.getPriority() == Priority.HIGH
));
```

This is useful when we care about the contents of an object rather than simply verifying that the method was called.

## 5. Case-Insensitive Matching

The requirement states that `"URGENT"` should be recognized regardless of case.

```java
message.toLowerCase().contains("urgent")
```

Therefore, all of the following should result in `Priority.HIGH`:

```text
URGENT
Urgent
urgent
UrGeNt
```
