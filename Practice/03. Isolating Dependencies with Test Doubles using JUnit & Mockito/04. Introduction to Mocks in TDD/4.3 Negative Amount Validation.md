# Task

In this task, we need to verify that the `convertPrice()` method in `PricingService` throws an exception when a negative amount is provided.

The requirements are:

1. `convertPrice()` should throw an `IllegalArgumentException` when `amount` is less than `0`. 
2. The exception message should be:

```text
Amount cannot be negative
```

3. The `IExchangeRateService` dependency should not be called when the amount is invalid.

This exercise introduces exception testing with JUnit's `assertThrows()` and reinforces the importance of validating input before interacting with external dependencies.

---

# Learning Objectives

By completing this task, you learn how to:

- Test exceptions using `assertThrows()`.    
- Verify exception messages.
- Validate method input.
- Throw an `IllegalArgumentException`.
- Prevent unnecessary dependency calls when input validation fails.
- Apply the **Red-Green-Refactor** TDD workflow.

# Expected Behavior

## Valid Amount

For a valid amount:

```java
pricingService.convertPrice(100, "USD", "EUR");
```

The service should:

1. Call `getRate("USD", "EUR")`.
2. Retrieve the exchange rate.
3. Perform the conversion.
4. Return the converted amount.

---

## Same Currency

For identical currencies:

```java
pricingService.convertPrice(100, "USD", "USD");
```

The service should:

1. Return the original amount.
2. Avoid calling the exchange rate service.

---

## Negative Amount

For a negative amount:

```java
pricingService.convertPrice(-100, "USD", "EUR");
```

The service should:

1. Immediately validate the amount.
2. Throw an `IllegalArgumentException`.
3. Use the message `"Amount cannot be negative"`.
4. Avoid calling `getRate()`.

The validation flow should look like this:

```text
convertPrice()
     │
     ▼
Is amount negative?
     │
 ┌───┴───┐
 │       │
Yes      No
 │       │
 ▼       ▼
Throw    Continue
Exception
 │
 ▼
Do NOT call
getRate()
```

# JUnit `assertThrows()`

JUnit provides `assertThrows()` to verify that a specific exception is thrown.

The general syntax is:

```java
ExceptionType exception = assertThrows(
    ExceptionType.class,
    () -> {
        // Code expected to throw the exception
    }
);
```

For this task:

```java
IllegalArgumentException exception = assertThrows(
    IllegalArgumentException.class,
    () -> pricingService.convertPrice(-100, "USD", "EUR")
);
```

The method returns the thrown exception, allowing us to inspect it.

For example:

```java
exception.getMessage();
```

returns the exception message.

## `PricingServiceTest.java`

```java
import org.junit.jupiter.api.Test;

import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import org.junit.jupiter.api.extension.ExtendWith;

import static org.mockito.Mockito.*;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

@ExtendWith(MockitoExtension.class)
public class PricingServiceTest {

    @Mock
    private IExchangeRateService mockExchangeRateService;

    @InjectMocks
    private PricingService pricingService;

    @Test
    public void testConvertPriceUsesExchangeRate() throws Exception {

        // Arrange
        when(mockExchangeRateService.getRate("USD", "EUR"))
                .thenReturn(1.5);

        // Act
        double result =
                pricingService.convertPrice(100, "USD", "EUR");

        // Assert
        verify(mockExchangeRateService, times(1))
                .getRate("USD", "EUR");

        assertEquals(150.00, result);
    }

    @Test
    public void testConvertPriceWithSameCurrenciesDoesNotCallGetRate()
            throws Exception {

        // Arrange
        // No setup is needed because getRate() should not be called.

        // Act
        double result =
                pricingService.convertPrice(100, "USD", "USD");

        // Assert
        verify(mockExchangeRateService, never())
                .getRate(anyString(), anyString());

        assertEquals(100.00, result);
    }

    @Test
    public void testConvertPriceThrowsExceptionForNegativeAmount()
            throws Exception {

        // Act
        IllegalArgumentException exception = assertThrows(
                IllegalArgumentException.class,
                () -> pricingService.convertPrice(
                        -100,
                        "USD",
                        "EUR"
                )
        );

        // Assert
        assertEquals(
                "Amount cannot be negative",
                exception.getMessage()
        );

        verify(mockExchangeRateService, never())
                .getRate(anyString(), anyString());
    }
}
```

if (amount < 0) {

# Final `PricingService.java`

```java
public class PricingService {

    private final IExchangeRateService exchangeRateService;

    public PricingService(
            IExchangeRateService exchangeRateService
    ) {
        this.exchangeRateService = exchangeRateService;
    }

    public double convertPrice(
            double amount,
            String fromCurrency,
            String toCurrency
    ) throws Exception {

        // Validate the input first.
        if (amount < 0) {
            throw new IllegalArgumentException(
                    "Amount cannot be negative"
            );
        }

        // No conversion is required for identical currencies.
        if (fromCurrency.equalsIgnoreCase(toCurrency)) {
            return Math.round(amount * 100.0) / 100.0;
        }

        // Retrieve the exchange rate for different currencies.
        double rate = exchangeRateService.getRate(
                fromCurrency,
                toCurrency
        );

        // Convert and round the result to two decimal places.
        return Math.round(amount * rate * 100.0) / 100.0;
    }
}
```

---

# Why Input Validation Must Come First

Consider this incorrect implementation:

```java
double rate = exchangeRateService.getRate(
        fromCurrency,
        toCurrency
);

if (amount < 0) {
    throw new IllegalArgumentException(
            "Amount cannot be negative"
    );
}
```

This implementation throws the correct exception, but it has a problem.

The external service is called before validating the input.

For example:

```text
convertPrice(-100, "USD", "EUR")
        │
        ▼
Call getRate() ❌
        │
        ▼
Validate amount
        │
        ▼
Throw exception
```

The call to `getRate()` was unnecessary.

---

## Correct Implementation

```text
convertPrice(-100, "USD", "EUR")
        │
        ▼
Is amount negative?
        │
       Yes
        │
        ▼
Throw IllegalArgumentException
        │
        ▼
Do NOT call getRate() ✅
```

This is more efficient and prevents unnecessary interaction with external dependencies.

# Understanding `IllegalArgumentException`

`IllegalArgumentException` is commonly used when a method receives an invalid argument.

For example:

```java
if (amount < 0) {
    throw new IllegalArgumentException(
            "Amount cannot be negative"
    );
}
```

The caller has provided an argument that violates the method's requirements.

In this case:

```text
Valid amount   → 0 or greater

Invalid amount → Less than 0
```

Examples:

```text
100     → Valid
0       → Valid
50.75   → Valid
-1      → Invalid
-100    → Invalid
```

# Understanding `assertThrows()`

The following code:

```java
IllegalArgumentException exception = assertThrows(
        IllegalArgumentException.class,
        () -> pricingService.convertPrice(
                -100,
                "USD",
                "EUR"
        )
);
```

verifies two things:

1. The code throws an exception.
2. The exception is an `IllegalArgumentException`.

The returned exception object can then be used to verify additional details.

For example:

```java
assertEquals(
        "Amount cannot be negative",
        exception.getMessage()
);
```

This ensures that the exception has the expected message.

# Testing Exception Messages

Testing only the exception type:

```java
assertThrows(
        IllegalArgumentException.class,
        () -> pricingService.convertPrice(
                -100,
                "USD",
                "EUR"
        )
);
```

confirms that an exception is thrown.

However, testing the message as well:

```java
assertEquals(
        "Amount cannot be negative",
        exception.getMessage()
);
```

confirms that the implementation provides the expected error information.

This can be useful when exception messages are part of the required behavior.

# Interaction Verification with Invalid Input

The following verification:

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

ensures that:

```text
Number of getRate() calls = 0
```

This is an example of verifying **negative interactions**.

A unit test can verify:

```text
What should happen
```

and also:

```text
What should not happen
```

For this scenario:

|Expected Behavior|Verification|
|---|---|
|An exception is thrown|`assertThrows()`|
|Correct exception type|`IllegalArgumentException.class`|
|Correct exception message|`assertEquals()`|
|Exchange rate service is not called|`verify(..., never())`|

```java
if (amount < 0) {
    throw new IllegalArgumentException(
            "Amount cannot be negative"
    );
}
```

```java
assertThrows()
```

---

## Exception Message Verification

Capture the exception:

```java
IllegalArgumentException exception = assertThrows(...);
```

Then verify:

```java
exception.getMessage();
```

---

## Negative Interaction Verification

Use:

```java

```

# Key Takeaways

- Use `assertThrows()` to test expected exceptions.
- Capture the returned exception to verify its message.
- Use `IllegalArgumentException` for invalid method arguments.
- Validate input before performing business logic or external calls.
- Negative amounts should be rejected immediately.
- Use `verify(..., never())` to ensure unnecessary dependency calls do not occur.
- A good unit test can verify both the output/exception and interactions with dependencies.
- Input validation should generally happen before calling external services.
- Mockito can verify both positive and negative interactions.
- This exercise follows the **Red-Green-Refactor** TDD workflow.
