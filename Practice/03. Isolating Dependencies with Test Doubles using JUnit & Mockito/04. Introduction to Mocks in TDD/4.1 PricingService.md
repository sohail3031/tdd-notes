# Task

In this task, we learn how to use **Mockito mocks** to isolate dependencies in unit tests.

Specifically, we mock the `IExchangeRateService` to test the `PricingService` without relying on real external API calls.

The task involves:

1. Configuring `mockExchangeRateService.getRate()` to return a mocked exchange rate using Mockito.    
2. Calling `pricingService.convertPrice()` with specific parameters.
3. Verifying that `getRate()` was called with the correct parameters.
4. Verifying that the converted price matches the expected result.

---

# Learning Objective

The goal of this exercise is to understand how mocks help isolate a class from its dependencies.

The dependency structure is:

```text
PricingService
      │
      ▼
IExchangeRateService
      │
      ▼
External Exchange Rate API
```

During the unit test, we replace the real `IExchangeRateService` with a mock:

```text
PricingService
      │
      ▼
Mock IExchangeRateService
      │
      ▼
Controlled Return Value
```

This allows the test to run without:

- Calling a real API.
- Making a network request.
- Depending on real-time exchange rates.
- Being affected by external service failures.

# Final Implementation

## `PricingServiceTest.java`

```java
import org.junit.jupiter.api.Test;

import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import org.junit.jupiter.api.extension.ExtendWith;

import static org.mockito.Mockito.*;
import static org.junit.jupiter.api.Assertions.assertEquals;

@ExtendWith(MockitoExtension.class)
public class PricingServiceTest {

    @Mock
    private IExchangeRateService mockExchangeRateService;

    @InjectMocks
    private PricingService pricingService;

    @Test
    public void testConvertPriceUsesExchangeRate() throws Exception {

        // Arrange
        when(mockExchangeRateService.getRate("USD", "EUR"))
                .thenReturn(1.5);

        // Act
        double convertedPrice =
                pricingService.convertPrice(100, "USD", "EUR");

        // Assert
        verify(mockExchangeRateService, times(1))
                .getRate("USD", "EUR");

        assertEquals(150.00, convertedPrice);
    }
}
```

---

# Understanding the Test

## Arrange

```java
when(mockExchangeRateService.getRate("USD", "EUR"))
        .thenReturn(1.5);
```

This configures the mock behavior.

It means:

> When `getRate("USD", "EUR")` is called, return `1.5`.

The real exchange rate service is not called.

```text
getRate("USD", "EUR")
          │
          ▼
Mock Exchange Rate Service
          │
          ▼
Returns 1.5
```

This is called **stubbing** the mock.

---

## Act

```java
double convertedPrice =
        pricingService.convertPrice(100, "USD", "EUR");
```

This calls the actual method we want to test.

The `PricingService` internally calls:

```java
exchangeRateService.getRate("USD", "EUR");
```

Since `exchangeRateService` is a mock, Mockito returns the configured value:

```text
1.5
```

The conversion becomes:

```text
100 × 1.5 = 150.00
```

---

## Assert

The test performs two different assertions.

### 1. Verify the Dependency Interaction

```java
verify(mockExchangeRateService, times(1))
        .getRate("USD", "EUR");
```

This verifies that:

- `getRate()` was called.
- It was called exactly once.
- `"USD"` was passed as the source currency.
- `"EUR"` was passed as the target currency.

This is an **interaction-based verification**.

---

### 2. Verify the Result

```java
assertEquals(150.00, convertedPrice);
```

This verifies that the result returned by `convertPrice()` is correct.

This is a **state/output-based verification**.

# Final `PricingService.java`

```java
public class PricingService {

    private final IExchangeRateService exchangeRateService;

    public PricingService(IExchangeRateService exchangeRateService) {
        this.exchangeRateService = exchangeRateService;
    }

    public double convertPrice(
            double amount,
            String fromCurrency,
            String toCurrency
    ) throws Exception {

        double rate =
                exchangeRateService.getRate(
                        fromCurrency,
                        toCurrency
                );

        return Math.round(amount * rate * 100.0) / 100.0;
    }
}
```

---

# Understanding the Conversion Logic

The exchange rate is retrieved from the dependency:

```java
double rate =
        exchangeRateService.getRate(
                fromCurrency,
                toCurrency
        );
```

The amount is then multiplied by the exchange rate:

```text
convertedPrice = amount × rate
```

For example:

```text
Amount = 100
Rate = 1.5

100 × 1.5 = 150
```

---

# Rounding to Two Decimal Places

The following code rounds the result to two decimal places:

```java
Math.round(amount * rate * 100.0) / 100.0;
```

For example:

```text
Amount × Rate = 123.4567

123.4567 × 100 = 12345.67

Math.round(...) = 12346

12346 / 100.0 = 123.46
```

This is useful for currency values.

# Important Mockito Concepts Used

## `@Mock`

```java
@Mock
private IExchangeRateService mockExchangeRateService;
```

Creates a mock implementation of `IExchangeRateService`.

The real implementation is not executed.

---

## `@InjectMocks`

```java
@InjectMocks
private PricingService pricingService;
```

Creates the `PricingService` and injects the available mock dependency into it.

Conceptually:

```java
PricingService pricingService =
        new PricingService(mockExchangeRateService);
```

---

## `when(...).thenReturn(...)`

```java
when(mockExchangeRateService.getRate("USD", "EUR"))
        .thenReturn(1.5);
```

Defines the behavior of the mock.

```text
When this method is called:
getRate("USD", "EUR")

Return:
1.5
```

---

## `verify()`

```java
verify(mockExchangeRateService, times(1))
        .getRate("USD", "EUR");
```

Verifies that the mock was interacted with correctly.

# Test Execution Flow

```text
┌─────────────────────────────┐
│          Arrange            │
│ Mock getRate() → 1.5        │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│             Act             │
│ convertPrice(100, USD, EUR) │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│      PricingService         │
│ calls getRate(USD, EUR)     │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ Mock returns 1.5            │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 100 × 1.5 = 150.00          │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│           Assert            │
│ Verify API interaction      │
│ Verify result = 150.00      │
└─────────────────────────────┘
```

# Key Takeaways

- A **mock** replaces a real dependency during testing.
- `@Mock` creates a mock object.
- `@InjectMocks` injects mocks into the class under test.
- `when(...).thenReturn(...)` defines the behavior of a mock.
- `verify(...)` verifies interactions with the mock.
- The real `IExchangeRateService` implementation is not executed.
- Mocking external services makes tests faster and more reliable.
- A unit test can verify both:
    - The **result** of a method.
    - The **interaction** with its dependencies.
- This example follows the **Arrange-Act-Assert (AAA)** pattern.
- Mocks are particularly useful for isolating dependencies such as APIs, databases, and external services.
