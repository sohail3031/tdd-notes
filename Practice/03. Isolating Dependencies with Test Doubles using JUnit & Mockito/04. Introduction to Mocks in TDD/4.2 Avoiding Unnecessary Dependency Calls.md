# Task

In this task, we verify that the `getRate()` method of `IExchangeRateService` is **not called** when converting an amount between identical currencies.

For example, converting:

```text
100 USD → USD
```

does not require an exchange rate lookup because the source and target currencies are the same.

The `PricingService` should:

1. Return the original amount.    
2. Avoid calling the external `IExchangeRateService`.
3. Be verified using Mockito's `never()` method.

---

# Learning Objective

The purpose of this exercise is to learn how Mockito can verify that a dependency was **not interacted with**.

This is important because unit tests should verify not only what a system does, but sometimes also what it **should not do**.

In this example, calling an external exchange rate service when both currencies are identical would be unnecessary.

---

# Expected Behavior

## Different Currencies

When converting between different currencies:

```text
100 USD → EUR
```

The `PricingService` should call:

```java
exchangeRateService.getRate("USD", "EUR");
```

Then use the returned exchange rate to perform the conversion.

---

## Identical Currencies

When converting between identical currencies:

```text
100 USD → USD
```

No conversion is required.

Therefore:

```text
Result = 100
```

The exchange rate service should not be called.

```text
PricingService
      │
      ├── Are currencies the same?
      │
      └── Yes
            │
            ▼
      Return original amount
            │
            ▼
      Do NOT call getRate()
```

# Final Test Implementation

## `PricingServiceTest.java`

```java
import org.junit.jupiter.api.Test;

import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import org.junit.jupiter.api.extension.ExtendWith;

import static org.mockito.Mockito.*;
import static org.junit.jupiter.api.Assertions.assertEquals;

@ExtendWith(MockitoExtension.class)
public class PricingServiceTest {

    @Mock
    private IExchangeRateService mockExchangeRateService;

    @InjectMocks
    private PricingService pricingService;

    @Test
    public void testConvertPriceUsesExchangeRate() throws Exception {

        // Arrange
        when(mockExchangeRateService.getRate("USD", "EUR"))
                .thenReturn(1.5);

        // Act
        double result =
                pricingService.convertPrice(100, "USD", "EUR");

        // Assert
        verify(mockExchangeRateService, times(1))
                .getRate("USD", "EUR");

        assertEquals(150.00, result);
    }

    @Test
    public void testConvertPriceWithSameCurrenciesDoesNotCallGetRate()
            throws Exception {

        // Arrange
        // No setup is needed because getRate() should not be called.

        // Act
        double result =
                pricingService.convertPrice(100, "USD", "USD");

        // Assert
        verify(mockExchangeRateService, never())
                .getRate(anyString(), anyString());

        assertEquals(100.00, result);
    }
}
```

# Understanding `never()`

Mockito's `never()` verifies that a method was never called.

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

This means:

> Verify that `getRate()` was called zero times, regardless of the `String` arguments passed to it.

Conceptually:

```text
Expected number of calls to getRate():

0
```

---

# `never()` and `times(0)`

The following two expressions are equivalent:

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

and:

```java
verify(mockExchangeRateService, times(0))
        .getRate(anyString(), anyString());
```

However, `never()` is generally more readable because it clearly communicates the intention of the test.

```text
never()   → The method should not be called.

times(0)  → The method should be called zero times.
```

Both verify the same behavior.

---

# Why Use `anyString()`?

The verification uses:

```java
anyString()
```

for both arguments:

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

This means that the test verifies that `getRate()` was never called with **any combination of string arguments**.

For example, all of the following would cause the verification to fail:

```java
getRate("USD", "USD");
```

```java
getRate("USD", "EUR");
```

```java
getRate("EUR", "GBP");
```

The method must not be called at all.

# Final `PricingService.java`

```java
public class PricingService {

    private final IExchangeRateService exchangeRateService;

    public PricingService(IExchangeRateService exchangeRateService) {
        this.exchangeRateService = exchangeRateService;
    }

    public double convertPrice(
            double amount,
            String fromCurrency,
            String toCurrency
    ) throws Exception {

        if (fromCurrency.equals(toCurrency)) {
            return amount;
        }

        double rate =
                exchangeRateService.getRate(
                        fromCurrency,
                        toCurrency
                );

        return Math.round(amount * rate * 100.0) / 100.0;
    }
}
```

---

# Understanding the Implementation

The method first checks whether both currencies are identical.

```java
if (fromCurrency.equals(toCurrency)) {
    return amount;
}
```

For example:

```java
convertPrice(100, "USD", "USD");
```

The condition evaluates to:

```text
"USD".equals("USD") → true
```

Therefore, the method immediately returns:

```text
100
```

The following code is never reached:

```java
exchangeRateService.getRate(fromCurrency, toCurrency);
```

This prevents an unnecessary dependency call.

# Interaction Verification

This exercise demonstrates two types of interaction verification.

## Verifying That a Method Was Called

```java
verify(mockExchangeRateService, times(1))
        .getRate("USD", "EUR");
```

This verifies that the dependency was called exactly once.

---

## Verifying That a Method Was Not Called

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

This verifies that the dependency was not called at all.

Both types of verification are important when testing interactions between classes.

---

# Important Testing Principle

A good unit test can verify both:

1. **What the method returns.**
2. **How the method interacts with its dependencies.**

In this example:

## Output Verification

```java
assertEquals(100.00, result);
```

This verifies the returned value.

## Interaction Verification

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

This verifies that an unnecessary external dependency call was avoided.

Testing both gives stronger confidence that the implementation behaves correctly.

---

# Why Avoid Unnecessary External Calls?

Avoiding unnecessary calls to external services can improve:

- Performance
- Reliability
- Response time
- API rate-limit usage
- Cost
- System efficiency

For example, there is no reason to request an exchange rate for:

```text
USD → USD
```

because the conversion rate is effectively:

```text
1.0
```

The original amount can simply be returned.

# Key Mockito Concepts Used

## `@Mock`

```java
@Mock
private IExchangeRateService mockExchangeRateService;
```

Creates a mock dependency.

---

## `@InjectMocks`

```java
@InjectMocks
private PricingService pricingService;
```

Injects the mock dependency into the class being tested.

---

## `when(...).thenReturn(...)`

```java
when(mockExchangeRateService.getRate("USD", "EUR"))
        .thenReturn(1.5);
```

Defines the behavior of the mock.

---

## `verify(..., times(1))`

```java
verify(mockExchangeRateService, times(1))
        .getRate("USD", "EUR");
```

Verifies that a method was called exactly once.

---

## `verify(..., never())`

```java
verify(mockExchangeRateService, never())
        .getRate(anyString(), anyString());
```

Verifies that a method was never called.

# Key Takeaways

- Mockito can verify that a dependency was **not called**.
- `never()` verifies that a method was called zero times.
- `never()` is equivalent to `times(0)`.
- `anyString()` allows verification against any `String` arguments.
- When converting between identical currencies, no exchange rate lookup is necessary.
- The `PricingService` should return the original amount immediately.
- Unit tests should verify both output and dependency interactions when relevant.
- Avoiding unnecessary external calls improves application performance and efficiency.
- This exercise demonstrates how mocks can verify optimization-related behavior.
- The implementation follows the **Red-Green-Refactor** TDD cycle.
