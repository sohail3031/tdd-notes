# Task

Refactor the `UserRegistrationService` class by extracting the **user validation logic** into a dedicated method.

The validation logic currently lives inside `processUserRegistration()`. It validates:

- Username    
- Email
- Password

The goal is to separate these validation responsibilities from the registration process while keeping the application's behavior unchanged.

> [!IMPORTANT]  
> This is a **refactoring task**, so the existing tests should continue to pass. We are changing the structure of the code, not its behavior.

---

# Problem: Too Many Responsibilities

Before refactoring, `processUserRegistration()` handles several different responsibilities:

1. Username validation    
2. Email validation
3. Password validation
4. Date-of-birth validation
5. Address validation
6. Data transformation
7. Data storage
8. Error handling

The user validation section is a logical unit that can be extracted into its own method.

---

# Refactoring: Extract Method

Create a dedicated method:

```java
private RegistrationResponse validateUser(UserData userData)
```

This method becomes responsible for:

- Username validation    
- Email validation
- Password validation

The extracted method returns:

- A `RegistrationResponse` when validation fails
- `null` when validation succeeds

# Refactored `processUserRegistration()`

```java
public RegistrationResponse processUserRegistration(UserData userData) {
    try {
        RegistrationResponse validationResponse = validateUser(userData);

        if (validationResponse != null) {
            return validationResponse;
        }

        // Date validation
        LocalDate birthDate;

        try {
            birthDate = LocalDate.parse(userData.getDateOfBirth());
        } catch (DateTimeParseException e) {
            return new RegistrationResponse(
                false,
                "Registration failed: The string '"
                    + userData.getDateOfBirth()
                    + "' is not a valid date.",
                null
            );
        }

        LocalDate today = LocalDate.now();
        Period age = Period.between(birthDate, today);

        if (age.getYears() < 18 || age.getYears() > 120) {
            return new RegistrationResponse(
                false,
                "Invalid date of birth or user must be 18+",
                null
            );
        }

        // Address validation
        Address address = userData.getAddress();

        if (address == null) {
            return new RegistrationResponse(
                false,
                "Address cannot be null.",
                null
            );
        }

        if (address.getStreet() == null
            || address.getStreet().isBlank()
            || address.getStreet().length() < 5) {

            return new RegistrationResponse(
                false,
                "Invalid street address",
                null
            );
        }

        if (address.getCity() == null
            || address.getCity().isBlank()
            || address.getCity().length() < 2) {

            return new RegistrationResponse(
                false,
                "Invalid city",
                null
            );
        }

        if (address.getCountry() == null
            || address.getCountry().isBlank()
            || address.getCountry().length() < 2) {

            return new RegistrationResponse(
                false,
                "Invalid country",
                null
            );
        }

        if (address.getPostalCode() == null
            || address.getPostalCode().isBlank()
            || !Pattern.compile("^[A-Z0-9]{3,10}$")
                .matcher(address.getPostalCode())
                .matches()) {

            return new RegistrationResponse(
                false,
                "Invalid postal code",
                null
            );
        }

        // Data transformation
        String userId = "USER_"
            + UUID.randomUUID().toString().substring(0, 8);

        UserData normalizedData = new UserData(
            userData.getUsername().toLowerCase(),
            userData.getEmail().toLowerCase(),
            userData.getPassword(),
            birthDate.toString(),
            new Address(
                address.getStreet().trim(),
                address.getCity().trim(),
                address.getCountry().toUpperCase(),
                address.getPostalCode().toUpperCase()
            )
        );

        dataStore.store(normalizedData);

        return new RegistrationResponse(
            true,
            "User registered successfully",
            userId
        );

    } catch (Exception e) {
        return new RegistrationResponse(
            false,
            "Registration failed: " + e.getMessage(),
            ""
        );
    }
}
```

# Why `validateUser()` Is a Good Extraction

The extracted method has a clear responsibility:

```text
validateUser()
    ├── Validate username
    ├── Validate email
    └── Validate password
```

While `processUserRegistration()` focuses more on the overall workflow:

```text
processUserRegistration()
    ↓
Validate user
    ↓
Validate date
    ↓
Validate address
    ↓
Transform data
    ↓
Store data
    ↓
Return response
```

This makes the code easier to understand.

        LocalDate birthDate = validateDateOfBirth(userData.getDateOfBirth());

# Refactoring vs. Behavior Change

This exercise is specifically about **refactoring**, not adding new validation rules.

### Refactoring

```text
Move existing validation logic
        ↓
Create validateUser()
        ↓
Call validateUser()
        ↓
Same tests
        ↓
Same behavior
```

### Behavior change

For example, adding a new rule:

```java
if (userData.getUsername().contains("admin")) {
    // reject username
}
```

would change the application's behavior.

That would be a **feature/behavior change**, not simply a refactoring.

> [!IMPORTANT]  
> A successful refactoring changes the **structure** of the code while preserving its **observable behavior**.

# Key Takeaways

- **Extract Method** is useful for breaking long methods into smaller, focused methods.    
- `processUserRegistration()` was responsible for too many things.
- User validation was a logical responsibility that could be extracted.
- `validateUser()` now handles username, email, and password validation.
- A `null` return value indicates that validation succeeded in this exercise.
- Existing tests provide a safety net during refactoring.
- Run the tests after each structural change.
- Refactoring should not change the application's behavior.
- The **Single Responsibility Principle** encourages methods to have focused responsibilities.
- Other parts of `processUserRegistration()` can be extracted in future refactoring steps.

> [!TIP]  
> When looking at a long method, ask: **"Can I give this block of code a meaningful name?"** If you can, it is often a strong candidate for the **Extract Method** refactoring technique.
