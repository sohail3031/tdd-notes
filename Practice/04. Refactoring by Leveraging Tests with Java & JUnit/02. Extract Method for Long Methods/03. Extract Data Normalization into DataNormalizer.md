# Task

Refactor the existing `UserRegistrationService` by extracting the **data normalization logic** into a dedicated `DataNormalizer` class.

The goal is to make `processUserRegistration()` shorter, easier to read, and focused on coordinating the registration workflow.

### Goals

1. Create a `DataNormalizer` class.    
2. Move the user-data normalization logic into that class.
3. Normalize:
    - Username → lowercase
    - Email → lowercase
    - Street → trimmed
    - City → trimmed
    - Country → uppercase
    - Postal code → uppercase
4. Preserve the password and date of birth.
5. Create a new normalized `UserData` object instead of modifying the original object.
6. Update `UserRegistrationService` to use `DataNormalizer`.
7. Keep existing test behavior unchanged.

---

## What Is Data Normalization?

**Data normalization** means converting input data into a consistent format before storing or processing it.

For example:

```text
Input:
    Username: JohnDOE
    Email: John.Doe@EXAMPLE.com
    Street: " 123 Main Street "
    Country: usa
    Postal Code: "m5v123"

        ↓ normalize

Output:
    Username: johndoe
    Email: john.doe@example.com
    Street: "123 Main Street"
    Country: USA
    Postal Code: M5V123
```

The purpose is to ensure that data follows a consistent format regardless of how the user entered it.

# 2. Create `DataNormalizer`

Create a new class called `DataNormalizer`.

```java
import models.Address;
import models.UserData;

public class DataNormalizer {

    public UserData normalizeUserData(UserData userData) {
        if (userData == null) {
            return null;
        }

        Address originalAddress = userData.getAddress();
        Address normalizedAddress = null;

        if (originalAddress != null) {
            normalizedAddress = new Address(
                originalAddress.getStreet().trim(),
                originalAddress.getCity().trim(),
                originalAddress.getCountry().toUpperCase(),
                originalAddress.getPostalCode().toUpperCase()
            );
        }

        return new UserData(
            userData.getUsername().toLowerCase(),
            userData.getEmail().toLowerCase(),
            userData.getPassword(),
            userData.getDateOfBirth(),
            normalizedAddress
        );
    }
}
```

# 3. Understanding `normalizeUserData()`

The main method is:

```java
public UserData normalizeUserData(UserData userData)
```

It:

1. Receives the original `UserData`.    
2. Creates a normalized `Address`.
3. Creates a new normalized `UserData`.
4. Returns the new object.

### Important

The method does **not** modify the original `UserData`.

Instead:

```text
Original UserData
       │
       │ normalize
       ▼
New UserData
```

This is preferable because the original input remains unchanged.

# 4. Null Handling

The first check is:

```java
if (userData == null) {
    return null;
}
```

This prevents a `NullPointerException` inside the normalizer.

However, in the registration workflow, validation occurs **before** normalization:

```java
userValidator.validateUserData(userData);
addressValidator.validateAddress(userData.getAddress());
UserData normalizedData = dataNormalizer.normalizeUserData(userData);
```

Therefore, valid registration data should reach the normalizer.

The null check makes `DataNormalizer` safer when used independently.

# 5. Normalizing the Address

First, retrieve the original address:

```java
Address originalAddress = userData.getAddress();
```

Then create a normalized address:

```java
Address normalizedAddress = null;

if (originalAddress != null) {
    normalizedAddress = new Address(
        originalAddress.getStreet().trim(),
        originalAddress.getCity().trim(),
        originalAddress.getCountry().toUpperCase(),
        originalAddress.getPostalCode().toUpperCase()
    );
}
```

Each field is normalized differently.

| Field       | Normalization   |
| ----------- | --------------- |
| Street      | `trim()`        |
| City        | `trim()`        |
| Country     | `toUpperCase()` |
| Postal code | `toUpperCase()` |

Example:

```text
"  123 Main Street  " → "123 Main Street"
"  New York  "        → "New York"
"usa"                 → "USA"
"m5v123"              → "M5V123"
```

```java

```

This is important because changing the case or trimming a password could change its meaning.

# 9. Final `UserRegistrationService`

```java
import java.util.UUID;

import datastore.*;
import models.*;

public class UserRegistrationService {

    private final IDataStore dataStore;
    private final UserValidator userValidator;
    private final AddressValidator addressValidator;
    private final DataNormalizer dataNormalizer;

    public UserRegistrationService(IDataStore dataStore) {
        this.dataStore = dataStore;
        this.userValidator = new UserValidator();
        this.addressValidator = new AddressValidator();
        this.dataNormalizer = new DataNormalizer();
    }

    public RegistrationResponse processUserRegistration(UserData userData) {
        try {
            // Validate user data
            userValidator.validateUserData(userData);

            // Validate address data
            addressValidator.validateAddress(userData.getAddress());

            // Normalize user data
            UserData normalizedData =
                    dataNormalizer.normalizeUserData(userData);

            // Generate unique user ID
            String userId =
                    "USER_" + UUID.randomUUID().toString().substring(0, 8);

            // Store normalized data
            dataStore.store(normalizedData);

            return new RegistrationResponse(
                true,
                "User registered successfully",
                userId
            );

        } catch (ValidationException e) {
            return new RegistrationResponse(
                false,
                e.getMessage(),
                null
            );

        } catch (Exception e) {
            return new RegistrationResponse(
                false,
                "Registration failed: " + e.getMessage(),
                ""
            );
        }
    }
}
```

# 13. TDD and Refactoring

This is another example of **Extract Class** refactoring.

The existing tests act as a safety net.

The expected process is:

```text
┌───────────────────────┐
│ Run existing tests    │
└───────────┬───────────┘
            ↓
┌───────────────────────┐
│ Extract normalization │
│ into DataNormalizer   │
└───────────┬───────────┘
            ↓
┌───────────────────────┐
│ Update service        │
└───────────┬───────────┘
            ↓
┌───────────────────────┐
│ Run tests again       │
└───────────┬───────────┘
            ↓
       All tests pass
```

The behavior should remain the same.

The test:

```java
@Test
public void testProcessUserRegistrationNormalizesDataSuccess() {
    UserData mixedCaseData = getValidUserData();

    mixedCaseData.setUsername("JohnDOE");
    mixedCaseData.setEmail("John.Doe@EXAMPLE.com");
    mixedCaseData.getAddress().setCountry("usa");

    RegistrationResponse result =
            service.processUserRegistration(mixedCaseData);

    assertTrue(result.isSuccess());

    UserData loggedData = dataStore.getStoredData().get(0);

    assertEquals("johndoe", loggedData.getUsername());
    assertEquals("john.doe@example.com", loggedData.getEmail());
    assertEquals("USA", loggedData.getAddress().getCountry());
    assertEquals("10001", loggedData.getAddress().getPostalCode());
}
```

should continue to pass because the normalization behavior has not changed—only its location has changed.

# Key Takeaways

- **Extract Class** moves a responsibility into a dedicated class.    
- `DataNormalizer` is responsible for converting data into a consistent format.
- `UserRegistrationService` should coordinate the workflow rather than contain all implementation details.
- `normalizeUserData()` creates a **new `UserData` object** instead of modifying the original.
- Username and email are converted to lowercase.
- Street and city are trimmed.
- Country and postal code are converted to uppercase.
- Password and date of birth remain unchanged.
- Validation happens **before** normalization.
- Existing tests should continue to pass after a behavior-preserving refactoring.
- This improves **Separation of Concerns, Single Responsibility, readability, maintainability, and reusability**.
