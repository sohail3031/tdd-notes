# Task Objective

The existing `ShoppingCart` class contains logic for handling discount codes and calculating discounts.

The goal of this refactoring is to extract the discount-related responsibilities into a dedicated `DiscountCalculator` class.

The new `DiscountCalculator` will be responsible for:

- Storing available discount rates.
- Validating and applying discount codes.
- Remembering the currently applied discount code.
- Calculating the discount amount based on the cart subtotal.

The `ShoppingCart` should delegate discount operations to `DiscountCalculator`.

### Requirements

- Extract discount-related logic from `ShoppingCart`.
- Create a new `DiscountCalculator` class.
- Preserve the existing `ShoppingCart` public API.
- Ensure all existing tests continue to pass.
- Do not change the system's behavior.

---

## Code Smell Before Refactoring

Before the refactoring, `ShoppingCart` was responsible for several different concerns:

```text
ShoppingCart
├── Cart item management
├── Price calculations
├── Tax calculations
├── Discount code management
├── Discount calculation
├── Shipping calculations
├── Loyalty point calculations
└── Order summary generation
```

The discount-related code was:

```java
private String discountCode;

public void applyDiscountCode(String code) {
    if (List.of("SAVE10", "SUMMER20", "VIP15").contains(code)) {
        discountCode = code;
    } else {
        throw new IllegalStateException("Invalid discount code");
    }
}

public double calculateDiscount(double subtotal) {
    return switch (discountCode) {
        case "SAVE10" -> subtotal * 0.1;
        case "SUMMER20" -> subtotal * 0.2;
        case "VIP15" -> subtotal * 0.15;
        default -> 0;
    };
}
```

This creates another responsibility inside an already large class.

# Refactoring Strategy

Use the **Extract Class** refactoring.

The discount responsibilities will be moved from:

```text
ShoppingCart
```

to:

```text
DiscountCalculator
```

The resulting relationship is:

```text
ShoppingCart
    │
    ├── CartItemCollection
    ├── PriceCalculator
    └── DiscountCalculator
            │
            ├── Discount rates
            ├── Current discount code
            ├── Apply discount code
            └── Calculate discount
```

`ShoppingCart` will continue exposing:

```java
applyDiscountCode()
calculateDiscount()
```

but these methods will simply delegate to `DiscountCalculator`.

---

# Step 1: Create `DiscountCalculator`

The first step is to create a new class responsible for discount logic.

Instead of storing discount rates in multiple places, the rates are stored in a `Map`:

```java
private final Map<String, Double> discountRates = new HashMap<>();
```

This gives us a simple relationship:

```text
Discount Code → Discount Rate

SAVE10   → 0.10
SUMMER20 → 0.20
VIP15    → 0.15
```

# Step 2: Move Discount Rates

The discount rates are initialized inside the constructor:

```java
public DiscountCalculator() {
    discountRates.put("SAVE10", 0.1);
    discountRates.put("SUMMER20", 0.2);
    discountRates.put("VIP15", 0.15);
}
```

This replaces the previous `List.of(...)` validation and `switch` statement.

# Step 3: Move `applyDiscountCode()`

The discount-code validation is moved from `ShoppingCart` into `DiscountCalculator`.

Before:

```java
if (List.of("SAVE10", "SUMMER20", "VIP15").contains(code)) {
    discountCode = code;
} else {
    throw new IllegalStateException("Invalid discount code");
}
```

After:

```java
if (discountRates.containsKey(code)) {
    discountCode = code;
} else {
    throw new IllegalStateException("Invalid discount code");
}
```

This is a useful improvement because the same data structure that stores valid discount codes is also used to validate them.

There is now a **single source of truth** for discount codes.

---

# Step 4: Move `calculateDiscount()`

The discount calculation is also moved into `DiscountCalculator`.

Instead of:

```java
switch (discountCode) {
    case "SAVE10" -> subtotal * 0.1;
    case "SUMMER20" -> subtotal * 0.2;
    case "VIP15" -> subtotal * 0.15;
    default -> 0;
}
```

the discount rate can be retrieved from the map:

```java
return subtotal * discountRates.getOrDefault(discountCode, 0.0);
```

This removes the need for a `switch` statement.

# Final `DiscountCalculator.java`

```java
import java.util.HashMap;
import java.util.Map;

public class DiscountCalculator {
    private final Map<String, Double> discountRates = new HashMap<>();
    private String discountCode;

    public DiscountCalculator() {
        discountRates.put("SAVE10", 0.1);
        discountRates.put("SUMMER20", 0.2);
        discountRates.put("VIP15", 0.15);
    }

    public void applyDiscountCode(String code) {
        // Simplified discount code validation
        if (discountRates.containsKey(code)) {
            discountCode = code;
        } else {
            throw new IllegalStateException("Invalid discount code");
        }
    }

    public double calculateDiscount(double subtotal) {
        if (discountCode == null) {
            return 0;
        }

        return subtotal * discountRates.getOrDefault(discountCode, 0.0);
    }
}
```

# Final `ShoppingCart.java`

```java
import java.util.List;

public class ShoppingCart {
    private final CartItemCollection items = new CartItemCollection();
    private final PriceCalculator priceCalculator;
    private final DiscountCalculator discountCalculator = new DiscountCalculator();
    private final Customer customer;

    public ShoppingCart(Customer customer) {
        this.customer = customer;
        this.priceCalculator = new PriceCalculator(customer, items);
    }

    // Cart management
    public void addItem(Product product, int quantity) {
        if (!product.isInStock()) {
            throw new IllegalStateException("Product out of stock");
        }
        items.add(product.getId(), quantity);
    }

    public void removeItem(String productId) {
        items.remove(productId);
    }

    public void updateQuantity(String productId, int quantity) {
        if (quantity <= 0) {
            removeItem(productId);
        } else {
            items.update(productId, quantity);
        }
    }

    public void applyDiscountCode(String code) {
        discountCalculator.applyDiscountCode(code);
    }

    public double calculateDiscount(double subtotal) {
        return discountCalculator.calculateDiscount(subtotal);
    }

    // Shipping calculations
    public double calculateShippingCost(List<Product> products) {
        double subTotal = priceCalculator.calculateSubtotal(products);

        double totalWeight = items.getAll().stream().mapToDouble(entry -> {
            Product product = products.stream()
                    .filter(p -> p.getId().equals(entry.getProductId()))
                    .findFirst()
                    .orElse(null);

            return product != null
                    ? product.getWeight() * entry.getQuantity()
                    : 0;
        }).sum();

        // Base shipping rate calculation
        double shippingCost = 5 + (totalWeight * 0.1);

        // Free shipping for VIP customers or orders over $100
        if (customer.getPriceLevel() == PriceLevel.VIP || subTotal > 100) {
            return 0;
        }

        return shippingCost;
    }

    // Loyalty points
    public int calculateLoyaltyPoints(List<Product> products) {
        int points = 0;
        double subtotal = priceCalculator.calculateSubtotal(products);

        // Base points: 1 point per $10 spent
        points += (int) (subtotal / 10);

        // Bonus points for specific categories
        for (CartItem entry : items.getAll()) {
            Product product = products.stream()
                    .filter(p -> p.getId().equals(entry.getProductId()))
                    .findFirst()
                    .orElse(null);

            if (product != null && "electronics".equals(product.getCategory())) {
                points += entry.getQuantity() * 5;
            }
        }

        // VIP customers get double points
        if (customer.getPriceLevel() == PriceLevel.VIP) {
            points *= 2;
        }

        return points;
    }

    // Order summary
    public OrderSummary getOrderSummary(List<Product> products) {
        double subtotal = priceCalculator.calculateSubtotal(products);
        double tax = priceCalculator.calculateTax(subtotal);
        double discount = calculateDiscount(subtotal);
        double shippingCost = calculateShippingCost(products);
        double total = subtotal + tax - discount + shippingCost;
        int loyaltyPoints = calculateLoyaltyPoints(products);

        return new OrderSummary(
                subtotal,
                tax,
                discount,
                shippingCost,
                total,
                loyaltyPoints
        );
    }
}
```

# Why `ShoppingCart` Still Has `applyDiscountCode()`

A natural question is:

> If `DiscountCalculator` handles discounts, why doesn't the code call it directly?

Because `ShoppingCart` is the public interface for cart operations.

The existing API is:

```java
cart.applyDiscountCode("SUMMER20");
```

and:

```java
cart.calculateDiscount(subtotal);
```

Changing callers to:

```java
cart.getDiscountCalculator().applyDiscountCode("SUMMER20");
```

would expose unnecessary implementation details.

Instead, `ShoppingCart` acts as a **facade** and delegates the operation:

```text
Client
  │
  ▼
ShoppingCart
  │
  ▼
DiscountCalculator
```

This allows the internal implementation to change without requiring changes to callers.

# Single Responsibility Principle

The original `ShoppingCart` had multiple reasons to change.

For example:

- A new discount code could require changing `ShoppingCart`.
- Discount calculation rules could require changing `ShoppingCart`.
- Pricing changes could require changing `ShoppingCart`.
- Shipping changes could require changing `ShoppingCart`.

After extraction, discount-related changes can primarily happen in:

```text
DiscountCalculator
```

For example, adding:

```text
BLACKFRIDAY30 → 30%
```

only requires updating the discount component.

This improves adherence to the **Single Responsibility Principle (SRP)**.

# Why Use a `Map`?

The original implementation used a list for validation and a `switch` for calculation.

```java
List.of("SAVE10", "SUMMER20", "VIP15")
```

and:

```java
switch (discountCode)
```

The refactored version uses:

```java
Map<String, Double>
```

This combines the discount code and its rate:

```text
SAVE10   → 0.10
SUMMER20 → 0.20
VIP15    → 0.15
```

This provides a single source of truth.

It also makes the calculation simpler:

```java
double rate = discountRates.getOrDefault(discountCode, 0.0);
return subtotal * rate;
```

# Behavior Preservation

An important part of this refactoring is that **behavior must not change**.

For example:

### `SAVE10`

```text
Subtotal = $1000
Discount = 1000 × 0.10
         = $100
```

### `SUMMER20`

```text
Subtotal = $1000
Discount = 1000 × 0.20
         = $200
```

### `VIP15`

```text
Subtotal = $1000
Discount = 1000 × 0.15
         = $150
```

Applying a second valid discount code still replaces the previous code:

```java
cart.applyDiscountCode("SAVE10");
cart.applyDiscountCode("SUMMER20");
```

The resulting discount is:

```text
SUMMER20 → 20%
```

This preserves the behavior tested by:

```java
shouldAllowUpdatingDiscountCode()
```

# Key Takeaways

1. **Extract Class** moves a cohesive group of responsibilities into a new class.
2. `DiscountCalculator` now owns discount-related data and behavior.
3. `ShoppingCart` delegates discount operations instead of implementing them.
4. A `Map<String, Double>` provides a single source of truth for discount rates.
5. The public `ShoppingCart` API remains unchanged.
6. Delegation reduces the responsibilities of `ShoppingCart`.
7. The refactoring improves **Single Responsibility Principle** adherence.
8. Existing tests provide a safety net for behavior-preserving refactoring.
9. TDD and refactoring work together through the **Red → Green → Refactor → Green** cycle.
10. The goal of refactoring is not to change what the application does, but to improve **how the code is organized**.
