# Task Objective

The `ShoppingCart` class has become overloaded with multiple responsibilities, making it difficult to maintain and extend.

One area that stands out as a good candidate for refactoring is **cart item management**, including:

- Adding items    
- Removing items
- Updating item quantities
- Storing cart items
- Retrieving all cart items

The goal is to extract these responsibilities into a new class called `CartItemCollection`.

This refactoring helps:

- Reduce the responsibilities of `ShoppingCart`
- Improve cohesion
- Follow the **Single Responsibility Principle (SRP)**
- Reduce direct manipulation of the underlying collection
- Make the code easier to maintain and evolve

---

## Problem: `ShoppingCart` Has Too Many Responsibilities

Initially, `ShoppingCart` directly managed the internal item map:

```java
private final Map<String, Integer> items = new HashMap<>();
```

It also contained the logic for:

```java
addItem()
removeItem()
updateQuantity()
```

Additionally, it used the same collection directly when calculating:

- Subtotal    
- Shipping
- Loyalty points
- Order summary

This means `ShoppingCart` was responsible for both **managing cart items** and **performing calculations based on those items**.

### Before Refactoring

```text
ShoppingCart
├── Store cart items
├── Add items
├── Remove items
├── Update quantities
├── Calculate subtotal
├── Calculate tax
├── Apply discount codes
├── Calculate discounts
├── Calculate shipping
├── Calculate loyalty points
└── Generate order summary
```

This is a sign that the class is becoming a **Large Class** and has multiple areas of responsibility.

---

# Extract Class Refactoring

The solution is to extract item-management behavior into a dedicated class:

```text
ShoppingCart
    │
    │ owns
    ▼
CartItemCollection
    │
    │ manages
    ▼
CartItem
```

The responsibilities become:

### `ShoppingCart`

Responsible for the overall shopping cart and calculations.

### `CartItemCollection`

Responsible for managing the collection of cart items.

### `CartItem`

Represents an individual cart item.

---

# Step 1: Create `CartItem`

The original implementation stored items as:

```java
Map<String, Integer>
```

where:

- `String` = product ID
- `Integer` = quantity

Instead of exposing this implementation directly, we introduce a `CartItem` type.

```java
public class CartItem {
    private final String productId;
    private final int quantity;

    public CartItem(String productId, int quantity) {
        this.productId = productId;
        this.quantity = quantity;
    }

    public String getProductId() {
        return productId;
    }

    public int getQuantity() {
        return quantity;
    }
}
```

## Why Create `CartItem`?

`CartItem` represents the relationship between:

```text
Product ID → Quantity
```

For example:

```text
"p1" → 2
```

becomes:

```java
new CartItem("p1", 2);
```

This gives the item data a meaningful domain type instead of exposing a raw `Map.Entry`.

---

# Step 2: Create `CartItemCollection`

The `CartItemCollection` class owns the internal map and provides operations for managing items.

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class CartItemCollection {
    private final Map<String, Integer> items = new HashMap<>();

    public void add(String productId, int quantity) {
        items.put(productId, items.getOrDefault(productId, 0) + quantity);
    }

    public void update(String productId, int quantity) {
        if (quantity <= 0) {
            remove(productId);
        } else {
            items.put(productId, quantity);
        }
    }

    public void remove(String productId) {
        items.remove(productId);
    }

    public List<CartItem> getAll() {
        List<CartItem> result = new ArrayList<>();

        for (Map.Entry<String, Integer> entry : items.entrySet()) {
            result.add(new CartItem(entry.getKey(), entry.getValue()));
        }

        return result;
    }
}
```

---

# `CartItemCollection` Responsibilities

The new class has four main operations.

|Method|Responsibility|
|---|---|
|`add()`|Add an item or increase its quantity|
|`update()`|Set a new quantity|
|`remove()`|Remove an item|
|`getAll()`|Return all cart items|

The internal `Map` is now an implementation detail of `CartItemCollection`.

---

## `add()`

```java
public void add(String productId, int quantity) {
    items.put(productId, items.getOrDefault(productId, 0) + quantity);
}
```

If the item does not exist:

```text
p1 → 0 + quantity
```

If it already exists:

```text
existing quantity + new quantity
```

For example:

```java
add("p1", 2);
add("p1", 3);
```

results in:

```text
p1 → 5
```

---

## `update()`

```java
public void update(String productId, int quantity) {
    if (quantity <= 0) {
        remove(productId);
    } else {
        items.put(productId, quantity);
    }
}
```

This preserves the original behavior.

A positive quantity updates the item:

```text
p1 → 5
```

becomes:

```text
p1 → 2
```

A quantity of `0` or less removes the item.

```text
p1 → 5
```

becomes:

```text
p1 → removed
```

---

## `remove()`

```java
public void remove(String productId) {
    items.remove(productId);
}
```

The collection itself now knows how to remove an item.

`ShoppingCart` no longer needs to interact with the `Map` directly.

---

## `getAll()`

```java
public List<CartItem> getAll() {
    List<CartItem> result = new ArrayList<>();

    for (Map.Entry<String, Integer> entry : items.entrySet()) {
        result.add(new CartItem(entry.getKey(), entry.getValue()));
    }

    return result;
}
```

This converts the internal map into a list of `CartItem` objects.

For example:

```text
Internal Map

p1 → 2
p2 → 5
```

becomes:

```text
List<CartItem>

CartItem("p1", 2)
CartItem("p2", 5)
```

This allows other classes to work with `CartItem` rather than knowing that a `HashMap` is being used internally.

---

# Step 3: Update `ShoppingCart`

The original field:

```java
private final Map<String, Integer> items = new HashMap<>();
```

is replaced with:

```java
private final CartItemCollection items = new CartItemCollection();
```

`ShoppingCart` now delegates item-management operations to `CartItemCollection`.

---

# Updated Cart Management Methods

### `addItem()`

Before:

```java
items.put(product.getId(), items.getOrDefault(product.getId(), 0) + quantity);
```

After:

```java
public void addItem(Product product, int quantity) {
    if (!product.isInStock()) {
        throw new IllegalStateException("Product out of stock");
    }

    items.add(product.getId(), quantity);
}
```

Notice that the **product availability check remains in `ShoppingCart`**.

This is important because checking whether a product is in stock is a responsibility of the cart operation involving a `Product`, while managing the collection itself belongs to `CartItemCollection`.

---

### `removeItem()`

```java
public void removeItem(String productId) {
    items.remove(productId);
}
```

---

### `updateQuantity()`

Before:

```java
public void updateQuantity(String productId, int quantity) {
    if (quantity <= 0) {
        removeItem(productId);
    } else {
        items.put(productId, quantity);
    }
}
```

After:

```java
public void updateQuantity(String productId, int quantity) {
    items.update(productId, quantity);
}
```

The quantity-management logic has been moved into `CartItemCollection`.

---

# Updating Item-Related Calculations

The calculations in `ShoppingCart` still need access to the cart items.

Instead of iterating over:

```java
items.entrySet()
```

they now call:

```java
items.getAll()
```

For example, subtotal calculation changes from:

```java
for (Map.Entry<String, Integer> entry : items.entrySet()) {
    String productId = entry.getKey();
    int quantity = entry.getValue();
```

to:

```java
for (CartItem item : items.getAll()) {
    String productId = item.getProductId();
    int quantity = item.getQuantity();
```

The same pattern is applied to shipping and loyalty-point calculations.

# Final `ShoppingCart.java`

```java
import java.util.*;

public class ShoppingCart {

    private final CartItemCollection items = new CartItemCollection();

    private final Customer customer;
    private String discountCode;
    private final double taxRate = 0.1;

    public ShoppingCart(Customer customer) {
        this.customer = customer;
    }

    // Cart management

    public void addItem(Product product, int quantity) {
        if (!product.isInStock()) {
            throw new IllegalStateException("Product out of stock");
        }
        items.add(product.getId(), quantity);
    }

    public void removeItem(String productId) {
        items.remove(productId);
    }

    public void updateQuantity(String productId, int quantity) {
        items.update(productId, quantity);
    }

    public double calculateSubtotal(List<Product> products) {
        double subtotal = 0.0;

        for (CartItem item : items.getAll()) {
            String productId = item.getProductId();
            int quantity = item.getQuantity();

            Optional<Product> optionalProduct = products.stream()
                    .filter(p -> p.getId().equals(productId))
                    .findFirst();

            if (optionalProduct.isPresent()) {
                Product product = optionalProduct.get();
                double price = product.getPrice();

                // Apply price level discounts
                if (customer.getPriceLevel() == PriceLevel.PREMIUM) {
                    price *= 0.9; // 10% off for premium customers
                } else if (customer.getPriceLevel() == PriceLevel.VIP) {
                    price *= 0.85; // 15% off for VIP customers
                }

                subtotal += price * quantity;
            }
        }

        return subtotal;
    }

    public double calculateTax(double subtotal) {
        return subtotal * taxRate;
    }

    public void applyDiscountCode(String code) {
        // Simplified discount code validation
        List<String> validCodes = Arrays.asList(
                "SAVE10",
                "SUMMER20",
                "VIP15"
        );

        if (validCodes.contains(code)) {
            discountCode = code;
        } else {
            throw new IllegalStateException("Invalid discount code");
        }
    }

    public double calculateDiscount(double subtotal) {
        if (discountCode == null) {
            return 0.0;
        }

        switch (discountCode) {
            case "SAVE10":
                return subtotal * 0.1;
            case "SUMMER20":
                return subtotal * 0.2;
            case "VIP15":
                return subtotal * 0.15;
            default:
                return 0.0;
        }
    }

    // Shipping calculations

    public double calculateShippingCost(List<Product> products) {
        double totalWeight = 0.0;

        for (CartItem item : items.getAll()) {
            String productId = item.getProductId();
            int quantity = item.getQuantity();

            Optional<Product> optionalProduct = products.stream()
                    .filter(p -> p.getId().equals(productId))
                    .findFirst();

            if (optionalProduct.isPresent()) {
                Product product = optionalProduct.get();
                totalWeight += product.getWeight() * quantity;
            }
        }

        // Base shipping rate calculation
        double shippingCost = 5.0 + (totalWeight * 0.1);

        // Free shipping for VIP customers or orders over $100
        double subtotal = calculateSubtotal(products);

        if (customer.getPriceLevel() == PriceLevel.VIP || subtotal > 100.0) {
            return 0.0;
        }

        return shippingCost;
    }

    // Loyalty points

    public int calculateLoyaltyPoints(List<Product> products) {
        int points = 0;
        double subtotal = calculateSubtotal(products);

        // Base points: 1 point per $10 spent
        points += (int) (subtotal / 10);

        // Bonus points for specific categories
        for (CartItem item : items.getAll()) {
            String productId = item.getProductId();
            int quantity = item.getQuantity();

            Optional<Product> optionalProduct = products.stream()
                    .filter(p -> p.getId().equals(productId))
                    .findFirst();

            if (optionalProduct.isPresent()) {
                Product product = optionalProduct.get();

                if ("electronics".equalsIgnoreCase(product.getCategory())) {
                    points += quantity * 5;
                }
            }
        }

        // VIP customers get double points
        if (customer.getPriceLevel() == PriceLevel.VIP) {
            points *= 2;
        }

        return points;
    }

    // Order summary

    public OrderSummary getOrderSummary(List<Product> products) {
        double subtotal = calculateSubtotal(products);
        double tax = calculateTax(subtotal);
        double discount = calculateDiscount(subtotal);
        double shippingCost = calculateShippingCost(products);
        double total = subtotal + tax - discount + shippingCost;
        int loyaltyPoints = calculateLoyaltyPoints(products);

        return new OrderSummary(
                subtotal,
                tax,
                discount,
                shippingCost,
                total,
                loyaltyPoints
        );
    }
}
```

# What Changed?

The main structural change is:

### Before

```text
ShoppingCart
    │
    └── Map<String, Integer>
```

`ShoppingCart` directly controlled the map.

### After

```text
ShoppingCart
    │
    └── CartItemCollection
            │
            └── Map<String, Integer>
```

`ShoppingCart` delegates item management to `CartItemCollection`.

---

# Why Keep `addItem()` on `ShoppingCart`?

Even though `CartItemCollection` has an `add()` method, the public API of the shopping cart remains:

```java
cart.addItem(product, quantity);
```

rather than:

```java
cart.getItems().add(...);
```

This is useful because `ShoppingCart` still controls the business rule:

```java
if (!product.isInStock()) {
    throw new IllegalStateException("Product out of stock");
}
```

After the validation succeeds, it delegates the actual collection operation:

```java
items.add(product.getId(), quantity);
```

This creates a clean separation:

```text
ShoppingCart
    │
    ├── Validate product is in stock
    │
    └── Delegate item storage
              ↓
       CartItemCollection
```

# What Happens to the Tests?

The existing `ShoppingCartTest` and its subclasses continue to use the public `ShoppingCart` API:

```java
cart.addItem(laptop, 1);
cart.removeItem(laptop.getId());
cart.updateQuantity(laptop.getId(), 2);
```

Therefore, the tests do not need to know that the internal implementation has changed.

For example:

```java
cart.addItem(laptop, 1);
cart.addItem(book, 2);
```

still produces the same subtotal.

The important point is that this is a **behavior-preserving refactoring**.

The internal structure changes, but the externally observable behavior remains the same.

# TDD Perspective

This refactoring follows the **Red-Green-Refactor** cycle.

```text
RED
 ↓
Existing tests define the expected behavior
 ↓
GREEN
 ↓
Existing implementation passes
 ↓
REFACTOR
 ↓
Extract CartItemCollection
 ↓
GREEN
 ↓
All existing tests still pass
```

The tests act as a safety net while changing the internal design.

The goal is **not** to change what the shopping cart does.

The goal is to improve **how the code is organized**.

# Single Responsibility Principle

Before refactoring, `ShoppingCart` had responsibility for both:

```text
Cart item management
+
Shopping cart calculations
```

After refactoring:

```text
ShoppingCart
    ├── Cart-level business operations
    ├── Pricing
    ├── Tax
    ├── Discounts
    ├── Shipping
    └── Loyalty points

CartItemCollection
    ├── Add item
    ├── Update quantity
    ├── Remove item
    └── Retrieve items

CartItem
    ├── Product ID
    └── Quantity
```

This gives each class a more focused responsibility.

---

# Extract Class vs. Extract Method

This refactoring is different from simply extracting a method.

### Extract Method

Used when a method contains a logical piece of functionality that should be separated.

```text
Large Method
    ↓
Several smaller methods
```

### Extract Class

Used when a class contains a group of related responsibilities that belong together.

```text
Large Class
    ↓
Original Class + New Focused Class
```

Here, several item-management operations belong together, so **Extract Class** is appropriate.

---

# Important Design Principle

> **A class should not need to know how another class stores its data.**

`ShoppingCart` previously knew that its items were stored in:

```java
Map<String, Integer>
```

After refactoring, that implementation detail belongs to:

```java
CartItemCollection
```

This reduces coupling.

If the internal implementation later changes from:

```java
HashMap
```

to another data structure, `ShoppingCart` does not necessarily need to change.

---

# Benefits of This Refactoring

### 1. Improved Cohesion

`CartItemCollection` contains operations that are closely related.

### 2. Reduced Complexity

`ShoppingCart` no longer directly manages the item map.

### 3. Better Encapsulation

The internal `Map` is hidden inside `CartItemCollection`.

### 4. Easier Maintenance

Changes to item-management behavior can be made in one place.

### 5. Easier Testing

`CartItemCollection` can be tested independently.

### 6. Better SRP Compliance

The item-management responsibility has been separated from the larger shopping-cart responsibility.

### 7. Reduced Coupling

`ShoppingCart` depends on the behavior of `CartItemCollection` rather than its internal `Map` implementation.

---

# Refactoring Pattern

This task demonstrates:

**Extract Class**

The general pattern is:

```text
Identify related fields and methods
            ↓
Create a new class
            ↓
Move related data into the new class
            ↓
Move related behavior into the new class
            ↓
Replace direct access with delegation
            ↓
Run tests
            ↓
Confirm behavior is unchanged
```

---

# Refactoring Checklist

When extracting a collection-management class, look for:

-  A large class with multiple responsibilities
-  A group of related fields
-  Multiple methods operating on those fields
-  A cohesive responsibility that can be isolated
-  A new class representing that responsibility
-  Delegation from the original class
-  Existing tests still passing
-  No unnecessary behavior changes

---

# Key Takeaways

- `ShoppingCart` was becoming a **Large Class** with too many responsibilities.
- Item management was a cohesive responsibility that could be extracted.
- `CartItemCollection` now owns the internal item map.
- `CartItem` represents an individual product ID and quantity.
- `ShoppingCart` delegates item operations to `CartItemCollection`.
- The public `ShoppingCart` API remains unchanged.
- The existing tests provide confidence that behavior was preserved.
- This refactoring improves **cohesion, encapsulation, maintainability, and SRP compliance**.
- **Extract Class** is useful when a class contains a group of related fields and methods that form a distinct responsibility.
- Good refactoring changes the **structure of the code without unnecessarily changing its behavior**.

> **Core principle:** Extract cohesive responsibilities into focused classes, keep implementation details encapsulated, and use tests as a safety net while refactoring.
