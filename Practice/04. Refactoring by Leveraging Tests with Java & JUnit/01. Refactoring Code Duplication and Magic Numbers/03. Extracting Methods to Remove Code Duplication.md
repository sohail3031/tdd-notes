The goal of this task is to improve the maintainability of the `ShoppingCart` class by identifying and refactoring duplicated code.

The logic for calculating the cost of an individual `CartItem`, including the bulk discount, is duplicated in both:

- `calculateTotal()`    
- `calculateTotalWithStudentDiscount()`

The objective is to extract this duplicated logic into a separate method called `calculateItemCost()`.

---

## Identifying the Duplication

Both methods originally contained the same logic:

```java
double itemTotal = item.getPrice() * item.getQuantity();

if (item.getQuantity() >= 5) {
    itemTotal *= 0.9; // 10% discount
}
```

This code calculates the cost of one item and applies a **10% bulk discount** when the quantity is 5 or more.

The same logic appeared in both methods.

### `calculateTotal()`

```java
for (CartItem item : items) {
    double itemTotal = item.getPrice() * item.getQuantity();

    if (item.getQuantity() >= 5) {
        itemTotal *= 0.9;
    }

    total += itemTotal;
}
```

### `calculateTotalWithStudentDiscount()`

```java
for (CartItem item : items) {
    double itemTotal = item.getPrice() * item.getQuantity();

    if (item.getQuantity() >= 5) {
        itemTotal *= 0.9;
    }

    total += itemTotal;
}
```

The duplicated logic should be extracted into its own method.

---

## Extracting `calculateItemCost()`

Create a method that accepts a single `CartItem` and returns its calculated cost.

```java
public double calculateItemCost(CartItem cartItem) {
    double itemTotal = cartItem.getPrice() * cartItem.getQuantity();

    if (cartItem.getQuantity() >= 5) {
        itemTotal *= 0.9; // 10% discount
    }

    return itemTotal;
}
```

This method is now responsible for:

1. Getting the item's price.    
2. Getting the item's quantity.
3. Calculating the base item cost.
4. Applying the 10% bulk discount when the quantity is 5 or more.
5. Returning the final cost for that item.

---

## Updating `calculateTotal()`

The duplicated calculation is removed and replaced with a call to `calculateItemCost()`:

```java
public double calculateTotal() {
    double total = 0;

    for (CartItem item : items) {
        total += calculateItemCost(item);
    }

    return total;
}
```

Instead of calculating the item cost directly, the method delegates that responsibility to `calculateItemCost()`.

---

## Updating `calculateTotalWithStudentDiscount()`

The same refactoring is applied to `calculateTotalWithStudentDiscount()`:

```java
public double calculateTotalWithStudentDiscount() {
    double total = 0;

    for (CartItem item : items) {
        total += calculateItemCost(item);
    }

    return total * 0.85; // 15% student discount
}
```

The bulk discount logic is now located in only one place.

---

## Refactored `ShoppingCart.java`

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private final List<CartItem> items = new ArrayList<>();

    public void addItem(String name, double price, int quantity) {
        items.add(new CartItem(name, price, quantity));
    }

    public double calculateItemCost(CartItem cartItem) {
        double itemTotal = cartItem.getPrice() * cartItem.getQuantity();

        if (cartItem.getQuantity() >= 5) {
            itemTotal *= 0.9; // 10% discount
        }

        return itemTotal;
    }

    public double calculateTotal() {
        double total = 0;

        for (CartItem item : items) {
            total += calculateItemCost(item);
        }

        return total;
    }

    public double calculateTotalWithStudentDiscount() {
        double total = 0;

        for (CartItem item : items) {
            total += calculateItemCost(item);
        }

        return total * 0.85; // 15% student discount
    }
}
```

## Refactoring Strategy

This task demonstrates **Extract Method**, a common refactoring technique.

The process was:

```text
Identify duplicated logic
        ↓
Extract the duplicated logic
        ↓
Create calculateItemCost()
        ↓
Replace duplicated code with method calls
        ↓
Run tests
        ↓
Verify behavior is unchanged
```

---

## Why Extract the Method?

Without refactoring:

```text
calculateTotal()
    └── item cost calculation

calculateTotalWithStudentDiscount()
    └── item cost calculation
```

The same business logic exists in two places.

After refactoring:

```text
calculateTotal()
    └── calculateItemCost()

calculateTotalWithStudentDiscount()
    └── calculateItemCost()
              ↓
       Item cost calculation
```

Now there is a **single source of truth** for calculating an item's cost.

If the bulk discount changes in the future, only `calculateItemCost()` needs to be updated.

---

## Important Takeaway

> **Extract duplicated logic into a method when multiple parts of the code perform the same operation.**

This improves:

- Maintainability    
- Readability
- Reusability
- Consistency
- Ease of future changes

### Small Refactor, Then Verify

The task intentionally leaves the duplicated `for` loops in place.

This is an important refactoring principle:

> **Make small changes and verify that the tests still pass after each change.**

The next refactoring step can deal with the duplicated loops separately.
