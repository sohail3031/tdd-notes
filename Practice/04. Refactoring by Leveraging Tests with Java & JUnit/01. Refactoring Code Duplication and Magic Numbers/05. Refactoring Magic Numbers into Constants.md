# Task

Refactor the `ShoppingCart` class by extracting **magic numbers** into meaningful named constants.

### Magic numbers to extract

| Magic Number | Meaning                                     | Constant                  |
| -----------: | ------------------------------------------- | ------------------------- |
|          `5` | Minimum quantity required for bulk discount | `BULK_DISCOUNT_THRESHOLD` |
|        `0.9` | Price multiplier after 10% bulk discount    | `BULK_DISCOUNT_RATE`      |
|       `0.85` | Price multiplier after 15% student discount | `STUDENT_DISCOUNT_RATE`   |

The goal is to improve **readability, maintainability, and expressiveness** without changing the behavior of the application.

---

## What Are Magic Numbers?

A **magic number** is a numerical value used directly in code without explaining what it represents.

For example:

```java
if (item.getQuantity() >= 5) {
    itemTotal *= 0.9;
}
```

Someone reading this code has to figure out:

- Why is the threshold `5`?    
- Why is the multiplier `0.9`?
- What does `0.9` represent?

The code becomes much clearer when these values are given meaningful names.

---

## Refactoring Approach

Replace:

```java
if (item.getQuantity() >= 5) {
    itemTotal *= 0.9;
}
```

with:

```java
if (item.getQuantity() >= BULK_DISCOUNT_THRESHOLD) {
    itemTotal *= BULK_DISCOUNT_RATE;
}
```

And replace:

```java
return calculateSubtotal() * 0.85;
```

with:

```java
return calculateSubtotal() * STUDENT_DISCOUNT_RATE;
```

## Constants in Java

Constants are commonly declared using:

```java
private static final
```

Naming convention:

```text
UPPER_SNAKE_CASE
```

For example:

```java
private static final double BULK_DISCOUNT_RATE = 0.9;
```

### Why `static final`?

- `static` → belongs to the class rather than an individual `ShoppingCart` object.    
- `final` → the value cannot be changed after initialization.
- Together, they are appropriate for fixed configuration values such as discount rates and thresholds.

---

## Final `ShoppingCart.java`

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private static final double BULK_DISCOUNT_THRESHOLD = 5;
    private static final double BULK_DISCOUNT_RATE = 0.9;
    private static final double STUDENT_DISCOUNT_RATE = 0.85;

    private final List<CartItem> items = new ArrayList<>();

    public void addItem(String name, double price, int quantity) {
        items.add(new CartItem(name, price, quantity));
    }

    private static double calculateItemCost(CartItem item) {
        double itemTotal = item.getPrice() * item.getQuantity();

        if (item.getQuantity() >= BULK_DISCOUNT_THRESHOLD) {
            itemTotal *= BULK_DISCOUNT_RATE; // 10% discount
        }

        return itemTotal;
    }

    public double calculateSubtotal() {
        double total = 0;

        for (CartItem item : items) {
            total += calculateItemCost(item);
        }

        return total;
    }

    public double calculateTotal() {
        return calculateSubtotal();
    }

    public double calculateTotalWithStudentDiscount() {
        return calculateSubtotal() * STUDENT_DISCOUNT_RATE; // 15% student discount
    }
}
```

## `CartItem.java`

No changes are required to `CartItem`.

```java
public class CartItem {
    private final String name;
    private final double price;
    private final int quantity;

    public CartItem(String name, double price, int quantity) {
        this.name = name;
        this.price = price;
        this.quantity = quantity;
    }

    public String getName() {
        return name;
    }

    public double getPrice() {
        return price;
    }

    public int getQuantity() {
        return quantity;
    }
}
```

## Why This Refactoring Is Useful

### 1. Improved readability

The purpose of each value is immediately clear.

```java
BULK_DISCOUNT_THRESHOLD
```

is much more descriptive than:

```java
5
```

### 2. Easier maintenance

Suppose the business changes the bulk discount from **10% to 15%**.

Instead of searching through the code for every occurrence of `0.9`, we can change:

```java
private static final double BULK_DISCOUNT_RATE = 0.9;
```

to:

```java
private static final double BULK_DISCOUNT_RATE = 0.85;
```

### 3. Reduced duplication

If the same discount rate is needed in multiple places, all locations can use the same constant.

### 4. Better communication

Well-named constants make the code closer to business/domain language.

```java
BULK_DISCOUNT_THRESHOLD
BULK_DISCOUNT_RATE
STUDENT_DISCOUNT_RATE
```

tell us what the values mean without requiring additional comments.

## TDD: Refactor Step

The overall TDD cycle is:

```text
Red → Green → Refactor
```

### Red

Write a test that initially fails.

### Green

Implement the simplest solution that makes the test pass.

### Refactor

Improve the internal structure of the code **without changing its behavior**.

In this task, the code was refactored by replacing magic numbers with named constants.

The tests provide confidence that the refactoring did not introduce behavioral changes.

> [!IMPORTANT]  
> **Refactoring should change the structure of the code, not its externally observable behavior.**

## Key Takeaways

- **Magic numbers** are unexplained numerical values embedded directly in code.    
- Replace magic numbers with **meaningful named constants**.
- Java constants are commonly declared using `private static final`.
- Use **UPPER_SNAKE_CASE** for constant names.
- Good constant names communicate business meaning.
- Constants make future changes easier and safer.
- Existing tests act as a **safety net during refactoring**.
- The goal of the **Refactor** step is to improve code quality while preserving behavior.

> [!TIP]  
> When you see a hard-coded value such as `5`, `0.9`, `0.85`, `100`, `60`, etc., ask: **"Does this number have a business or domain meaning?"** If it does, consider replacing it with a well-named constant.
