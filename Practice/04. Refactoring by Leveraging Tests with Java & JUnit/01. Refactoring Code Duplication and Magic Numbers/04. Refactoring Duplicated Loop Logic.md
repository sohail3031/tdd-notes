The goal of this task is to continue refactoring the `ShoppingCart` class by eliminating duplication in the **looping logic**.

Previously, the duplicated logic for calculating the cost of an individual `CartItem` was extracted into the `calculateItemCost()` method.

However, there is still duplication between:

- `calculateTotal()`    
- `calculateTotalWithStudentDiscount()`

Both methods iterate over the `items` list and calculate the total.

The goal is to extract this repeated loop into a reusable method while keeping the existing behavior and test coverage unchanged.

---

## Identifying the Duplication

Both methods originally contained the same loop:

```java
double total = 0;

for (CartItem item : items) {
    total += calculateItemCost(item);
}
```

### `calculateTotal()`

```java
public double calculateTotal() {
    double total = 0;

    for (CartItem item : items) {
        total += calculateItemCost(item);
    }

    return total;
}
```

### `calculateTotalWithStudentDiscount()`

```java
public double calculateTotalWithStudentDiscount() {
    double total = 0;

    for (CartItem item : items) {
        total += calculateItemCost(item);
    }

    return total * 0.85;
}
```

The loop itself is duplicated, so it can be extracted into a reusable method.

---

## Extracting the Loop

Create a method that accepts a list of `CartItem` objects and calculates the total cost.

```java
private double calculateItemCost(List<CartItem> itemsList) {
    double total = 0;

    for (CartItem item : itemsList) {
        double itemTotal = item.getPrice() * item.getQuantity();

        if (item.getQuantity() >= 5) {
            itemTotal *= 0.9; // 10% discount
        }

        total += itemTotal;
    }

    return total;
}
```

The extracted method now handles the iteration over the items and calculates the total.

---

## Updating `calculateTotal()`

The `calculateTotal()` method no longer needs its own loop.

```java
public double calculateTotal() {
    return calculateItemCost(items);
}
```

It simply delegates the calculation to the extracted method.

---

## Updating `calculateTotalWithStudentDiscount()`

The student discount is applied after calculating the regular cart total:

```java
public double calculateTotalWithStudentDiscount() {
    return calculateItemCost(items) * 0.85; // 15% student discount
}
```

The shared loop is now reused instead of being duplicated.

## Refactored `ShoppingCart.java`

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private final List<CartItem> items = new ArrayList<>();

    public void addItem(String name, double price, int quantity) {
        items.add(new CartItem(name, price, quantity));
    }

    private double calculateItemCost(List<CartItem> itemsList) {
        double total = 0;

        for (CartItem item : itemsList) {
            double itemTotal = item.getPrice() * item.getQuantity();

            if (item.getQuantity() >= 5) {
                itemTotal *= 0.9; // 10% discount
            }

            total += itemTotal;
        }

        return total;
    }

    public double calculateTotal() {
        return calculateItemCost(items);
    }

    public double calculateTotalWithStudentDiscount() {
        return calculateItemCost(items) * 0.85; // 15% student discount
    }
}
```

```text
calculateTotal()

calculateTotalWithStudentDiscount()
```
```text
    └── calculateItemCost(items)
```

This progressively removes duplication through **small, controlled refactoring steps**.

---

## Important Refactoring Principle

> **Refactoring should be done in small steps, with tests run after each change.**

Instead of trying to completely redesign the `ShoppingCart` class at once:

1. Identify one duplication.
2. Extract it.
3. Replace the duplicated code.
4. Run the tests.
5. Confirm that behavior remains unchanged.
6. Move on to the next duplication.

This makes refactoring safer and easier to troubleshoot.

---

## Why Extract the Loop?

Extracting the loop provides several benefits:

- Removes duplicated code.
- Makes `calculateTotal()` much simpler.
- Makes `calculateTotalWithStudentDiscount()` much simpler.
- Centralizes the calculation logic.
- Makes future changes easier.
- Preserves the existing behavior.
- Keeps the public methods focused on their specific responsibilities.

The two public methods now clearly express their purpose:

```java
public double calculateTotal() {
    return calculateItemCost(items);
}
```

```java
public double calculateTotalWithStudentDiscount() {
    return calculateItemCost(items) * 0.85;
}
```

The implementation details are hidden inside the reusable method.
