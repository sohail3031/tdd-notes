The goal of this task is to improve the maintainability of the `ShoppingCartTest` suite by identifying duplicated test cases and refactoring them into a **parameterized test**.

The three tests that verify the bulk discount are essentially identical:

- `testAppliesBulkDiscountForFiveItems()`    
- `testAppliesBulkDiscountForSixItems()`
- `testAppliesBulkDiscountForTenItems()`

The only differences are the **quantity** and **expected total**.

Instead of maintaining three separate test methods, we can use JUnit 5's:

- `@ParameterizedTest`
- `@MethodSource`
- `Arguments`
- `Stream`

This allows the same test logic to run multiple times with different input values.

---

## Problem: Duplicated Test Cases

Before refactoring, the tests contain the same Arrange, Act, and Assert structure:

```java
@Test
public void testAppliesBulkDiscountForFiveItems() {
    // Arrange
    cart.addItem("notebook", 10, 5);

    // Act
    double total = cart.calculateTotal();

    // Assert
    assertEquals(45, total);
}
```

```java
@Test
public void testAppliesBulkDiscountForSixItems() {
    // Arrange
    cart.addItem("notebook", 10, 6);

    // Act
    double total = cart.calculateTotal();

    // Assert
    assertEquals(54, total);
}
```

```java
@Test
public void testAppliesBulkDiscountForTenItems() {
    // Arrange
    cart.addItem("notebook", 10, 10);

    // Act
    double total = cart.calculateTotal();

    // Assert
    assertEquals(90, total);
}
```

The test logic is the same. Only the input values and expected result change.

This is a good candidate for a **parameterized test**.

## Parameterized Tests

A parameterized test allows the same test method to execute multiple times using different sets of input data.

JUnit 5 provides `@ParameterizedTest` for this purpose.

For example:

```java
@ParameterizedTest
@MethodSource("provideAdditionData")
public void testSumAddsTwoNumbersCorrectly(int a, int b, int expected) {
    // Arrange
    Math math = new Math();

    // Act
    int result = math.sum(a, b);

    // Assert
    assertEquals(expected, result);
}
```

The data is provided by the `@MethodSource` method:

```java
private static Stream<Arguments> provideAdditionData() {
    return Stream.of(
        Arguments.of(1, 2, 3),
        Arguments.of(4, 5, 9),
        Arguments.of(10, 11, 21)
    );
}
```

Each `Arguments.of(...)` represents one test case.

---

## `@MethodSource`

`@MethodSource` allows a test to receive its input values from a separate method.

The method returns a `Stream<Arguments>`:

```java
private static Stream<Arguments> provideAdditionData() {
    return Stream.of(
        Arguments.of(1, 2, 3),
        Arguments.of(4, 5, 9),
        Arguments.of(10, 11, 21)
    );
}
```

The arguments correspond to the parameters of the test method.

For example:

```java
Arguments.of(1, 2, 3)
```

maps to:

```java
public void testSumAddsTwoNumbersCorrectly(
    int a,
    int b,
    int expected
)
```

So:

```text
a        = 1
b        = 2
expected = 3
```

Each set of arguments causes the parameterized test to run once.

## Refactoring the Bulk Discount Tests

The three duplicated tests can be replaced with a single parameterized test.

### Test Data

```java
private static Stream<Arguments> applyBulkDiscount() {
    return Stream.of(
        Arguments.of("notebook", 10, 5, 45),
        Arguments.of("notebook", 10, 6, 54),
        Arguments.of("notebook", 10, 10, 90)
    );
}
```

The values represent:

```text
name       price    quantity    expected
-----------------------------------------
notebook   10       5           45
notebook   10       6           54
notebook   10       10          90
```

### Parameterized Test

```java
@ParameterizedTest
@MethodSource("applyBulkDiscount")
public void testApplyBulkDiscounts(
        String name,
        int price,
        int quantity,
        int expected) {

    // Arrange
    cart.addItem(name, price, quantity);

    // Act
    double total = cart.calculateTotal();

    // Assert
    assertEquals(expected, total);
}
```

The same test now runs three times:

```text
Test 1 → notebook, 10, 5  → expected 45
Test 2 → notebook, 10, 6  → expected 54
Test 3 → notebook, 10, 10 → expected 90
```

## Final Refactored `ShoppingCartTest.java`

```java
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.Arguments;
import org.junit.jupiter.params.provider.MethodSource;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.stream.Stream;

public class ShoppingCartTest {

    private ShoppingCart cart;

    @BeforeEach
    public void setUp() {
        cart = new ShoppingCart();
    }

    @Test
    public void testCalculatesTotalForSingleItem() {
        // Arrange
        cart.addItem("book", 20, 1);

        // Act
        double total = cart.calculateTotal();

        // Assert
        assertEquals(20, total);
    }

    @Test
    public void testCalculatesTotalForMultipleItems() {
        // Arrange
        cart.addItem("book", 20, 1);
        cart.addItem("pen", 5, 1);

        // Act
        double total = cart.calculateTotal();

        // Assert
        assertEquals(25, total);
    }

    private static Stream<Arguments> applyBulkDiscount() {
        return Stream.of(
            Arguments.of("notebook", 10, 5, 45),
            Arguments.of("notebook", 10, 6, 54),
            Arguments.of("notebook", 10, 10, 90)
        );
    }

    @ParameterizedTest
    @MethodSource("applyBulkDiscount")
    public void testApplyBulkDiscounts(
            String name,
            int price,
            int quantity,
            int expected) {

        // Arrange
        cart.addItem(name, price, quantity);

        // Act
        double total = cart.calculateTotal();

        // Assert
        assertEquals(expected, total);
    }

    @Test
    public void testDoesNotApplyBulkDiscountForFourItems() {
        // Arrange
        cart.addItem("notebook", 10, 4);

        // Act
        double total = cart.calculateTotal();

        // Assert
        assertEquals(40, total); // 10 * 4
    }

    @Test
    public void testAppliesStudentDiscountToTotalOfOneItem() {
        // Arrange
        cart.addItem("textbook", 100, 1);

        // Act
        double total = cart.calculateTotalWithStudentDiscount();

        // Assert
        assertEquals(85, total); // 100 * 0.85
    }

    @Test
    public void testAppliesStudentDiscountToTotalOfMultipleItems() {
        // Arrange
        cart.addItem("textbook", 100, 1);
        cart.addItem("notebook", 20, 1);

        // Act
        double total = cart.calculateTotalWithStudentDiscount();

        // Assert
        assertEquals(102, total); // (100 + 20) * 0.85
    }

    @Test
    public void testAppliesBothBulkAndStudentDiscount() {
        // Arrange
        cart.addItem("textbook", 100, 5);

        // Act
        double total = cart.calculateTotalWithStudentDiscount();

        // Assert
        assertEquals(382.50, total, 0.001); // (100 * 5 * 0.9) * 0.85
    }
}
```

## Why Use Parameterized Tests?

Parameterized tests are useful when:

- The **test logic is identical**.
- Only the **input values change**.
- Multiple scenarios need to be tested.
- You want to avoid duplicating test methods.
- You want to make it easy to add additional test cases.

For example, adding another bulk discount scenario only requires adding another `Arguments.of(...)`:

```java
Arguments.of("notebook", 10, 7, 63)
```

No additional test method is required.

---

## Important Takeaway

> **Parameterized tests allow one test method to verify multiple input/output combinations without duplicating the test logic.**

The overall structure is:

```text
@MethodSource
      ↓
Provides test data
      ↓
Stream<Arguments>
      ↓
@ParameterizedTest
      ↓
Runs the same test logic
      ↓
One execution per Arguments.of(...)
```

### Key JUnit 5 Annotations and Classes

|Feature|Purpose|
|---|---|
|`@ParameterizedTest`|Marks a test that runs multiple times with different inputs|
|`@MethodSource`|Specifies the method that provides test data|
|`Arguments`|Represents one set of parameters for a test execution|
|`Stream<Arguments>`|Supplies multiple sets of test parameters|

---

## Refactoring Principle

This task demonstrates the **Don't Repeat Yourself (DRY)** principle in test code.

Instead of:

```text
Test 1 → Arrange → Act → Assert
Test 2 → Arrange → Act → Assert
Test 3 → Arrange → Act → Assert
```

we now have:

```text
Test Data
    ↓
Parameterized Test
    ↓
Same Arrange → Act → Assert logic
    ↓
Multiple test executions
```

The behavior and test coverage remain unchanged, while the test suite becomes **shorter, clearer, and easier to maintain**.
