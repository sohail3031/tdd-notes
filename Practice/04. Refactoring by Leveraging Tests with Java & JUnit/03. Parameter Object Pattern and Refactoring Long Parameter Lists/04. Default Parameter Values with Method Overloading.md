# Task

Refactor the `processExamScore` method to provide **reasonable default values** for parameters that usually do not change.

The goal is to simplify common method calls while keeping essential parameters explicit.

### Essential Parameters

These should always be provided:

- `courseCode`    
- `examScore`

### Parameters Suitable for Defaults

These commonly use the same values:

- `isHomeworkComplete`
- `attendanceScore`
- `bonusActivities`
- `isRetake`
- `ScoreWeights`
- `CoursePolicy`

The expected result is that common use cases can be handled with a much simpler call:

```java
examProcessor.processExamScore("MATH101", 85.0);
```

---

# Important Java Concept: Default Parameters

Java does **not** support default parameter values directly.

For example, this is **not valid Java**:

```java
public ExamResult processExamScore(
    String courseCode,
    double examScore,
    boolean isHomeworkComplete = true
) {
    // ...
}
```

Instead, Java commonly uses **method overloading** to provide default values.

---

# Method Overloading

Method overloading allows us to create multiple methods with the same name but different parameter lists.

For example:

```java
public ExamResult processExamScore(
    String courseCode,
    double examScore
) {
    // Use defaults
}
```

Internally, this method delegates to the more complete method:

```java
return processExamScore(
    courseCode,
    examScore,
    DEFAULT_IS_HOMEWORK_COMPLETE,
    DEFAULT_ATTENDANCE_SCORE,
    Arrays.asList(),
    DEFAULT_IS_RETAKE,
    DEFAULT_SCORE_WEIGHTS,
    DEFAULT_COURSE_POLICY
);
```

This gives callers a convenient API while keeping one method responsible for the actual calculation.

# Complete `ExamProcessor.java`

```java
import java.util.Arrays;
import java.util.List;

public class ExamProcessor {

    // Default configuration objects for typical scenarios
    public static final ScoreWeights DEFAULT_SCORE_WEIGHTS =
        new ScoreWeights(0.7, 0.2, 0.1);

    public static final CoursePolicy DEFAULT_COURSE_POLICY =
        new CoursePolicy(2, 75.0, 0.95, 0.6);

    // Default individual-performance values
    public static final boolean DEFAULT_IS_HOMEWORK_COMPLETE = true;
    public static final int DEFAULT_ATTENDANCE_SCORE = 3;
    public static final boolean DEFAULT_IS_RETAKE = false;

    /**
     * Minimal call: only the essential, per-calculation inputs.
     */
    public ExamResult processExamScore(
        String courseCode,
        double examScore
    ) {
        return processExamScore(
            courseCode,
            examScore,
            DEFAULT_IS_HOMEWORK_COMPLETE,
            DEFAULT_ATTENDANCE_SCORE,
            Arrays.asList(),
            DEFAULT_IS_RETAKE,
            DEFAULT_SCORE_WEIGHTS,
            DEFAULT_COURSE_POLICY
        );
    }

    /**
     * Call with custom bonus activities but everything else default.
     */
    public ExamResult processExamScore(
        String courseCode,
        double examScore,
        List<String> bonusActivities
    ) {
        return processExamScore(
            courseCode,
            examScore,
            DEFAULT_IS_HOMEWORK_COMPLETE,
            DEFAULT_ATTENDANCE_SCORE,
            bonusActivities,
            DEFAULT_IS_RETAKE,
            DEFAULT_SCORE_WEIGHTS,
            DEFAULT_COURSE_POLICY
        );
    }

    /**
     * Call with custom homework status, attendance,
     * bonus activities, and retake flag.
     */
    public ExamResult processExamScore(
        String courseCode,
        double examScore,
        boolean isHomeworkComplete,
        int attendanceScore,
        List<String> bonusActivities,
        boolean isRetake
    ) {
        return processExamScore(
            courseCode,
            examScore,
            isHomeworkComplete,
            attendanceScore,
            bonusActivities,
            isRetake,
            DEFAULT_SCORE_WEIGHTS,
            DEFAULT_COURSE_POLICY
        );
    }

    /**
     * Full call: all parameters explicitly provided.
     */
    public ExamResult processExamScore(
        String courseCode,
        double examScore,
        boolean isHomeworkComplete,
        int attendanceScore,
        List<String> bonusActivities,
        boolean isRetake,
        ScoreWeights scoreWeights,
        CoursePolicy coursePolicy
    ) {
        // Normalize input scores to handle edge cases
        double normalizedExamScore = clamp(examScore, 0, 100);
        double normalizedAttendanceScore = clamp(attendanceScore, 0, 3);

        // Calculate weighted exam score
        double weightedScore =
            normalizedExamScore * scoreWeights.getExam();

        // Calculate homework component
        double homeworkScore =
            isHomeworkComplete
                ? 100.0
                : 100.0 * coursePolicy.getMissedHomeworkPenaltyPercentage();

        weightedScore +=
            homeworkScore * scoreWeights.getHomework();

        // Calculate attendance component
        double normalizedAttendancePercentage =
            (normalizedAttendanceScore / 3.0) * 100.0;

        weightedScore +=
            normalizedAttendancePercentage * scoreWeights.getAttendance();

        // Add bonus points
        double bonusPoints =
            bonusActivities.size()
            * coursePolicy.getBonusPointsPerActivity();

        weightedScore += bonusPoints;

        // Apply retake penalty if applicable
        if (isRetake) {
            weightedScore *=
                coursePolicy.getRetakePenaltyPercentage();
        }

        // Ensure score doesn't exceed 100
        weightedScore = Math.min(100.0, weightedScore);

        // Round to the nearest 0.5
        double finalScore =
            roundToNearestHalf(weightedScore);

        return new ExamResult(
            finalScore,
            finalScore >= coursePolicy.getPassingThreshold(),
            calculateGradeLevel(finalScore)
        );
    }

    private double clamp(double value, double min, double max) {
        return Math.max(min, Math.min(max, value));
    }

    private double roundToNearestHalf(double value) {
        return Math.round(value * 2.0) / 2.0;
    }

    private GradeLevel calculateGradeLevel(double score) {
        if (score >= 93) return GradeLevel.A;
        if (score >= 90) return GradeLevel.AMinus;
        if (score >= 87) return GradeLevel.BPlus;
        if (score >= 83) return GradeLevel.B;
        if (score >= 80) return GradeLevel.BMinus;
        if (score >= 77) return GradeLevel.CPlus;
        if (score >= 73) return GradeLevel.C;
        if (score >= 70) return GradeLevel.CMinus;
        if (score >= 60) return GradeLevel.D;
        return GradeLevel.F;
    }
}
```

# Why This Is Better

## Before

A common operation required many arguments:

```java
processExamScore(
    "MATH101",
    85.0,
    true,
    3,
    Arrays.asList(),
    false,
    weights,
    coursePolicy
);
```

This creates unnecessary noise when most values are standard.

## After

The common case becomes:

```java
processExamScore("MATH101", 85.0);
```

This clearly communicates the important information:

> Calculate the exam result for MATH101 using an exam score of 85 and the standard settings.

# Default Values vs. Required Values

A useful design principle is to distinguish between **required inputs** and **optional configuration**.

### Required

```java
String courseCode
double examScore
```

These identify the specific calculation.

### Usually Defaulted

```java
boolean isHomeworkComplete
int attendanceScore
List<String> bonusActivities
boolean isRetake
ScoreWeights scoreWeights
CoursePolicy coursePolicy
```

These have reasonable values for the common scenario.

# Method Overloading as a Java Alternative to Default Parameters

Because Java does not have native default arguments, method overloading provides a similar experience.

```text
processExamScore(courseCode, examScore)
                 ↓
            most common

processExamScore(courseCode, examScore, bonusActivities)
                 ↓
          custom bonuses

processExamScore(
    courseCode,
    examScore,
    homework,
    attendance,
    bonuses,
    retake
)
                 ↓
      custom performance

processExamScore(
    courseCode,
    examScore,
    homework,
    attendance,
    bonuses,
    retake,
    scoreWeights,
    coursePolicy
)
                 ↓
           fully custom
```

All simplified methods eventually delegate to the full implementation.

This avoids duplicating the actual exam-calculation logic.

# TDD Perspective

This task demonstrates an important benefit of having a strong test suite.

### 1. Start with existing behavior

The original tests establish what the application is supposed to do.

### 2. Introduce defaults

Add default values and overloaded methods.

### 3. Run the tests

The existing assertions should continue to pass.

### 4. Simplify the tests

Once the defaults are proven to work, remove unnecessary inputs from the test calls.

### 5. Keep the assertions unchanged

For example:

```java
assertEquals(89.5, result.getFinalScore(), 0.001);
```

does not change.

Only the way the method is called changes.

This gives confidence that the refactoring changed the **API structure**, not the underlying behavior.

# Key Takeaways

- Java does **not** support default parameter values directly.    
- Use **method overloading** to provide default behavior.
- Keep required parameters explicit.
- Provide reasonable defaults for parameters that usually do not change.
- Use constants for shared default values.
- Centralize the actual business logic in the most complete method.
- Have overloaded methods delegate to the full implementation.
- Avoid duplicating business logic across overloaded methods.
- Simplified method calls improve readability and usability.
- Existing tests act as a safety net during refactoring.
- Refactor the test inputs without changing the assertions.
- The final API supports both **simple common cases** and **fully customized cases**.

> **Core principle:** Make the common case simple while keeping advanced configuration available when needed.
