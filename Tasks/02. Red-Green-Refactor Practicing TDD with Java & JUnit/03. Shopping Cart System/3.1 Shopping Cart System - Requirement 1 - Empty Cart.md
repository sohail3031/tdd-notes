# Requirement

When a new `ShoppingCart` is created, it should start without any items, and the total price should be zero.

### Expected Behavior

A newly created `ShoppingCart` should:

- Have an item count of `0`.    
- Have a total price of `0`.

---

## TDD Cycle

### 🔴 Red — Write the Test

The first step is to write a test that describes the required behavior before implementing the functionality.

```java
import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Test;

public class ShoppingCartTest {

    @Test
    public void testShoppingCartIsEmpty() {
        ShoppingCart shoppingCart = new ShoppingCart();

        assertEquals(0, shoppingCart.getItemCount());
        assertEquals(0, shoppingCart.getTotal());
    }
}
```

The test creates a new `ShoppingCart` and verifies that:

- `getItemCount()` returns `0`.
- `getTotal()` returns `0`.

At this point, the test should fail because the required methods have not been implemented yet.

---

### 🟢 Green — Make the Test Pass

The goal of the Green phase is to write the **minimum amount of code necessary** to make the test pass.

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    public List<String> cart = new ArrayList<>();

    public int getItemCount() {
        return cart.size();
    }

    public int getTotal() {
        return 0;
    }
}
```

### How It Works

- `cart` is initialized as an empty `ArrayList`.
- `getItemCount()` returns the size of the cart.
- Since the cart is initially empty, `cart.size()` returns `0`.
- `getTotal()` returns `0` because an empty cart has no items and therefore no total price.

The test should now pass.

---

### 🔵 Refactor

After the test passes, review the implementation and improve it without changing its behavior.

The original implementation exposes the `cart` field publicly:

```java
public List<String> cart = new ArrayList<>();
```

A better approach is to make the field private because the internal state of the `ShoppingCart` should be encapsulated.

```java
import java.util.ArrayList;
import java.util.List;

public class ShoppingCart {

    private final List<String> cart = new ArrayList<>();

    public int getItemCount() {
        return cart.size();
    }

    public int getTotal() {
        return 0;
    }
}
```

### Why This Is Better

- `private` prevents other classes from directly modifying the cart.
- `final` prevents the `cart` reference from being reassigned.
- The cart's internal state is properly encapsulated.
- The behavior remains unchanged, so the test should still pass.

> **Note:** The `List<String>` implementation is only a minimal starting point for this exercise. Later requirements will introduce actual item objects and quantities.

---

## Key Takeaways

- **Red:** Write a test describing the required behavior.
- **Green:** Implement the minimum code needed to pass the test.
- **Refactor:** Improve the implementation without changing its behavior.
- A newly created shopping cart should contain **0 items** and have a **total of 0**.
- Encapsulation is important: internal state should generally not be exposed through `public` fields.
