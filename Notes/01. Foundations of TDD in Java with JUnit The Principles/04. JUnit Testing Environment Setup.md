# Overview

To practice **Test-Driven Development (TDD)** in Java, you need a testing environment that supports writing and executing tests efficiently.

The most common setup includes:

- **Java**
- **Gradle** (build tool)
- **JUnit 5 (Jupiter)** (testing framework)

This environment supports the **Red → Green → Refactor** TDD workflow by allowing rapid feedback after every code change.

---

# Creating a Gradle Project

Initialize a new Java project using Gradle:

```bash
gradle init --type java-application
```

---

# Add JUnit Dependency

In `build.gradle`:

```gradle
dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.9.3'
}
```

Download dependencies and build the project:

```bash
gradle build
```

---

# Running Tests

Execute all tests:

```bash
gradle test
```

Benefits:

- Runs every test automatically
- Provides immediate feedback
- Essential for the TDD development cycle

---

# Organizing Tests with `@Nested`

Use `@Nested` to group related test cases.

```java
public class UserTest {

    @Nested
    class InitializationTest {

        @Test
        void createsUsersCorrectly() {
            // test logic
        }
    }

    @Nested
    class EmailTest {

        @Test
        void getEmailReturnsCorrectEmail() {
            // test logic
        }

        @Test
        void emailContainsAtSymbol() {
            // test logic
        }
    }
}
```

### Benefits

- Improves readability
- Groups related tests
- Easier maintenance
- Better organization

# Setup and Teardown

## `@BeforeEach`

Runs **before every test**.

Used for:

- Creating objects
- Initializing variables
- Common setup

```java
@BeforeEach
void setUp() {
    user = new User("Jane Doe", "jane@example.com");
}
```

---

## `@AfterEach`

Runs **after every test**.

Used for:

- Cleanup
- Closing resources
- Resetting state

```java
@AfterEach
void tearDown() {
    // cleanup code
}
```

### Benefits

- Eliminates duplicate setup code
- Ensures test independence
- Keeps tests consistent

# Common JUnit Assertions

## `assertEquals()`

Checks whether two values are equal.

```java
assertEquals("Jane Doe", user.getName());
```

---

## `assertSame()`

Checks whether two references point to the **same object instance**.

```java
assertSame(user, userInstance);
```

---

## `assertInstanceOf()`

Verifies an object's type.

```java
assertInstanceOf(User.class, user);
```

---

## `assertTrue()`

Checks whether a condition is true.

```java
assertTrue(user.getEmail().contains("@"));
```

---

## `assertFalse()`

Checks whether a condition is false.

```java
assertFalse(user.getEmail().isEmpty());
```

---

# Parameterized Tests

Parameterized tests allow one test method to run with multiple inputs.

```java
@ParameterizedTest
@ValueSource(strings = {
    "jane@example.com",
    "john.doe@domain.com"
})
void emailValidationAcceptsValidEmails(String email) {
    assertTrue(User.validateEmail(email));
}
```

### Advantages

- Reduces duplicate tests
- Improves coverage
- Easier maintenance
- Cleaner code

---

# `@MethodSource`

Use `@MethodSource` when multiple arguments or complex data are required.

Typical use cases:

- Multiple parameters
- Objects
- Collections
- Dynamic test data

---

# Testing Exceptions

Use `assertThrows()` when verifying that code throws an expected exception.

```java
@Test
void invalidEmailThrowsException() {
    assertThrows(
        IllegalArgumentException.class,
        () -> new User("Invalid", "invalid-email")
    );
}
```

## Syntax

```java
assertThrows(
    ExceptionType.class,
    () -> {
        // code expected to throw exception
    }
);
```

### Components

**Expected Exception**

Specifies the exception type.

```java
IllegalArgumentException.class
```

**Executable Code**

The code expected to throw the exception.

```java
() -> new User(...)
```

If no exception (or a different exception) is thrown, the test fails.

# JUnit Features Covered

|Feature|Purpose|
|---|---|
|`@Test`|Marks a test method|
|`@Nested`|Groups related tests|
|`@BeforeEach`|Runs before every test|
|`@AfterEach`|Runs after every test|
|`assertEquals()`|Checks value equality|
|`assertSame()`|Checks object identity|
|`assertInstanceOf()`|Verifies object type|
|`assertTrue()`|Checks true conditions|
|`assertFalse()`|Checks false conditions|
|`@ParameterizedTest`|Runs one test with multiple inputs|
|`@ValueSource`|Supplies simple test data|
|`@MethodSource`|Supplies complex test data|
|`assertThrows()`|Verifies expected exceptions|

# Key Takeaways

- Use **Gradle** to create and manage Java test projects.
- **JUnit 5** is the standard testing framework for Java TDD.
- Run tests with `gradle test` for rapid feedback.
- Organize tests using `@Nested`.
- Use `@BeforeEach` and `@AfterEach` for consistent setup and cleanup.
- Assertions validate expected behavior.
- Parameterized tests improve test coverage while reducing duplication.
- `assertThrows()` ensures proper exception handling.
