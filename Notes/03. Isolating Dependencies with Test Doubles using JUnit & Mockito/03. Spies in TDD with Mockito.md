# Introduction

This is the third lesson on **Test-Driven Development (TDD)** with **Test Doubles**.

In previous lessons, we covered:

- **Dummies** — used to satisfy dependencies without providing real functionality.    
- **Stubs** — used to provide predefined responses from dependencies.

In this lesson, we will learn about **Spies**, another type of test double that allows us to observe how dependencies are used during a test.

The goal is to understand how Spies fit into the **Red-Green-Refactor** cycle and how to use them with **Java**, **JUnit**, and **Mockito**.

---

## What Are Spies?

A **Spy** is a test double that wraps a real object and allows us to observe how that object is used.

Unlike a stub, which primarily provides predefined responses, a Spy allows us to verify interactions with an object while generally preserving the object's real behavior.

Spies are useful when we want to verify:

- Whether a method was called.
- How many times a method was called.
- What arguments were passed to a method.

For example, we may want to verify that a notification service sends exactly one notification with the correct user, message, and priority.

---

## Spies and the Red-Green-Refactor Cycle

Spies can be used as part of the **Red-Green-Refactor** cycle.

### Red

Write a test that verifies the expected interaction. The test should initially fail because the required behavior has not been implemented.

### Green

Implement the minimum amount of functionality necessary to make the test pass.

### Refactor

Improve the implementation and test structure while keeping the behavior unchanged.

# Example: Notification Service

Suppose we have a `NotificationService` that sends notifications through a `RealNotificationSender`.

We want to verify that the notification sender is called correctly.

## Creating a Spy

A Spy can be created from a real object using `Mockito.spy()`.

```java
public class NotificationServiceTest {

    private RealNotificationSender senderSpy;
    private NotificationService notificationService;

    @Before
    public void setUp() {
        // Arrange
        RealNotificationSender realSender = new RealNotificationSender();
        senderSpy = Mockito.spy(realSender);

        notificationService = new NotificationService(senderSpy);
    }

    // Test cases to follow...
}
```

### How This Works

First, we create a real instance:

```java
RealNotificationSender realSender = new RealNotificationSender();
```

Then, we create a Spy around the real object:

```java
senderSpy = Mockito.spy(realSender);
```

The Spy allows us to observe calls to the real object's methods.

Finally, we pass the Spy to the service:

```java
notificationService = new NotificationService(senderSpy);
```

The `NotificationService` now interacts with the Spy instead of directly interacting with the real sender.

---

# Testing Interactions with a Spy

We can use Mockito's `verify()` method to verify how the Spy was used.

```java
@Test
public void testNotifyUserSendsNotificationWithLowPriorityForShortMessages() throws Exception {
    // Act
    notificationService.notifyUser("user1", "Hi!");

    // Assert
    verify(senderSpy, times(1)).send(any(Notification.class));

    verify(senderSpy, times(1)).send(argThat(notification ->
        notification.getUserId().equals("user1") &&
        notification.getMessage().equals("Hi!") &&
        notification.getPriority() == Priority.LOW
    ));
}
```

This test verifies that the `send()` method was called correctly.

---

## Understanding `verify()`

Mockito's `verify()` method allows us to verify interactions with a mock or Spy.

### Verify That a Method Was Called Once

```java
verify(senderSpy, times(1)).send(any(Notification.class));
```

This verifies that:

```text
senderSpy.send(...)
```

was called exactly **one time**.

### Breaking It Down

```java
verify(senderSpy, times(1))
```

Specifies that we want to verify an interaction with `senderSpy` and that it must have occurred exactly once.

```java
send(any(Notification.class))
```

Specifies that the `send()` method must have been called with an instance of `Notification`.

---

# Using `any()`

Mockito provides argument matchers such as `any()`.

```java
any(Notification.class)
```

This means:

> Accept any object of type `Notification` as the argument.

For example:

```java
verify(senderSpy).send(any(Notification.class));
```

The exact contents of the `Notification` object are not checked.

---

# Using `argThat()`

Sometimes we need to verify the actual contents of an object passed to a method.

Mockito provides `argThat()` for this purpose.

```java
verify(senderSpy, times(1)).send(argThat(notification ->
    notification.getUserId().equals("user1") &&
    notification.getMessage().equals("Hi!") &&
    notification.getPriority() == Priority.LOW
));
```

The predicate inside `argThat()` checks the properties of the `Notification`.

The test verifies that:

- `getUserId()` returns `"user1"`.
- `getMessage()` returns `"Hi!"`.
- `getPriority()` returns `Priority.LOW`.

This allows us to verify not only that the method was called, but also that it was called with the correct data.

---

# Making the Test Pass

Once the test has been written, we implement the minimum functionality necessary to make it pass.

```java
public class NotificationService {

    private final INotificationSender sender;

    public NotificationService(INotificationSender sender) {
        this.sender = sender;
    }

    public void notifyUser(String userId, String message) {
        sender.send(new Notification(userId, message, Priority.LOW));
    }
}
```

The service creates a `Notification` and passes it to the sender:

```java
sender.send(new Notification(userId, message, Priority.LOW));
```

Because the Spy is wrapping the sender, Mockito can verify that this interaction occurred.

# Spies with Mockito Annotations

Mockito also provides the `@Spy` annotation.

Instead of manually creating a Spy:

```java
RealNotificationSender realSender = new RealNotificationSender();
senderSpy = Mockito.spy(realSender);
```

we can use:

```java
@Spy
private RealNotificationSender senderSpy = new RealNotificationSender();
```

We can also use `@InjectMocks` to inject the Spy into the class under test.

```java
@ExtendWith(MockitoExtension.class)
public class NotificationServiceTest {

    @Spy
    private RealNotificationSender senderSpy = new RealNotificationSender();

    @InjectMocks
    private NotificationService notificationService;

    // Test cases
}
```

---

## `@Spy`

```java
@Spy
private RealNotificationSender senderSpy = new RealNotificationSender();
```

`@Spy` creates a Spy around the provided real object.

The object can continue to use its real behavior while allowing Mockito to observe interactions with it.

---

## `@InjectMocks`

```java
@InjectMocks
private NotificationService notificationService;
```

`@InjectMocks` tells Mockito to create the `NotificationService` and inject the available Mockito-managed dependencies into it.

In this example, the `senderSpy` is injected into the `NotificationService`.

---

## `@ExtendWith(MockitoExtension.class)`

```java
@ExtendWith(MockitoExtension.class)
```

This enables Mockito's JUnit 5 integration and allows annotations such as:

- `@Mock`
- `@Spy`
- `@InjectMocks`

to be initialized automatically.

# Spy vs. Stub

It is important to understand the difference between a **Stub** and a **Spy**.

|Test Double|Main Purpose|
|---|---|
|Dummy|Satisfies a dependency without providing meaningful behavior|
|Stub|Provides predefined responses|
|Spy|Observes interactions with an object|

### Stub

A stub answers the question:

> **"What should this dependency return?"**

For example:

```java
when(weatherServiceMock.getCurrentWeather("London"))
    .thenReturn(new WeatherData(36, Condition.Sunny));
```

### Spy

A Spy answers the question:

> **"How was this dependency used?"**

For example:

```java
verify(senderSpy, times(1)).send(any(Notification.class));
```

---

# Key Takeaways

- **Spies** are test doubles used to observe interactions with dependencies.
- Mockito provides `Mockito.spy()` for creating Spies from real objects.
- `verify()` checks whether a method was called.
- `times(1)` verifies that a method was called exactly once.
- `any()` allows us to match any argument of a specified type.
- `argThat()` allows us to inspect and validate the contents of an argument.
- `@Spy` can simplify Spy creation when using Mockito's annotation support.
- `@InjectMocks` can automatically inject the Spy into the class under test.
- `@ExtendWith(MockitoExtension.class)` enables Mockito annotations in JUnit 5.
- Spies are particularly useful when the test needs to verify **interactions** with a dependency.
