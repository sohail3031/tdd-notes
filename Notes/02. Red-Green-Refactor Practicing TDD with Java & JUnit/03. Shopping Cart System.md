# Introduction

This is the **third unit** of the TDD practice course using **Java** and **JUnit**.

In this unit, we will build a new **shopping cart system** from the ground up.

Unlike the previous exercises, where tests were provided for each requirement, this unit requires you to **write the tests yourself** and then implement the functionality needed to make them pass.

The requirements will be introduced incrementally, allowing you to practice the complete **Red → Green → Refactor** cycle.

> [!important]  
> Follow the TDD process for each requirement:
> 
> 1. **Red** — Write a test that fails.
>     
> 2. **Green** — Implement the minimum code needed to pass the test.
>     
> 3. **Refactor** — Improve the implementation while keeping all tests passing.
>     

---

# Red-Green-Refactor Cycle

## 🔴 Red

Write a failing test that describes the next behavior the application should support.

## 🟢 Green

Implement the **minimum amount of code** required to make the test pass.

## 🔵 Refactor

Improve the code's readability, structure, and maintainability without changing its behavior.

```text
🔴 Red
Write a failing test
      ↓
🟢 Green
Make the test pass
      ↓
🔵 Refactor
Improve the implementation
      ↓
Repeat
```

# Shopping Cart Requirements

We will gradually build the `ShoppingCart` class by implementing the following requirements:

1. Start with an empty cart.
2. Add a single item.
3. Add multiple items.
4. Handle multiple quantities of the same item.
5. Remove an item.

---

# 1. Starting with an Empty Cart

## Requirement

A newly created `ShoppingCart` should start with no items and a total price of `0`.

### Expected Behavior

```text
New ShoppingCart
       ↓
Item Count = 0
Total      = 0
```

The following behavior must be supported:

- Create a new `ShoppingCart` using its constructor.
- `getItemCount()` should return `0`.
- `getTotal()` should return `0`.

### Example

```java
ShoppingCart cart = new ShoppingCart();

cart.getItemCount(); // 0
cart.getTotal();     // 0
```

### TDD Approach

```text
🔴 Write test
      ↓
Verify a new cart has 0 items
and a total of 0
      ↓
🟢 Implement minimum functionality
      ↓
🔵 Refactor if necessary
```

# 2. Adding a Single Item

## Requirement

Adding a single item should:

- Increase the item count.
- Increase the total price by the item's price.

The cart should provide an:

```java
addItem(Item item)
```

method.

### Example

An item with:

```text
ID    = "1"
Name  = "Book"
Price = 10
```

is added to the cart.

Expected result:

```text
Item Count = 1
Total      = 10
```

### Example Usage

```java
Item book = new Item("1", "Book", 10);

ShoppingCart cart = new ShoppingCart();
cart.addItem(book);

cart.getItemCount(); // 1
cart.getTotal();     // 10
```

### TDD Approach

```text
🔴 Write test
      ↓
Add one item and verify count + total
      ↓
🟢 Implement addItem()
      ↓
🔵 Refactor
```

# 3. Adding Multiple Items

## Requirement

Adding multiple distinct items should update the cart so that:

- `getItemCount()` represents the number of items.
- `getTotal()` represents the sum of the prices of all items.

### Example

Add:

```text
Book
ID    = "1"
Price = 10

Pen
ID    = "2"
Price = 5
```

Expected result:

```text
Item Count = 2
Total      = 15
```

### Example Usage

```java
Item book = new Item("1", "Book", 10);
Item pen = new Item("2", "Pen", 5);

ShoppingCart cart = new ShoppingCart();

cart.addItem(book);
cart.addItem(pen);

cart.getItemCount(); // 2
cart.getTotal();     // 15
```

### TDD Approach

```text
🔴 Write test
      ↓
Add two distinct items
      ↓
Verify count and total
      ↓
🟢 Implement minimum functionality
      ↓
🔵 Refactor
```

# 4. Handling Multiple Quantities of the Same Item

## Requirement

The cart should support adding multiple quantities of the same item.

The method should accept:

```java
addItem(Product item, int quantity)
```

> [!warning]  
> The requirement uses `Product` here, whereas the previous requirements use `Item`. This may be a naming inconsistency in the course material. Verify the class name expected by the exercise before implementing it.

The cart should:

- Track the total quantity.
- Calculate the total using the item's unit price multiplied by its quantity.

### Example

A `Book` costs `$10`.

Adding:

```text
Quantity = 3
Unit Price = $10
```

should produce:

```text
Item Count = 3
Total      = 30
```

### Calculation

```text
10 × 3 = 30
```

### Example Usage

```java
Product book = new Product("1", "Book", 10);

ShoppingCart cart = new ShoppingCart();
cart.addItem(book, 3);

cart.getItemCount(); // 3
cart.getTotal();     // 30
```

### TDD Approach

```text
🔴 Write test
      ↓
Add an item with quantity 3
      ↓
Verify count = 3
and total = 30
      ↓
🟢 Implement quantity support
      ↓
🔵 Refactor
```

# 5. Removing an Item

## Requirement

The cart should support removing an item using:

```java
removeItem(String id)
```

Removing an item should:

- Decrease the item count.
- Update the total price.
- Remove the item associated with the specified ID.

### Example

Add:

```text
Book
Price    = 10
Quantity = 2
```

Then remove one quantity.

Expected result:

```text
Item Count = 1
Total      = 10
```

### Expected Calculation

```text
Original:
10 × 2 = 20

After removing one:
10 × 1 = 10
```

### Example Usage

```java
Product book = new Product("1", "Book", 10);

ShoppingCart cart = new ShoppingCart();

cart.addItem(book, 2);
cart.removeItem("1");

cart.getItemCount(); // 1
cart.getTotal();     // 10
```

> [!warning]  
> There is a potential ambiguity in the requirement: `removeItem(String id)` sounds like it removes an item entirely, while the example says that removing an item from a quantity of `2` should leave a quantity of `1`. For the exercise, follow the behavior specified by the actual tests.

### TDD Approach

```text
🔴 Write test
      ↓
Add an item with quantity 2
      ↓
Remove one
      ↓
Verify count = 1
and total = 10
      ↓
🟢 Implement removal
      ↓
🔵 Refactor
```

# Requirements Summary

|#|Requirement|Expected Behavior|
|---|---|---|
|1|Empty cart|Count = `0`, Total = `0`|
|2|Single item|Count = `1`, Total = item price|
|3|Multiple items|Count = number of items, Total = sum of prices|
|4|Multiple quantities|Count = total quantity, Total = price × quantity|
|5|Remove item|Decrease quantity/count and update total|

# TDD Strategy

For each requirement, follow the same process:

```text
Requirement
     ↓
🔴 Write a test
     ↓
Run test → FAIL
     ↓
🟢 Implement minimum code
     ↓
Run tests → PASS
     ↓
🔵 Refactor
     ↓
Run all tests again
     ↓
Next requirement
```

> [!important]  
> Do not implement future functionality before its corresponding test requires it. This exercise is specifically designed to practice **incremental development through TDD**.

# Key Takeaways

- This unit introduces a new **Shopping Cart System**.
- Unlike previous units, you are responsible for **writing the tests**.
- Requirements should be implemented incrementally.
- Each requirement should follow the **Red → Green → Refactor** cycle.
- Start with the simplest possible implementation.
- Avoid implementing functionality that has not yet been requested by a test.
- Run the **full test suite** after each change to ensure existing behavior remains intact.
- Requirements should drive the implementation rather than assumptions about future functionality.

> [!tip]  
> **Red → Green → Refactor → Repeat.**  
> Let the tests guide the design and implementation of the `ShoppingCart` system.
