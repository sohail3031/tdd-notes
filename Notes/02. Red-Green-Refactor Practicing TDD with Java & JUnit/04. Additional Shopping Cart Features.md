This unit continues practicing **Test-Driven Development (TDD)** with Java and **JUnit** by adding additional functionality to the `ShoppingCart` class.

The exercises follow a real-world TDD workflow where requirements are introduced through tests, one at a time.

The goal is to:

1. Write a test for the required behavior.
2. Run the test and verify that it fails (**Red**).
3. Implement the minimum amount of code required to make the test pass (**Green**).
4. Improve the implementation while keeping all tests passing (**Refactor**).

---

## New Requirements

The following requirements add functionality for:

- Removing non-existent items
- Applying percentage discounts
- Applying automatic bulk discounts
- Clearing the cart
- Updating item quantities

---

## Requirement #6: Removing a Non-Existent Item

### Description

Attempting to remove an item that is not present in the cart should throw an exception indicating that the item was not found.

### Requirements

- Implement removal through a `removeItem(int id)` method.
- If the specified item does not exist in the cart, the method should throw an exception.
- The exception message should be `"Item not found"`.

### Example

Attempting to remove an item with ID `999` should throw an exception with the message:

```text
Item not found
````

### Expected Behavior

```text
Item exists → Remove the item
Item does not exist → Throw an exception
```

---

## Requirement #7: Applying a Percentage Discount

### Description

Applying a percentage discount should reduce the total price of the items in the cart accordingly.

### Requirements

- Implement an `applyDiscount(double percentage)` method.
- The discount should be applied to the cart's total.
- `getTotal()` should return the discounted total.

### Example

For a cart with a total of `100`, applying a `10%` discount should result in:

```text
Original total: 100
Discount: 10%
Final total: 90
```

### Formula

```text
discountAmount = total × (percentage / 100)

discountedTotal = total - discountAmount
```

---

## Requirement #8: Applying a Bulk Discount

### Description

A **10% bulk discount** should automatically be applied when the total price of the items in the cart exceeds `$150`.

### Requirements

- If the cart total is greater than `150`, automatically apply a `10%` discount.
- `getTotal()` should return the discounted total when the bulk discount applies.
- A total of exactly `$150` does not exceed the threshold, so the bulk discount should not apply.

### Example

Adding a `Book` with a price of `200` should result in:

```text
Original total: 200
Bulk discount: 10%
Final total: 180
```

---

## Requirement #9: Clearing All Items

### Description

The cart should provide a way to remove all items at once.

### Requirements

- Implement a `clear()` method.
- The method should remove all items from the cart.
- `getItemCount()` should return `0` after clearing.
- `getTotal()` should return `0` after clearing.

### Example

If the cart contains multiple items:

```text
Before clear:
Item count: 3
Total: 50

After clear:
Item count: 0
Total: 0
```

---

## Requirement #10: Updating Item Quantity

### Description

The quantity of an item should be updateable after the item has been added to the cart.

Both the item count and total price should reflect the new quantity.

### Requirements

- Implement an `updateQuantity(int id, int quantity)` method.
- Update the quantity of the specified item.
- `getItemCount()` should return the new total quantity.
- `getTotal()` should reflect the new quantity.

### Example

A `Book` costs `10` and currently has a quantity of `2`.

Updating its quantity from `2` to `3` should result in:

```text
Item count: 3
Total: 30
```

## TDD Practice

These requirements should be implemented using the **Red-Green-Refactor** cycle.

### Red

Write a test describing the expected behavior.

The test should initially fail because the functionality has not been implemented yet.

### Green

Implement the **minimum amount of code necessary** to make the failing test pass.

Avoid implementing functionality that is not required by the current test.

### Refactor

Once the test passes, improve the implementation if necessary while ensuring that all tests continue to pass.

## Key Takeaways

- Write tests before implementing the required functionality.
- Use the **Red-Green-Refactor** cycle throughout the exercises.
- Implement only the minimum code necessary to make each test pass.
- Test both normal behavior and exceptional cases.
- Discounts should affect the value returned by `getTotal()`.
- Cart operations such as clearing and updating quantities should keep the item count and total price consistent.

> [!important]  
> The main objective of these exercises is not simply to implement the features. The focus is on practicing the **TDD workflow** by allowing tests to drive the implementation.
