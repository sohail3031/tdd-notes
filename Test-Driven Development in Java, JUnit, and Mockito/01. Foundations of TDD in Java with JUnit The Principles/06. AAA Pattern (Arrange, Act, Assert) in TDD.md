# Overview

The **AAA Pattern** is a simple and widely adopted structure for writing clean, readable, and maintainable unit tests.

AAA stands for:

- **Arrange**
- **Act**
- **Assert**

Although you've already been separating your tests into **Setup**, **Action**, and **Validation**, these stages have formal names in TDD:

| Previous Name | AAA Name |
|--------------|----------|
| Setup | **Arrange** |
| Action | **Act** |
| Validation | **Assert** |

> [!note]
> The AAA pattern complements the **Red → Green → Refactor** workflow by providing a consistent structure for individual test cases.

---

# The AAA Pattern

Every unit test should follow the same three-step structure.

```text
Arrange
    ↓
   Act
    ↓
Assert
```

---

# 1. Arrange

The **Arrange** phase prepares everything required for the test.

Typical tasks include:

- Creating objects
- Initializing dependencies
- Setting up mock objects
- Preparing input data
- Configuring the environment

### Example

```java
TaskList taskList = new TaskList();
```

Here, a new `TaskList` object is created and prepared for testing.

> [!tip]
> Arrange should only prepare the test environment—it should not execute the behavior being tested.

---

# 2. Act

The **Act** phase performs the action being tested.

This should usually be **a single method call**.

### Example

```java
Task task = taskList.addTask("Test task");
```

The method under test is executed, and its result is stored for later verification.

> [!important]
> A test should generally contain **only one Act step**. Multiple actions often indicate that the test is verifying more than one behavior.

---

# 3. Assert

The **Assert** phase verifies that the outcome matches the expected result.

Assertions can verify:

- Return values
- Object state
- Collections
- Exceptions
- Side effects

### Example

```java
assertNotNull(task);
assertEquals("Test task", task.getDescription());
assertTrue(taskList.getTasks().contains(task));
```

These assertions verify that:

- The task was successfully created.
- The task description is correct.
- The task exists in the task list.

---

# Complete AAA Example

```java
public class TaskListTest {

    @Test
    public void shouldAddTaskToList() {

        // Arrange
        TaskList taskList = new TaskList();

        // Act
        Task task = taskList.addTask("Test task");

        // Assert
        assertNotNull(task);
        assertEquals("Test task", task.getDescription());
        assertTrue(taskList.getTasks().contains(task));
    }
}
```

# Testing Exceptions with AAA

Sometimes the expected behavior is an exception.

JUnit provides `assertThrows()` for these scenarios.

## Example

```java
public class TaskListTest {

    @Test
    public void shouldThrowErrorWhenCompletingNonExistentTask() {

        // Arrange
        TaskList taskList = new TaskList();

        // Act & Assert
        Exception exception =
                assertThrows(
                        IllegalArgumentException.class,
                        () -> taskList.completeTask(999)
                );

        assertEquals(
                "Task with id 999 not found",
                exception.getMessage()
        );
    }
}
```

---

# Why Are Act and Assert Combined?

When testing exceptions:

- The **Act** is the method call.
- The **Assert** verifies that the exception occurred.

Since `assertThrows()` performs both operations simultaneously, they naturally appear together.

```text
Arrange

	↓

assertThrows(...)

	↓

Verify exception
```

---

# Understanding `assertThrows()`

```java
Exception exception =
        assertThrows(
                IllegalArgumentException.class,
                () -> taskList.completeTask(999)
        );
```

### Breakdown

- `IllegalArgumentException.class`
  - The expected exception type.

- `() -> taskList.completeTask(999)`
  - Lambda expression containing the code expected to throw the exception.

- Returned `exception`
  - Allows verification of additional details, such as the exception message.

---

# Verifying Exception Messages

```java
assertEquals(
    "Task with id 999 not found",
    exception.getMessage()
);
```

Checking the exception message ensures that the failure occurred for the correct reason.

# AAA vs TDD

These concepts serve different purposes but work together.

| TDD Workflow | AAA Structure |
|--------------|---------------|
| **Red** – Write a failing test | **Arrange** – Prepare the test |
| **Green** – Make the test pass | **Act** – Execute the behavior |
| **Refactor** – Improve the implementation | **Assert** – Verify the outcome |

> [!note]
> **TDD** describes the overall development workflow, while **AAA** defines the structure of an individual test.

---

# Benefits of the AAA Pattern

- Improves readability.
- Makes tests easier to understand.
- Clearly separates setup, execution, and verification.
- Simplifies maintenance.
- Makes debugging easier.
- Encourages focused, single-purpose tests.

# Common Pitfalls

## ❌ Mixing Arrange and Act

Bad

```java
Task task = new TaskList().addTask("Task");
```

Good

```java
TaskList taskList = new TaskList();

Task task = taskList.addTask("Task");
```

---

## ❌ Multiple Act Steps

Bad

```java
taskList.addTask("Task 1");
taskList.addTask("Task 2");
taskList.completeTask(1);
```

One test should usually verify **one behavior**.

---

## ❌ Weak Assertions

Bad

```java
assertTrue(true);
```

Good

```java
assertEquals(
    "Test task",
    task.getDescription()
);
```

Assertions should validate meaningful behavior.

---

## ❌ Tests Depending on Each Other

Every test should:

- Create its own objects.
- Prepare its own data.
- Run independently.
- Produce the same result regardless of execution order.

---

# Best Practices

- Follow the **Arrange → Act → Assert** structure consistently.
- Use descriptive test names.

Example:

```text
shouldAddTaskToList()

shouldThrowErrorWhenCompletingNonExistentTask()
```

- Keep the Arrange section concise.
- Limit each test to a single Act step.
- Write meaningful assertions.
- Ensure tests remain independent.
- Avoid coupling tests to implementation details.

# Key Takeaways

- **AAA** stands for **Arrange, Act, Assert**.
- Arrange prepares the test environment.
- Act executes the behavior being tested.
- Assert verifies the expected outcome.
- Most tests should contain **one Arrange**, **one Act**, and **one Assert** section.
- `assertThrows()` is the preferred way to test exceptions in JUnit.
- AAA improves test readability, maintainability, and consistency.
- The AAA pattern complements the **Red → Green → Refactor** workflow by providing a clear structure for writing individual unit tests.
