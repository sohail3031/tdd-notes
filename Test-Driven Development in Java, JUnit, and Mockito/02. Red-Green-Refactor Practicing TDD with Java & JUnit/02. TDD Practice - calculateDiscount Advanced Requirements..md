# Overview

This lesson continues the practical application of **Test-Driven Development (TDD)** using **Java** and **JUnit**.

Building on the previous requirements, the `calculateDiscount` function now needs to handle additional edge cases and business rules.

The new requirements cover:

- Negative discount percentages    
- Very small prices
- Minimum discount percentages
- Maximum discount amounts

The goal is to implement each requirement incrementally while following the **Red → Green → Refactor** cycle.

> [!note]  
> These requirements are intended to be implemented one at a time. Each new test represents the next behavior that the implementation must support.

---

# Red-Green-Refactor Cycle

## 🔴 Red

Write a failing test that defines the next required behavior.

## 🟢 Green

Implement the minimum amount of code necessary to make the test pass.

## 🔵 Refactor

Improve the code's readability, structure, and maintainability without changing its behavior.

```text
🔴 Red
Write a failing test
      ↓
🟢 Green
Make the test pass
      ↓
🔵 Refactor
Improve the implementation
      ↓
Repeat
```

# Additional `calculateDiscount` Requirements

## 6. Negative Discount Percentage

### Requirement

The function must reject **negative discount percentages**.

If the discount percentage is less than `0%`, the function should throw an `IllegalArgumentException` with the message:

```text
Discount cannot be negative
```

### Test

```java
@Test
public void testShouldThrowExceptionForDiscountsLessThanZeroPercent() {

    // Arrange
    double originalPrice = 100.0;
    double discountPercentage = -10.0;

    // Act & Assert
    Exception exception = assertThrows(
            IllegalArgumentException.class,
            () -> {
                CalculateDiscount.calculate(
                        originalPrice,
                        discountPercentage
                );
            }
    );

    assertEquals(
            "Discount cannot be negative",
            exception.getMessage()
    );
}
```

### Expected Behavior

```text
Discount = -10%
       ↓
Invalid input
       ↓
IllegalArgumentException
       ↓
"Discount cannot be negative"
```

> [!important]  
> This requirement is different from the previous `discountPercentage > 100` validation. The valid discount range is now constrained to **0%–100%**, subject to the additional minimum-discount rule described below.

# 7. Handling Very Small Prices

### Requirement

The discounted price must not fall below the minimum allowed price of **$0.01**.

### Test

```java
@Test
public void testCalculateDiscountHandlesVerySmallPricesCorrectly() {

    // Arrange
    double originalPrice = 0.001;
    double discountPercentage = 1.0;
    double expectedDiscountedPrice = 0.01;

    // Act
    double result =
            CalculateDiscount.calculate(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            expectedDiscountedPrice,
            result,
            0.001
    );
}
```

### Expected Behavior

```text
Original Price = $0.001
Discount       = 1%

Calculated Price < $0.01
        ↓
Apply minimum price
        ↓
Final Price = $0.01
```

> [!important]  
> The function must enforce a minimum discounted price of **$0.01**, even when the calculated result would be lower.

# 8. Minimum Discount Percentage

### Requirement

A minimum discount of **1%** should be applied when the provided discount percentage is greater than `0%` but less than `1%`.

### Example

```text
Original Price = $100
Requested Discount = 0.1%

Minimum Discount = 1%

Final Price = $99
```

### Test

```java
@Test
public void testCalculateDiscountShouldApplyMinimumDiscountAmountWhenDiscountIsLessThanMinimum() {

    // Arrange
    double originalPrice = 100.0;
    double discountPercentage = 0.1;
    double expectedDiscountedPrice = 99.0;

    // Act
    double result =
            CalculateDiscount.calculate(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            expectedDiscountedPrice,
            result,
            0.01
    );
}
```

### Expected Behavior

```text
Provided Discount
       │
       ▼
   0.1%
       │
       ▼
Less than minimum 1%
       │
       ▼
Apply 1% discount
       │
       ▼
Final Price = $99
```

> [!note]  
> A `0%` discount remains distinct from a positive discount below `1%`. The previous requirement states that a `0%` discount should return the original price.

# 9. Maximum Discount Amount

### Requirement

The discount amount must be capped at a maximum of **$500**, regardless of the calculated discount.

### Example

```text
Original Price = $2,500
Discount = 30%

Calculated Discount:
$2,500 × 30% = $750

Maximum Discount = $500

Actual Discount = $500

Final Price = $2,000
```

### Test

```java
@Test
public void testCalculateDiscountShouldCapMaximumDiscountAmountAt500() {

    // Arrange
    double originalPrice = 2500.0;
    double discountPercentage = 30.0;
    double expectedDiscountedPrice = 2000.0;

    // Act
    double result =
            CalculateDiscount.calculate(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            expectedDiscountedPrice,
            result,
            0.01
    );
}
```

### Expected Behavior

```text
Calculated Discount
       │
       ▼
    $750
       │
       ▼
Greater than $500
       │
       ▼
Cap Discount at $500
       │
       ▼
Final Price = $2,000
```

# Important Edge Cases

The requirements now introduce several boundaries that should be considered carefully:

|Input / Condition|Expected Result|
|---|---|
|Negative original price|`IllegalArgumentException`|
|Negative discount percentage|`IllegalArgumentException`|
|`0%` discount|Original price|
|Positive discount `< 1%`|Apply `1%` discount|
|Discount between `1%` and `100%`|Apply requested discount|
|Discount `> 100%`|`IllegalArgumentException`|
|Calculated price `< $0.01`|Use `$0.01`|
|Calculated discount `> $500`|Cap discount at `$500`|

# Key Takeaways

- TDD can be used to incrementally introduce increasingly complex business rules.
- Edge cases should be represented by explicit tests.
- Invalid input should be handled through appropriate exceptions.
- Business constraints can be enforced through tests.
- The **minimum discount** and **maximum discount** rules demonstrate how domain-specific requirements can drive implementation.
- The **$0.01 minimum price** protects against results that are too small to represent as a valid payable amount.
- The **$500 maximum discount** prevents the calculated discount from exceeding the business-defined limit.
- Continue following **Red → Green → Refactor** for every new requirement.
- Always run the complete test suite after making changes to ensure existing behavior remains intact.
