# Introduction

This lesson begins the practical portion of the **Test-Driven Development (TDD)** course using **Java** and **JUnit**.

Unlike previous lessons, this course provides requirements incrementally through tests. The goal is to implement the functionality required to make each test pass while continuously following the **Red → Green → Refactor** cycle.

> [!note]
> The provided tests represent the next requirement to implement. Your implementation may differ from the guided solution as long as all tests pass and the required behavior is satisfied.

---

# Red-Green-Refactor Cycle

The **Red-Green-Refactor** cycle is the foundation of TDD.

## 🔴 Red

Write or receive a test that defines the next required behavior.

The test should initially fail because the functionality has not been implemented yet.

## 🟢 Green

Implement the **minimum amount of code** required to make the test pass.

## 🔵 Refactor

Improve the code's:

- Readability
- Structure
- Maintainability
- Efficiency

without changing its behavior.

After refactoring, all tests should continue to pass.

```text
🔴 Red
Write a failing test
      ↓
🟢 Green
Make the test pass
      ↓
🔵 Refactor
Improve the code
      ↓
Repeat
```

# `calculateDiscount` Requirements

The goal is to implement a function named:

```java
calculateDiscount(double originalPrice, double discountPercentage)
```

The function calculates the final price after applying a percentage-based discount.

The following requirements will be introduced incrementally through tests.

---

# 1. Correct Discount Application

## Requirement

The function must correctly apply a percentage-based discount to the original price.

### Example

```text
Original Price = 100
Discount = 20%

Discount Amount = 100 × 20 / 100
                = 20

Final Price = 100 - 20
            = 80
```

## Test

```java
@Test
public void testCalculateDiscountAppliesCorrectDiscount() {

    // Arrange
    Math math = new Math();

    double originalPrice = 100;
    double discountPercentage = 20;
    double expectedDiscountedPrice = 80;

    // Act
    double result =
            math.calculateDiscount(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            expectedDiscountedPrice,
            result,
            0.01
    );
}
```

### What the Test Verifies

The test confirms that a **20% discount on 100 produces a final price of 80**.

The `0.01` value is the allowed tolerance for floating-point comparison.

---

# 2. Zero Discount Handling

## Requirement

When the discount percentage is `0`, the function should return the original price unchanged.

### Example

```text
Original Price = 50
Discount = 0%

Final Price = 50
```

## Test

```java
@Test
public void testCalculateDiscountReturnsOriginalPriceWhenDiscountIsZero() {

    // Arrange
    Math math = new Math();

    double originalPrice = 50;
    double discountPercentage = 0;

    // Act
    double result =
            math.calculateDiscount(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            originalPrice,
            result,
            0.01
    );
}
```

### What the Test Verifies

A `0%` discount should have **no effect** on the original price.

# 3. Decimal Discount Precision

## Requirement

The function must support **decimal discount percentages** and calculate the result accurately.

The result should be rounded to **two decimal places**.

### Example

```text
Original Price = 100
Discount = 33.333%

Discounted Price ≈ 66.67
```

## Test

```java
@Test
public void testCalculateDiscountHandlesDecimalDiscountsCorrectly() {

    // Arrange
    Math math = new Math();

    double originalPrice = 100;
    double discountPercentage = 33.333;
    double expectedDiscountedPrice = 66.67;

    // Act
    double result =
            math.calculateDiscount(
                    originalPrice,
                    discountPercentage
            );

    // Assert
    assertEquals(
            expectedDiscountedPrice,
            result,
            0.01
    );
}
```

### What the Test Verifies

The test checks that the function:

- Accepts decimal discount percentages.
- Performs the calculation accurately.
- Produces a result rounded to two decimal places.

> [!important]
> When working with `double` values, small floating-point differences can occur. The test therefore uses a tolerance of `0.01`.

# 4. Negative Price Handling

## Requirement

The function must reject negative prices.

If the original price is negative, it should throw an `IllegalArgumentException`.

## Test

```java
@Test
public void testCalculateDiscountShouldThrowErrorForNegativePrices() {

    // Arrange
    Math math = new Math();

    double originalPrice = -50;
    double discountPercentage = 10;

    // Act & Assert
    assertThrows(
            IllegalArgumentException.class,
            () -> {
                math.calculateDiscount(
                        originalPrice,
                        discountPercentage
                );
            }
    );
}
```

### What the Test Verifies

```text
Original Price = -50
        ↓
Invalid input
        ↓
IllegalArgumentException
```

The function should not attempt to calculate a discount for an invalid negative price.

# 5. Discount Greater Than 100%

## Requirement

The discount percentage must not exceed `100%`.

If the discount is greater than `100%`, the function should throw an `IllegalArgumentException`.

```java
    // Arrange

    double originalPrice = 100;
    double discountPercentage = 110;

    // Act & Assert

            IllegalArgumentException.class,
            () -> {
                math.calculateDiscount(
                        originalPrice,

            }
    );

```

### What the Test Verifies

```text
Discount = 110%
     ↓
Invalid input
     ↓
IllegalArgumentException
```

A discount cannot exceed the defined `100%` limit.

# Key Takeaways

- TDD starts with a **test**, not the implementation.
- Each new test represents the next behavior the application must support.
- The **Red** phase identifies missing functionality.
- The **Green** phase implements the minimum required behavior.
- The **Refactor** phase improves the implementation while preserving behavior.
- Tests can define both **normal behavior** and **error handling**.
- `assertThrows()` is used to verify that invalid inputs produce the expected exception.
- Floating-point calculations should account for precision when comparing `double` values.
- A strong test suite should cover both **valid and invalid inputs**.
- Your implementation does not have to exactly match a reference solution; it only needs to satisfy the specified requirements and pass the tests.
